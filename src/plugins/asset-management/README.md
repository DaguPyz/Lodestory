# 资产管理插件

资产管理插件拥有项目内的类型模板、资产记录与属性值，并通过 `projectStorageKey` 使用项目存储提供的字节缓冲。字段 ID 是稳定关联标识，字段标题只用于展示。

桌面端保存对象分组时，插件通过 `backgroundTasksKey` 调用 Rust 任务，检查分组归属和重复对象 ID 并编码文件。编码期间再次检查模板归属和分组文件，防止覆盖并发修改。浏览器环境使用插件登记的前端备用实现。对象编辑时的字段、属性值和跨组引用完整校验，以及读取时的校验，仍由前端执行。

每个项目在 `.lodestory/assets/` 下保存模板列表和各模板的对象数据。

- `templates.json` 是左侧模板列表。文件顶层是按 `order` 排列的数组，每条记录有 `id`、`name`、`description`、`order`、`status` 和可选的 `color`。新增、编辑和移动模板只写这个文件。
- 直接按模板 ID 查找 `objects/<模板 ID>.json`。文件顶层包含 `assets` 和 `fields`，模板字段和对象专属字段都放在该模板的数据文件中。无分类对象及其专属字段存放在 `objects/unclassified.json`。资产用 `typeId` 关联模板，模板字段用 `owner: {kind: "type", id}` 关联模板，对象属性值以字段 ID 为键。
- 模板数据文件缺失时，视为空模板。第一次保存字段或对象时直接创建文件，之后的修改只写对应文件。

旧项目的 `schema.json` 仅用于识别旧格式。已有分组文件的版本 4 项目直接按模板 ID 读取。版本 1 至 3 的内嵌数据在第一次保存对象或字段时先写入各模板文件，全部保存后删除旧文件。更早的项目可用 `types` 和 `type-order.json` 恢复模板列表。版本 4 的旧清单也在第一次保存对象或字段时清理。

字段值类型为 `text`、`number`、`singleSelect`、`multiSelect` 和 `reference`。单选与多选配置各自带有稳定 ID 的选项；关联字段可指定目标类型 ID。值会按字段类型和选项校验，关联值必须指向目标类型的现有资产。导航先列出启用的资产模板及对象数；选择模板会选中对应类型、清除对象选择，并打开按该模板筛选的对象列表。对象列表支持列表和卡片两种查看模式，默认列表；右上方的图标按钮提供悬停提示和无障碍名称，当前模式由 `aria-pressed` 标记。切换模板或从对象详情返回时，在当前项目会话内保留所选模式，重新打开项目时重置为列表；该模式不写入项目 schema。列表视图将对象简介放在名称列中。卡片采用最多三列的瀑布流，窄容器自动减少列数；先从左到右填满首行，后续对象依次放入当前最短列；高度相同时优先左列。对象和键盘顺序保持原始数据顺序，不因分列重排 DOM。卡片仅展示名称、全宽简介和右上角的两枚字段数量徽章，高度随文本自然变化；字段图例在卡片区域上方集中显示一次。模板字段和专属字段数量按各自所属的启用字段定义统计，包含未填写的字段，排除已归档字段，零值照常显示；徽章提供悬停说明和无障碍名称。卡片不根据字段标题或字段值推断语义，也不施加字段专属样式。新建对象时沿用当前模板，按其字段展示并初始化默认值；不再通过对象表单单独选择类型。模板字段只适用于类型匹配的对象。用户也可以给单个对象添加独立字段，这些字段只属于该对象。创建后当前版本不支持更改对象类型；之后新增的模板字段不会回填到既有对象。字段顺序以所属类型或对象内的整数 `order` 保存；重命名只改 `title`，保留字段 ID。

## 导航与对象列表呈现

创建或编辑资产模板时也可设置颜色，左侧对应选项使用该颜色作背景，并以边框标记当前选项。模板颜色复用对象的颜色控件与校验规则，保存在模板的可选 `color` 字段中；旧模板保持默认外观，保存失败时沿用模板草稿与重试流程。

创建和编辑对象共用颜色标记控件，提供“默认”、10 个候选色、系统取色器及 `#RRGGBB` 输入。颜色是作者选择的对象内容，不是应用主题色；保存时统一为小写六位十六进制，卡片直接使用该背景色，主题切换不改写它。标题、简介、字段徽章及悬停、按下与焦点状态按背景推导可读前景；默认对象继续使用主题配色。选择“默认”或清空颜色值会移除标记，列表与详情不会整页染色。

`color` 是版本 2 的可选字段，旧对象缺省时无需迁移或写回；创建输入可省略或传 `null`，更新时省略表示保留，传 `null` 表示清除。非法颜色输入拒绝保存，文件中的非法值会阻止覆盖原文件。颜色与名称、简介一起进入现有草稿和保存队列，保存失败后保留并可重试；不增加存储服务、定时器或插件依赖。

资产模板导航每项以单行显示模板名称和对象数；列表模式的字段数集中显示在右侧视图标题中。“未分类对象”行同样显示对象数。对象列表不绘制逐行外框，列宽随内容自然展开，首列固定，其他列在列表区域内横向滚动。点击列表或卡片的对象名称打开详情，不再另设重复的查看按钮。列表中的删除图标在鼠标悬停或行内获得键盘焦点时出现，触屏设备始终显示；列表行和卡片中的对象都可直接右键删除。列表和详情保留完整字段，字段名为“名称”时也不会因此隐藏对应数据。这些属于呈现和交互调整，不改变数据模型或项目会话生命周期。

“未分类对象”导航范围保留旧数据中未分类或类型已归档的对象；当前界面不允许新建未分类对象。

瀑布流由本插件的 `observeAssetCardMasonry` 测量卡片高度，复用 CSS Grid 定义的响应式列数；列宽按列表实际宽度扣除列间距后均分，避免 WebKit 在子项全部绝对定位后返回未扣除间距的 Grid 列宽，侵入页面右侧留白。`ResizeObserver` 跟随容器和卡片尺寸变化，`MutationObserver` 跟随筛选后的节点增减，更新合并到下一动画帧；离开卡片视图或组件卸载时断开观察器、取消待执行帧并恢复普通 Grid。观察器不可用时保留普通 Grid，避免内容不可见。该资源只属于对象视图，不写入 schema，也不新增跨插件契约。

删除资产前会要求确认。删除会一并移除该资产的专属字段及属性值，类型模板和其他资产保持不变；如果其他资产仍通过关联字段指向它，必须先解除这些关联，资产自身指向自己的引用不会阻止删除。删除单个专属字段也需要确认，只会移除该字段定义和所属资产中的对应值。保存失败时保留待删除状态，并可重试；离开项目会先尝试保存，失败则保留当前项目会话。

删除类型模板也需要确认，并会一并移除该类型的模板字段，但不会删除资产或其他类型。只要仍有资产使用该类型，或该类型之外的关联字段将它设为目标，就会阻止删除；该类型自己的模板字段即使指回本类型，也会随模板一起删除，不构成阻止条件。当前版本尚无修改或删除类型模板字段配置、解除外部引用的界面，因此被资产使用或被外部引用的类型暂时无法删除。保存失败时保留待删除状态并支持重试。

插件通过 `layoutKey` 登记“资产管理”导航、“模板设置”主视图和“对象管理”主视图。导航入口保留 `asset-management.navigation` 与 `order: 20`；模板设置展示 `asset-management.types`，对象管理展示 `asset-management.assets`（`order: 21`）。侧栏空白处右键可新建资产模板；模板条目右键可打开模板设置或删除模板。对象列表空白处右键可新建对象或打开模板设置；没有选中模板时，右键对象列表可新建资产模板；列表行和卡片中的对象可直接右键删除。模板设置主视图根区域右键可返回对象列表、编辑或删除当前模板，以及添加字段。打开对象详情后，详情根区域右键可返回对象列表、编辑或删除当前对象。新建模板的导航入口通过会话内请求打开模板表单；这是瞬时 UI 请求，不写入项目 schema。兼容布局可以自行决定各用途的呈现位置。

插件声明 `@lodestory/sdk/context-menu` 的 `contextMenuKey` 依赖，并将取得的 `ContextMenuService` 注入导航、模板设置和对象管理视图；菜单区域由共享 context-menu 插件提供。

每个工作台项目会话各自创建一个私有 schema store，资源不跨会话共享。会话开始时先登记资源，再加载数据；可恢复的读取失败保留在视图中，不阻止项目打开。未完成的表单会阻止离开项目；未保存的类型、字段或资产修改会在离开前重试保存，仍失败则保留会话与用户输入。停用时先撤回三项布局贡献，再撤销工作台参与并释放各会话 store。

类型模板、资产属性值及字段定义、标题修改和排序由资产管理插件负责。`@lodestory/sdk/asset-catalog` 提供按工作台会话隔离的只读资产目录能力，消费者只能读取类型 ID、名称、状态和资产 ID、名称、说明、类型 ID；属性值、schema store 和写入命令仍由本插件私有拥有。消费者可以按类型筛选目录；归档类型及其资产仍会出现在快照中，未分类资产的 `typeId` 为 `null`。会话释放时目录撤销底层订阅并失效，旧目录不能重试。共享项目存储只提供按项目会话隔离的字节文件操作；编码、schema 校验和迁移都属于本插件。

验收应确认：导航 ID 和顺序保持稳定；两个主视图通过布局登记接入；按模板切换对象范围后，各类型对象值都保留，显式未分类范围不会被写操作重置；旧未分类对象可查看但不能新建；对象按当前模板带出字段，也能添加只属于该对象的字段；删除确认可取消，资产和类型删除都遵循各自的引用及使用约束，成功删除只清理目标记录和所属字段；同一项目的新会话可从共享项目存储恢复资产、字段和值；不同会话使用各自 store；未完成编辑和保存失败不会丢弃用户内容；停用插件会先停止视图，再释放会话资源。
