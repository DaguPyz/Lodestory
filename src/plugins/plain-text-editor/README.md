# TXT 编辑器插件

`plain-text-editor` 通过 SDK 的 `bodyEditorKey.registerEditor` 登记 `plain-text` 编辑器，仅接管 TXT；应用配置显式选择它。Markdown 继续使用 Milkdown，`.lode` 继续使用 Quill。旧的 TXT→Quill 配置由声明式 `replaces` 映射接入新实现，不改写用户配置。

文本模型按原始 UTF-16 偏移分块管理，保留 BOM、混合换行和末尾空行。新输入和粘贴中的换行沿用原文件首个换行分隔符。历史只记录修改片段；不存每次编辑的全文副本。

显示层只创建可见行及少量预留行。非可见行先估算高度，显示时再排版，滚动范围会随实际排版校正；普通单行修改通过前缀和索引的点更新定位。超长单行也只显示可见行，但首次访问该逻辑行仍需计算其换行位置。

浏览器原生 textarea 只保留光标附近的输入上下文，负责输入法候选与原生输入事件；全文、选择、剪切粘贴、移动、查找替换和撤销重做由本插件处理。文本视口是唯一滚动容器，排版和颜色使用现有主题变量。

保存继续经正文宿主、文档插件和项目存储插件完成。只有 TXT 文档适配器对 `.txt` 路径显式使用项目存储的 `preferByteView` 紧凑字节视图；项目存储仍是唯一文件缓冲和保存队列拥有者，兼容用的字节数组按需物化。桌面端紧凑读取、创建和删除继续使用 base64 IPC；紧凑保存改用单个原始二进制帧，载荷包含新 UTF-8 字节和保存前的精确字节基线，以保持现有冲突校验。700 毫秒自动保存及单路径共享保存队列不变。Markdown、富文本和未选择该选项的调用仍使用原有字节数组路径。

打开大 TXT 时，文档适配器分块异步解码 UTF-8，最终仍生成并保留完整 JavaScript 字符串。编辑回调沿用 SDK 的完整字符串接口；每次内容变化都需获取全文快照，并由文档适配器编码为完整 UTF-8 字节。因此模型的局部编辑和行索引更新不会让快照与编码成本变成局部操作，该成本仍随文档长度增加。`flushContent` 也返回完整字符串，供宿主在保存和离开前读取已发生但尚待原生输入事件提交的内容。本插件不另建自动保存定时器或文件缓冲。TXT 转换为 `.lode` 由富文本插件贡献转换器，宿主通过通用转换登记调用既有另存为流程。

写作状态只对长度至少 1 Mi UTF-16 单元的 `.txt` 文档分块异步统计字数，完成前显示“统计中…”，并在文本版本变化、切换文档、隐藏文档详情或卸载时取消旧任务。较小 TXT、Markdown 和富文本仍沿用同步统计；字数统计是派生显示，不参与正文保存。

每份文档持有自己的模型、选区和历史；外部内容替换清除旧历史，标签切换保留实例。卸载和部分初始化失败均清理事件、观察器、动画帧、输入框和 DOM。主要验证见 `tests/plain-text-model.test.mjs`、`tests/plain-text-layout.test.mjs`、`tests/plain-text-browser.test.mjs` 和 `tests/documents-content-reader.test.mjs`。
