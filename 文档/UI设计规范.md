# Lodestory · UI 设计系统规范

**版本：1.1.0 ｜ 日期：2026-09-27 ｜ 状态：项目默认设计基线，界面待实现**

适用范围：Lodestory 全部桌面界面的视觉基础、布局原语、公共组件、交互状态、可访问性与平台适配。项目目前使用 Tauri 2 + React + TypeScript；本文定义全局共同标准，不表示相关界面已实现。

视觉依据：[参考图 1](../设计稿/1.png)、[参考图 2](../设计稿/2.png)、[参考图 3](../设计稿/3.png)、[参考图 4](../设计稿/4.png)。**本规范提取的是微冷石墨黑、连贯工作台、精细边界、紧凑控件、蓝色交互指示与正文优先的视觉秩序；所有色值和尺寸是工程化制定的默认基线，不声称是截图原始设计参数或精确取色结果。** 截图外部的桌面背景、环境光、暗角与投影不属于应用内容。截图中的低对比文字和边界按可读性要求修正。

**本文只规定全局设计规则，不包含具体页面的 UI 描述、内容清单、模块顺序、专属尺寸或业务流程。** 参考图仅用于提炼共用视觉语言，不作为页面模板。

## 00. 规范效力与执行模型

### GOV-01｜规范措辞

“必须 / 不得”是验收门槛；“应”是默认规则，偏离时必须记录理由；“可”是已有边界内的选项。未特别标注为“可”的表格数值均为默认必用值。数值中的 min/max 是受支持的变动范围，不是让各页面自由取值。

### GOV-02｜优先级与例外

约束优先级为：**系统原生窗口行为与可访问性要求 → 本规范 → 公共组件契约 → 页面实现 → 效果图。** 用户字体、缩放、密度偏好在本规范预留的覆盖层执行，不作为违规；不得以还原截图为由覆盖这些偏好。

确有新需求时，只能提交统一扩展：说明规则编号、适用范围、原因、替代方案、验证证据、负责人和到期/复核版本。不能在业务页面里先写一个“临时样式”。

### GOV-03｜唯一事实来源

当前以本文件为唯一规范来源。项目尚未建立 `tokens.json`、`tokens.css` 或组件库，不能把本文中的变量名当作已有实现。落地时先将本规范映射为统一主题变量；若后续引入 JSON 生成 CSS，机器源、生成结果与本文必须在同一变更中更新。文档与实现不一致属于缺陷，不能由开发者任选其一。

### GOV-04｜视觉权限边界

页面可以决定信息内容、模块顺序、显示条件和使用哪个已定义的布局/组件变体；**不能自行决定新的颜色、字号、阴影、圆角、控件高度或交互状态样式。** 图片像素、地图坐标、用户内容格式和经批准的画布几何数据不属于页面私有主题。

### GOV-05｜单位和默认环境

本文 px 均指 100% UI 缩放时的逻辑 CSS 像素，而不是显示器物理像素。Token 中可缩放尺寸以 rem 保存，基准为 1rem = 16px；边线等精细尺寸用 px。原生窗口区域由平台适配层管理。不得用 `transform: scale()` 冒充应用缩放。

### GOV-06｜合规对象

规则约束用户真正看到和操作的界面，而不仅是某份 CSS。Canvas/SVG 绘图、Portal 浮层、第三方编辑器内部、空状态、错误状态和离线状态都属于合规对象。

## 01. 视觉不变量

| 编号 | 必须保持的不变量 | 判定方式 |
| --- | --- | --- |
| VIS-01 | 内容是主角，结构性工具为次级 | 不用大面积实色、插画、光晕争夺正文注意力；默认状态无持续动画 |
| VIS-02 | 采用同一组微冷中性深色 | 非状态、非用户内容的颜色只能来自中性语义 Token |
| VIS-03 | 界面是一张连续工作台 | 停靠区域直连、共享边界；不能把所有区域做成悬浮卡片 |
| VIS-04 | 层级由排版、间距、位置和明度共同建立 | 移除强调色后仍可分辨主次；不得依赖彩色分类才能理解结构 |
| VIS-05 | 紧凑不等于缩小可读性 | 不缩减文本字号来容纳内容；以折叠、换行、溢出菜单解决 |
| VIS-06 | 装饰不能携带必要信息 | 去掉阴影、渐变、图片后功能和结构仍成立 |
| VIS-07 | 操作的视觉语义全局稳定 | 同一外观代表同一操作角色；同一状态不能换一套视觉规则 |
| VIS-08 | 平台原生感不等于复制 macOS 外观 | Windows 不画苹果红黄绿按钮；窗口边缘与系统行为由适配层接管 |

**高级感的可执行定义：统一的基线、稳定的密度、精确的对齐、受限的色彩、真实的交互层级。** “更高级”“更有设计感”不能作为增加新视觉变量的理由。

### REF-01｜全局风格提炼

- 采用连续面板、灰白文字、蓝色交互指示和低饱和表面；所有功能复用同一视觉语言。
- 图片、缩略图和头像属于内容资产，不作为全局装饰背景，不决定界面配色。
- 必要文字、边界与关系线保持清晰；选中用实线轮廓等结构标识表达，不依赖光晕。
- 默认只有深色主题。浅色主题、移动端界面不在本版定义范围内；窄桌面窗口按布局退化规则处理。

## 02. Token 架构与样式边界

### TOK-01｜三层结构

```text
原始变量 --ref-*        仅在主题定义中使用：中性色、蓝色、基础字色。
       ↓
语义变量 --ui-*         表达作用：surface-panel、text-secondary、focus-ring。
       ↓
组件变量 --cmp-*        绑定组件契约：field-height、row-radius、button-gap。
       ↓
公共组件 / 布局原语      业务页面只组合，不重新配色或重定尺寸。
```

### TOK-02｜禁止绕过语义层

业务代码不得直接引用 `--ref-*`，不得写未登记的 HEX/RGB/HSL、字号、间距、圆角或阴影。组件默认值也必须引用语义变量。`style={{color: ...}}`、Tailwind 任意色值、任意字号同样受约束。

允许的布局字面值包括 `0`、`auto`、`100%`、`1fr`、`minmax(0,1fr)` 和由受控 Token 推导的 `calc()`；允许数据驱动的分隔面板宽度与画布坐标，但必须在登记范围内，并与视觉变量分开。

### TOK-03｜命名约定

变量按“作用”命名，不能按“第几个页面”命名。禁止 `--character-page-blue`、`--timeline-special-radius`。组件可定义 `--cmp-node-border-selected`，但其值必须映射到 `--ui-accent-indicator`，不能另配一组蓝色。

### TOK-04｜新增条件

新增 Token 必须表达原体系没有覆盖的长期语义，而不是已有值的微调。新增组件需覆盖至少一种真实的新交互模式；只因内容不同，不构成新组件理由。

### TOK-05｜第三方适配

第三方编辑器、图谱、菜单库必须通过统一 Adapter 消费 Token，包括内部选区、搜索命中、工具提示、滚动、只读/禁用态。不得直接发布第三方默认皮肤。API 不开放样式能力的组件不能进入主工作区，除非例外评审通过。

### TOK-06｜主题传播

主题、密度、对比度、动效偏好必须传播到每个窗口、分离窗口、Portal 根节点和弹出层；不能出现主界面深色、菜单默认浅色的混用。本版本只定义默认深色，不代表用 `invert()` 生成浅色主题。

| `--ui-text-placeholder` | `#A4AEBA` | 输入占位提示；不能替代字段标签 |
| `--ui-text-disabled` | `#69737E` | 真正不可用的控件；不可用于正常说明 |
| `--ui-text-document` | `#D9DFE7` | 创作文稿正文 |

| `--ui-border-divider` | `#2D353F` | 纯结构分隔；不能作为唯一的控件识别边界 |

| `--ui-border-control` | `#82909F` | 识别输入区、勾选框等必需的边界 |


次要文字并不等于低对比文字。正常信息不能套 `opacity: .5`，不能使用 disabled 色模拟弱化。状态、链接、文字颜色均以最终渲染背景计算对比度。

| `--ui-accent-indicator` | `#3D9EFF` | 活动标签下划线、选中轮廓与定位标记 |
| `--ui-focus-ring` | `#8CC6FF` | 键盘焦点轮廓 |
| `--ui-action-bg` | `#286BB1` | 实色主操作默认背景 |
| `--ui-action-bg-hover` | `#2F72B7` | 实色主操作悬停 |
| `--ui-action-bg-pressed` | `#235D99` | 实色主操作按下 |
| `--ui-danger-bg` | `#A73542` | 不可逆操作最终确认背景 |
| `--ui-danger-bg-hover` | `#B63C49` | 危险确认按钮悬停 |

当前版本只有一组蓝色交互强调色。绿色、琥珀色、红色是状态语义，不是额外品牌色。主按钮前景与蓝色背景成对使用；不得把白字叠到任意较亮的强调蓝上。

### COL-04｜色彩使用预算

一个操作上下文中至多有一个实色主操作。子工具条与选中标签不能借用 Primary 外观制造多个视觉中心。对话框打开后可拥有自己的主操作，因为它是新的活动上下文。

常规标签、类型标识与未激活导航图标使用中性色。需要强调的操作图标统一使用 `accent-foreground`，活动指示与选中轮廓使用 `accent-indicator`，不按业务模块另配颜色。用户自定义数据颜色只能存在于明确的“用户内容/数据编码层”，必须提供图例或文字标签，不得污染外壳、按钮、焦点和错误语义。

### COL-05｜对比度底线

普通有效文字必须达到 4.5:1；即使标题可适用更低的大字门槛，本产品默认仍按 4.5:1 设计。控件识别必需的边界、图标和状态指示必须与相邻色达到 3:1。纯装饰分隔线不需要伪装成高对比边界，但也不能承担唯一的控件识别功能。[S1][S2]

### COL-06｜默认组合与再验证

以下为本版默认不透明色值按 sRGB 相对亮度计算的代表性组合，显示值保留两位小数，判断使用未舍入结果：

| 前景 / 背景 | 对比度 | 用途 |
| --- | --- | --- |
| text-primary / surface-workspace | 14.48:1 | 主要界面文字 |
| text-document / surface-workspace | 13.29:1 | 文稿正文 |
| text-muted / surface-overlay | 6.20:1 | 浮层元信息 |
| text-muted / surface-selected-hover | 4.62:1 | 选中且悬停的次要文字 |
| text-on-action / action-bg-hover | 4.69:1 | 主按钮悬停文字 |
| text-on-action / danger-bg-hover | 5.29:1 | 危险按钮悬停文字 |
| border-control / surface-control | 4.50:1 | 必要输入边界 |
| accent-indicator / surface-selected-hover | 3.72:1 | 选中指示与必要图形；不能据此用作小字号文字 |

本次未提供独立 `contrast-report.json`。上述检查不涵盖实际组件、图片背景、半透明叠加、系统材质或用户主题。新组合、状态叠加、第三方绘制必须重新测试，不能用“用了 Token”替代对实际效果的检查。

## 04. 排版与阅读规则

### TYPE-01｜三种字体角色

| 角色 | 默认字体栈 | 使用边界 |
| --- | --- | --- |
| Interface | 系统 UI 字体；中文依次回退苹方 / 微软雅黑 UI / Noto Sans CJK | 导航、控件、列表、说明、表单 |
| Document | Noto Serif CJK SC / Source Han Serif SC / Songti SC / SimSun / serif | 作者正文与文稿预览；用户可在阅读偏好中更改 |
| Mono | ui-monospace / SFMono-Regular / Consolas / Liberation Mono | 行列号、快捷键、标识符、代码或原始数据 |

UI 字体在同一平台必须一致；正文和 UI 各自独立配置。字体栈是回退声明，不表示随规范提供字体文件。正式发行必须测试已安装字体与回退字体的中英混排、标点、缺字与输入法表现。

### TYPE-02｜字号、行高和字重

| 文本角色 | 字号 / 行高 px | 字重 | 默认用途 |
| --- | --- | --- | --- |
| Caption | 12 / 18 | 400 | 元信息、快捷键、次级说明 |
| Body | 13 / 20 | 400 | 默认界面正文与列表文本 |
| Label | 13 / 20 | 500 | 控件标签、当前名称 |
| Strong | 14 / 22 | 600 | 分组标题、关键值 |
| Title | 16 / 24 | 600 | 内容区域标题 |
| Display | 20 / 28 | 600 | 独立对话或对象的大标题，不用于常规导航 |
| Document | 17 / 30 | 400 | 作者正文默认值 |
| Document H1 | 28 / 40 | 600 | 文稿一级标题 |
| Document H2 | 22 / 32 | 600 | 文稿二级标题 |
| Document H3 | 20 / 28 | 600 | 文稿三级标题 |
| Mono | 12 / 20 | 400 | 行号、路径片段、代码型标识 |

默认 UI 最小文字为 12px，不通过 10/11px 小字来腾空间。界面字重只用 400/500/600；正文中的作者自定义格式不受这条内容限制。字距默认 `normal`，不得对中文正文额外拉字距、伪加粗或水平压缩。

### TYPE-03｜对齐

同一排的文本按基线对齐；图标按控件光学中心对齐。标签列宽由同一个 Form/PropertyList 负责，不能逐行手工调整。数字对比场景使用等宽数字特性，不强制把整段中文换成等宽字体。

### TYPE-04｜截断与换行

单行名称空间不足时省略，完整值必须可以通过焦点/悬停提示、详情或复制取得；路径优先保留末端文件名，用中间省略。正文、错误原因、危险确认说明不截断。不能缩小字号解决溢出。

### TYPE-05｜长文本

默认文稿测量宽度 720px，仅在空间足够时达到，窄空间按容器收缩；用户文稿偏好可调整到 480–960px。正文默认左对齐，不强制两端对齐。段落视觉间距属于显示层，不得偷偷写入额外空行；默认段间距 16px，首行缩进由文稿偏好决定。

### TYPE-06｜缩放

界面缩放与文稿字号分离。界面必须在 100%、125%、150%、200% 测试；字号增大后控件可以增高、文字可以换行，功能不得被裁掉。系统字体差异允许字形不同，不允许布局溢出或不可读。

## 05. 间距、密度与几何尺度

### GEO-01｜间距刻度

唯一基础间距序列：**0、2、4、8、12、16、20、24、32、40、48、64px**，依次对应 `--ui-space-0` 到 `--ui-space-11`。2px 只用于图标/边缘的微调，不作为大区域布局步长。

| 关系 | 默认间距 | 组合规则 |
| --- | --- | --- |
| 图标与文字、同组小操作 | 8px | 紧凑变体可为 4px，必须由组件统一定义 |
| 表单字段标签与输入区 | 8px | 同一 Form 必须一致 |
| 同组字段或条目块 | 12px | 列表行高另由密度控制 |
| 面板内边距 | 16px | 四边一致；与组件共享边界时可为 0 |
| 独立 Section 之间 | 24px | Section 本身默认无背景、无阴影 |
| 常规内容区内边距 | 32px | 空间不足时统一降为 16px，而非任意缩放 |
| 阅读容器内边距 | 40px | 在窄容器中降为 24px；不能挤压正文到溢出 |

父布局负责子项间距，组件负责自己的内边距。不得同时用父 gap 和子 margin 重复制造间距。为避免抖动，不同状态的边框占位必须预留。

### GEO-02｜密度为全局设置

| 指标 | Compact 默认 | Comfortable |
| --- | --- | --- |
| 列表 / 树 / 单行表格最小行高 | 28px | 36px |
| 标准输入与按钮最小高度 | 32px | 40px |
| 紧凑按钮最小高度 | 28px | 32px |
| 菜单最小行高 | 28px | 36px |
| 双行列表最小行高 | 48px | 56px |
| 工具条 / 标签条最小高度 | 40px | 48px |
| 面板头部最小高度 | 36px | 44px |

页面不得各自决定密度。常规连续列表要采用同一种行高；只有实际含两行内容时使用双行变体，不能为了装饰拉高单行。

### GEO-03｜点击区与图形分离

图标画布为 14/16/20/24px，默认 16px；可操作区域不能跟着缩成 16px。一般自定义非行内操作的有效命中区至少 24×24px，推荐 28/32px，并且相邻命中区不得重叠。原生控件、行内链接、密集画布等例外需说明原因并保留等效操作。[S3]

分隔条可用 8px 拖拽带覆盖 1px 可见分隔线；它必须另外提供键盘或菜单调整/重置途径，不把细分隔条视为普通按钮。不得让不可见命中区遮住正文选字。

### GEO-04｜允许的非网格数值

1px 边线、2px 焦点、1.5 的 SVG 描边、排版字号、百分比/分数布局、用户拖动宽度、图片原始比例属于明确例外。不能借“4px 网格”强行把 13px UI 字体改成 12/16px，也不能借这些例外任意写 19px padding。

## 06. 布局语法：新增功能只能组合，不能重新造壳

### LAY-01｜结构角色

| 布局原语 | 负责的事情 | 不允许做的事情 |
| --- | --- | --- |
| AppShell | 唯一应用级顶区、工具轨、工作区、底区和原生窗口适配 | 业务页面不能另建一套全局导航与外框 |
| DockPanel | 可停靠、可折叠、可调整宽度的辅助区域 | 不能为了换业务主题更换背景、圆角和头部高度 |
| Workspace | 主内容承载区，可有多个内容标签 | 不能再包一层带阴影的“大内容卡片” |
| SplitGroup | 管理分隔、拖动约束、折叠优先级和焦点 | 页面不能散写绝对坐标拼三栏 |
| Toolbar | 同一上下文中的命令与视图控制 | 不能夹带宣传标题或重复主导航 |
| Section | 标题、内容、必要操作的逻辑分组 | 默认不生成背景、边框、圆角或阴影 |
| Stack / Inline / Grid | 垂直、水平、二维排布及合法 gap | 不能偷偷改内部组件的颜色或尺寸 |
| ScrollArea | 一块内容的滚动、滚动恢复和边缘处理 | 不把整个外壳变成一个纵向网页 |
| Layer | 菜单、提示、对话框、抽屉的浮层顺序与焦点 | 页面不能随意写 z-index 或跨层拦截输入 |

### LAY-02｜外壳尺度合同

以下是跨所有工作视图复用的结构约束，不是某一页的布局草图：

| 外壳参数 | 默认 / 范围 |
| --- | --- |
| 自绘顶区 | 44px；原生安全区由平台适配层保证 |
| 底部状态区域 | Compact 24px / Comfortable 32px |
| 工具轨 | 44px |
| 导航停靠区 | 默认 232px，允许 192–360px |
| 检查器停靠区 | 默认 312px，允许 280–420px |
| 主工作区目标最小宽度 | 480px；极窄/放大模式下保底 320px |
| 可见分隔线 / 拖拽命中带 | 1px / 8px |
| 文稿最大默认行宽 | 720px，空间不足时流动收缩 |

新功能可以不显示某个辅助区，但不能因此调整全局工具轨、标题区、密度或基本色彩。面板开闭与宽度按工作空间保存；打开/切换文件不能自动重置布局。

### LAY-03｜宽度计算与退化

主区可用宽度 = 内容客户区宽度 − 实际可见停靠区宽度 − 工具轨 − 分隔线。由这个约束触发退化，而不是为每个页面写一组断点。

空间不足时顺序为：**辅助操作进入溢出菜单 → 右侧辅助区折叠 → 左侧导航折叠 → 单工作区模式。** 不允许压缩字体、压缩按钮命中区或保持多个不足最小宽度的面板。自动折叠不能销毁用户之前保存的宽度和开闭偏好；空间恢复可还原。

### LAY-04｜对齐与网格

优先共享纵向边界、标题基线和控件起点。同一父容器里的字段/列表使用统一列规则。数据网格根据可用宽度和对象的最小宽度计算列数，默认对象单元最小 240px；其他尺寸必须定义为可复用的公共组件变体，不能按页面特设。不能仅为了“排得漂亮”制造空列或给每个对象随机宽度。

### LAY-05｜滚动

应用根容器不承担业务内容滚动，各主内容和停靠区分别滚动。禁止同一轴无必要的多重嵌套滚动。文稿和说明应换行；只有画布、宽表格、原始代码等确有二维内容的区域允许水平滚动。固定头部与浮层不得盖住正在操作的焦点目标。[S4]

### LAY-06｜容器选择

层级表达顺序为：**分组间距 → 标题 → 必要分隔线 → 必要背景 → 仅浮层使用阴影。** 只在“独立可操作对象、可拖拽单元、画布节点、媒体预览”场景使用带边界的对象容器；禁止因为有一个小标题就生成卡片。

## 07. 边界、圆角、材质与层级

### MAT-01｜圆角按角色分配

| 角色 | 圆角 |
| --- | --- |
| 停靠面板、连续分区、阅读底板 | 0 |
| 精细装饰或小型勾选图形 | 2px |
| 列表选中背景、标签、分段项 | 4px |
| 按钮、输入、独立对象容器 | 6px |
| 菜单、气泡、Popover | 8px |
| 应用内对话框 | 12px |
| 开关轨道、头像等明确的圆形语义 | pill / 50% |
| 操作系统窗口外轮廓 | 系统决定，业务页面不得模拟 |

不得任意发明 5、7、10、16、20px 圆角。嵌套曲面需要圆角时由公共组件计算，不允许出现内层圆角大于外层且边距很小的挤压效果。连续工具区不使用胶囊大圆角。

### MAT-02｜边框

默认边宽为 1px。相邻面板只能画一条共享分隔线，不能左右各画一条。hover/selected/focus 不改变盒模型。必要输入边界使用 `border-control`；边界可只表现为统一的底线，但该变体必须在组件层定义，全局一致。

`border-control` 只用于识别操作区域所必需的线条，不用于全部卡片和面板。已有明确图标、文字和布局识别的对象容器使用 `border-divider`；选中轮廓使用 `accent-indicator`。避免把参考图的细边界工作台变成满屏亮灰框。

### MAT-03｜阴影只表达“浮起”

| 层级 | 阴影 |
| --- | --- |
| 停靠区域、列表、常规按钮、Section | none |
| 浮动菜单与 Popover | `0 8px 24px rgba(0,0,0,.32), 0 2px 6px rgba(0,0,0,.24)` |
| 应用内对话框 | `0 20px 64px rgba(0,0,0,.48), 0 2px 8px rgba(0,0,0,.24)` |

禁止彩色阴影、选中发光、发亮头像光环。窗口外阴影由系统提供，不在内容层再次绘制一层。

### MAT-04｜克制的材质

仅外壳顶区可叠加统一的中性微高光：顶部白色 2.5% 到透明；底色保持 `surface-chrome`。内高光只有 `inset 0 1px 0 rgba(255,255,255,.04)` 一种，可用于外壳/浮层，不用于每个对象。

默认工作内容不使用模糊、噪点、纹理、暗角、背景风景和装饰渐变。内容图片需要叠加文字时，使用公共媒体组件的统一遮罩或不透明文字底板保证对比度，不修改原图；遮罩不得溢出媒体容器。系统原生半透明材质只能由平台适配层启用；必须有不透明回退，且文字区域仍满足对比度。截图外部的摄影光照不进入产品。

### MAT-05｜浮层层级

底层内容 z=0；区域内 sticky z=10；分隔交互 z=20；统一 Overlay 根 z=100。每个活动浮层建立自己的层上下文，内部按 backdrop=0、content=1、floating=10、tooltip=20 排列。

不允许全应用散落 `z-index: 9999`。模态中的菜单挂到该模态的 Layer，而不是跳回更低层。关闭模态时，其从属浮层同时关闭；操作系统输入法候选窗不纳入应用 z-index 竞争。

## 08. 图标、图片与数据图形

### IMG-01｜图标体系

同一构建版本只采用一种主图标风格：16px 画布为默认，1.5 描边，圆端点/圆连接，单色 `currentColor`。14/20/24px 是登记尺寸，不允许把 16px 图标随意缩放到 17/19px。必要的光学校正需记录在 Icon 组件，不在页面 `translateY(1px)`。

系统原生图标、品牌标志、用户素材是例外；不能把 Emoji、实心插画和线性功能图标混在同一工具条。

### IMG-02｜图形与命中区

图标不等于按钮。所有可操作图标必须使用 IconButton 契约，提供可访问名称、Tooltip 和键盘访问；只靠图标形状表达风险不合格。

### IMG-03｜图片与头像

图片必须有显式比例和加载占位，避免内容跳动。头像统一使用 24/32/40px 预设；更大尺寸通过公共组件变体统一定义，不能按页面单独指定。组件尺寸不能随 hover/selected 改变。对象图按容器定义比例，不强制所有图片为圆形。装饰性图片默认不出现在工作区域。**不得为了“统一高级感”对用户原图强制去饱和、压暗或改变对比度**；预览可以裁切，但必须可查看原图。图片缺失时使用同尺寸中性占位。

### IMG-04｜画布图形共用语法

图谱、思维导图、时间线、地图标注等采用相同规则：底板为 workspace；对象底为 panel/control；必要边界使用 control；选中轮廓用 accent；焦点使用独立轮廓。重要关系线至少 1px，并达到所需对比度；网格是装饰层，可更弱且应可关闭。

连接类型首先用线型、端点、箭头和文字区分。用户内容允许自定义颜色，但必须有非颜色替代标识。空间位置需要忠实表达数据，不能为了让整图对称而改变含义。

### IMG-05｜缩放分工

画布缩放只影响世界空间内容；工具条、浮层、文字详情及操作命中区保持可用的屏幕尺寸。缩小后难以点击的节点须提供搜索/列表等等效选择方式，不能把整个 UI 和节点一起无限缩小。

## 09. 公共组件契约

所有组件都必须登记：语义角色、结构、尺寸、允许的 variant、全部适用状态、键盘模型、文本溢出策略、无障碍名称、Token 映射与测试用例。没有这些信息的“漂亮组件”不能进入公共库。

| 组件家族 | 尺度和外观合同 | 行为/组合限制 |
| --- | --- | --- |
| Button / IconButton | 默认 32px，紧凑 28px；内横距 12px，图文距 8px；6px 圆角 | 仅 primary / secondary / ghost / danger 四种角色；页面不能发明第五种颜色按钮 |
| TextField / Select / Textarea | 单行最小 32px；内横距 12px；6px 圆角；control 底与功能边界 | 必须有标签；帮助/错误置于关联区域；多行高度随内容/设定增长 |
| Checkbox / Radio / Switch | checkbox 可见图形 16px；switch 32×20px；外部命中区至少 24px | 必须表示未选、选中、禁用、焦点；checkbox 还需混合态；只读与禁用不能混淆 |
| List / Tree / Table row | 单行 28px、双行 48px；行内距 8px；层级缩进 16px | 同类行全局一致；整行选择与行内操作的命中区不得相互争抢 |
| Tab / SegmentedControl | 文档标签条 40px；Tab 默认宽 120–240px；选中指示 2px | 选中和键盘焦点分开；关闭操作至少 24px；不以变粗变宽制造跳动 |
| Tag / Badge | 静态 Tag 高 20px、横距 4px、圆角 4px，12px 字号 | 可点击/可删除版本外部命中区至少 24px；默认中性，不给每类业务标签一种颜色 |
| Menu / Popover / Tooltip | Menu 内距 4px，条目 28px，宽 192–360px，圆角 8px | 内容长可扩展登记宽度或换行；不能截断危险操作说明；Tooltip 不是操作容器 |
| Dialog / Sheet | 宽度预设 420/560/720px，内距 24px，圆角 12px | 不超过当前可用区减两侧各 16px；长内容内部滚动；禁止叠套多级模态 |
| ObjectContainer / Node | 6px 圆角、无阴影；由内容选择 panel 或 control 表面 | 仅用于真正独立对象；不能用它把整个页面卡片化 |
| Progress / Status / Notice | 中性外壳 + 最少量状态色；12/13px 文字；固定状态占位 | 非阻塞状态就地显示；失败不能只弹一条自动消失的消息 |
| Form / PropertyList | 标签与值共享对齐规则；字段间 12px，Section 间 24px | 只读值默认是文字而非灰掉的输入框；长标签统一换行或切换上下布局 |

### CMP-01｜按钮状态合同

Primary：默认/hover/pressed 分别使用 `action-bg` / `action-bg-hover` / `action-bg-pressed`，前景始终 `text-on-action`。Secondary：中性底、明确标签与必要边界；Ghost：透明底，hover/pressed 才出现中性背景。Danger 默认可用红色文字；只有不可逆操作最终确认可用 `danger-bg` 系列。

Loading 保留原有按钮宽度，用内联进度替代图标或占位，不改变整排布局。Disabled 使用禁用 Token 并阻止动作，不对整个组件套透明度。主按钮如果需要轮廓识别，边界用 accent，不能借过亮蓝底牺牲文字对比度。

### CMP-02｜字段合同

字段至少覆盖 default、hover、focus-visible、filled、invalid、read-only、disabled、loading。invalid 包含边界/图标/文字，不只涂红。focus-visible 作为外轮廓与 invalid 内边界共存。只读仍可聚焦与选择/复制；禁用才禁止编辑与激活。

### CMP-03｜状态不能改变几何

切换选中、错误、加载、悬停时，文字起点、图标占位、按钮宽度与相邻控件基线必须保持。错误说明新出现可以增加该字段下方内容高度，但不能覆盖下方内容或借绝对定位溢出。

### CMP-04｜接口权限

业务层只能选择已经登记的 `variant`、`size`、`state` 和内容；不得传入任意 `color`、`radius`、`shadow`、`fontSize` 或“覆盖内部 className”的视觉逃生口。布局容器可以接受受限 gap/alignment/placement 枚举；画布数据坐标不属于视觉逃生口。

## 10. 全局状态语法与微交互

### STATE-01｜基本状态

| 状态 | 外观语义 | 必须避免 |
| --- | --- | --- |
| Default | 中性表面与清晰文字 | 默认让所有按钮发亮 |
| Hover | 轻量中性底/轮廓，显示可用的附属操作 | 字号、尺寸或布局变化 |
| Pressed | 更明确的中性按下底或 action-pressed | 弹跳、发光、缩小整个按钮 |
| Selected | 持续选中底 + 位置/符号/指示线 | 只改变文字色而没有第二种线索 |
| Focus-visible | 2px focus-ring + 2px 间隔，或等价的内部完整轮廓 | 取消 outline 而没有替代 |
| Read-only | 保留可读对比度，提供只读说明 | 等同 disabled，无法复制内容 |
| Disabled | 禁用语义色，无 hover/pressed 动作 | 将正常说明伪装成不可用 |
| Invalid / Warning | 局部状态边界/图标 + 明确原因 | 整个面板染色或只靠红黄区分 |
| Loading | 原位置进度与稳定占位，必要时可取消 | 不断闪烁、自动抢焦点 |
| Drag-over | 清晰的放置目标/插入线 + 可放置/不可放置说明 | 靠用户猜测落点 |
| Inactive selection | 失焦后仍保留中性选择标识 | 把已选择内容完全变回默认 |

### STATE-02｜状态叠加规则

状态是多个维度，不是一列互相覆盖的皮肤。按压/悬停只调整表面；Selected 保留选中背景；Invalid 保留局部错误边界和说明；Focus-visible 永远是独立可见的焦点层。Disabled 阻止交互，但已有错误文本仍须可读。

例如“选中 + hover + 键盘焦点”应是：selected-hover 背景 + selected 标识 + focus 轮廓。不得让 hover 把选中背景覆盖成普通灰色。

### STATE-03｜焦点与键盘

所有可操作控件都可通过键盘到达；焦点必须可见且不被固定区域或模态完全遮挡。列表、树、菜单、标签与对话框采用对应的 ARIA/APG 键盘模式，不靠随意堆 tabIndex 实现。[S4][S5][S6]

模态开启时焦点进入模态，背景不可操作；关闭后回到触发点或合理的后继控件。图标操作不能只在鼠标 hover 时才存在，键盘聚焦行时也必须可达。

### STATE-04｜拖拽不独占

涉及文件排序、面板调整、节点连接或定位等拖拽功能时，必须有不要求拖动的等效单指针操作，并支持合适的键盘途径；例如“移动到…”、“向上/向下移动”、尺寸输入或连接命令。[S7]

### STATE-05｜输入法、快捷键、选字

中文组合输入期间不得抢走 Enter/Esc 来触发提交、关闭或命令；快捷键适配层必须识别正在合成的输入。切换样式、保存状态提示或弹出检查结果不得破坏选区、滚动位置与未完成输入。正文可选可复制，不能全局 `user-select: none`。

### STATE-06｜辅助信息显示

Tooltip 默认延迟 500ms，距锚点 8px；只解释，不承载操作。菜单/Popover 距锚点默认 4px，边缘至少留 16px，自动翻转或调整位置。隐藏的附属操作要预留布局位置，并在行焦点状态同样显示。

## 11. 动效、加载和反馈

### MOT-01｜动效词汇

| Token 角色 | 时间 | 允许变化 |
| --- | --- | --- |
| Instant | 0ms | 输入、光标定位、窗口拖动中连续尺寸更新 |
| Fast | 100ms | hover、短状态反馈、微小控件状态 |
| Normal | 160ms | 菜单/Popover 出入、面板显示切换 |
| Slow | 220ms | 非频繁的布局重排、完整对话层出现 |

默认曲线 `cubic-bezier(.2,0,0,1)`；退出可用 `cubic-bezier(.4,0,1,1)`。浮层位移不超过 4px，opacity 与 transform 足够时不得增加复杂属性动画。页面不能自行新增 300/500/800ms 过渡。

### MOT-02｜不动画化创作

不对每次输入、每次保存、文稿重排做动画。禁止持续背景动画、霓虹呼吸、闪烁边界、自动轮播和装饰粒子；不得 `transition: all`。拖动分隔面板采用直接跟手更新，不套缓动。

### MOT-03｜减少动效

系统或用户要求减少动效时，非必要动画关闭，状态仍以静态图标/文字表达。不能关闭动画后把“正在处理”也隐藏。输入法和系统原生动画由系统管理，不强行覆盖。

### MOT-04｜异步反馈

操作开始先有即时按压/受理反馈；预计很短的任务不闪现加载组件，持续约 300ms 后在原位置显示处理中状态。任务确有可测进度时才显示百分比；未知时明确写“处理中”，不得伪造百分比。关键失败、保存冲突、权限问题必须保留到用户处理，不只发一个短暂 Toast。

### MOT-05｜空、错、无结果

无数据、搜索无结果、无权限、加载失败、未打开工作空间是不同状态，不得共享同一句“暂无数据”。结构采用简短标题 + 原因 + 下一可行动作；不用大插画占满工作台，不通过新配色表现不同状态。

### MOT-06｜提示层级

反馈先就地呈现；只有跨当前操作域的状态才提升为通知；只有确实阻塞或不可逆的操作才用模态。保存成功等常态不反复弹 Toast。通知不能抢焦点或遮住当前输入行。

## 12. 桌面适配与平台边界

### DESK-01｜原生窗口优先

macOS 窗口控制、Windows 标题按钮、窗口拖动/缩放/最大化区域、系统菜单、安全区、焦点失活外观由平台适配层管理。自绘标题区可统一工具排布，但不得覆盖原生命中区。窗口外阴影、窗口圆角和系统任务切换缩略图不由业务页面模拟。

### DESK-02｜多窗口与工作空间

每个工作空间共享同一设计系统。新窗口、分离的编辑窗口或辅助窗口可以删减结构区域，不能变成另一种 UI 皮肤。标题、路径、修改标识和当前工作空间身份必须能区分，不把应用名放成大宣传标题。

### DESK-03｜偏好与失焦

窗口失焦只弱化活动装饰，不降低正文到不可读。面板宽度、密度和字号按明确的用户/工作空间范围保存；不得因临时窗口缩小而覆盖持久设置。

### DESK-04｜缩放与滚动条

必须测试不同 DPI 与应用缩放。滚动条默认采用系统行为和可见性设置，不强行永久隐藏，不为“极简”缩成不可操作的装饰细线。必须自绘时另行登记控制尺寸、命中区与键盘操作合同，不能沿用未经验证的 4px 自定义滚动条。

### DESK-05｜最小工作条件

桌面默认目标设计基准为 1440×900 客户区；960×640 是常规最小窗口测试条件，不是可以无视高倍缩放的硬保证。缩放后不足完整布局时按 LAY-03 退化。所有模态以当前可用客户区限制尺寸，不根据显示器分辨率盲目居中和定宽。

## 13. 可访问性与内容语义

### A11Y-01｜纳入视觉验收，不作为补丁

本项目采用 WCAG 2.2 相关对比度、目标尺寸、键盘/焦点和拖拽条款作为视觉与交互基线；这不表示“写了本规范即获得完整 WCAG 合规”。桌面实现仍须进行实际平台辅助技术测试。[S1]–[S7]

### A11Y-02｜非颜色线索

成功/警告/失败配状态文字或图标；选中配指示线、勾选或其他结构标识；链接在正文中保留下划线或等价非颜色识别。不能只用红绿显示不同版本，也不能只用蓝色区分当前焦点。

### A11Y-03｜语义与名称

优先原生语义元素；定制结构必须给出正确的名称、角色、选中/展开/禁用状态。Tree、Grid、Tab 等应采用各自键盘模型；读屏名称不能把装饰图标重复朗读。新增自定义 Canvas 控件应有等效 DOM/平台无障碍表示或列表入口。[S6]

### A11Y-04｜适配模式

高对比度/forced-colors 模式下使用系统色映射，移除微渐变，保留实际边框、焦点轮廓及非颜色状态线索；不得全局设置 `forced-color-adjust: none`。Portal 与多窗口必须传播模式。用户内容图片可以保留原始色彩，不能让它影响控件可读性。

### A11Y-05｜内容与术语

所有操作文案采用明确动作，如“打开文件夹”“保存副本”“移到废稿箱”；避免模糊的“继续”“优化一下”。“只读”“不可用”“未保存”“保存失败”“已同步”分别有自己的状态含义，不得为了短文案混用。辅助检查结果是建议，不把不确定的模型判断显示成系统确定错误。

### A11Y-06｜可恢复性

对文稿有破坏性的操作必须明确对象和影响范围，提供撤销或确认路径。错误详情要可复制；被截断的完整名称和路径要可获取。操作失败不得静默关闭对话框并丢失用户输入。

## 14. 新增界面的开发合同

### NEW-01｜新增界面需要提交的内容

新界面只提交“组合清单”，包含：所处 AppShell 区域、使用的布局原语、公共组件与 variant、内容密度、主要操作上下文、焦点/键盘模型、宽度不足时退化方式、加载/空/错/只读状态、复用的测试基线。

**不提交一套新的配色、字号、阴影或圆角方案。** 即使新增的是地图编辑、版本对比或事件调度，也应先使用相同的 Surface、Toolbar、Field、List、Layer 和状态规则。

### NEW-02｜确有缺口时的唯一处理路径

```text
现有组件可组合 → 直接复用。
现有组件只有受限能力不足 → 提交通用 variant，更新契约和测试。
交互模式确实不同 → 新建公共组件，映射既有语义 Token。
语义 Token 无法覆盖 → 提交设计系统变更，统一评审与版本更新。
```

“这个页面特殊”不是新建视觉规则的理由。新增通用规则应能解释为什么未来相似需求也会使用它，而不只是解决这一张截图。

### NEW-03｜变更版本

新增兼容 Token/variant 为 minor；修正文档错误或不改变外观合同的修复为 patch；修改默认字体、颜色角色、尺寸体系、组件语义或删除 Token 为 major。版本号策略是本项目的治理规则，不把局部页面变化伪装成全局规范升级。

### NEW-04｜扩展登记记录

每项扩展记录：编号、需求、现有规则不足、推荐方案、影响组件、无障碍与缩放测试、迁移范围、批准版本。临时例外必须有复核期限；不能以“以后再统一”无限期绕过组件库。

## 15. 开发验收与禁止清单

### QA-01｜静态验收

主题源之外无未登记颜色、阴影、圆角、字号与间距；业务页面无组件内部视觉覆盖；没有 `transition: all`、全局 `outline: none`、未经批准的 `!important`、`z-index: 9999` 或整页 `user-select: none`。公共组件不得只测 default 状态。

### QA-02｜组件状态验收

每个交互组件至少演示适用的 default / hover / pressed / selected / focus-visible / disabled / read-only / loading / invalid；并验证 selected+hover、invalid+focus、只读+选字等叠加组合。状态切换不得导致 1px 跳位、文字起点移动和容器抖动。

### QA-03｜视觉回归

在固定平台、字体、窗口尺寸、DPI 和缩放条件下生成基线，macOS 与 Windows 分开保存。参考尺寸至少覆盖 1440×900、1280×800、960×640，缩放覆盖 100%、125%、150%、200%。不同平台不要求字体光栅化逐像素相同，但必须满足同一角色、间距、层级与状态合同。

### QA-04｜内容压力测试

使用长文件名、深层目录、无空格长串、中英混排、大量标签、空值、大数值、错误长文本、网络中断、图片缺失、多个滚动区域、中文组合输入和无权限内容。不能只用短示例文本验收。

### QA-05｜键盘和平台验收

只使用键盘完成核心操作；焦点不丢失、不被遮住；Esc/Enter 不破坏组合输入；拖拽有替代；模态焦点回归；系统高对比度与减少动效可用；Portal 与多窗口无主题泄漏。[S3]–[S7]

### QA-06｜发布门槛

必须项出现一项失败即不通过。允许例外需附 GOV-02 记录。截图仅作为视觉回归资产，**规范正文、Token 和组件状态合同才是验收依据**。

### 明确禁止

| 禁止项 | 应当替代为 |
| --- | --- |
| 每个新页面重新配色、重新定字号/圆角 | 语义 Token + 组件组合 |
| 五颜六色的业务标签/文件图标 | 中性标签 + 形状/文字/结构 |
| 大面积蓝紫渐变、霓虹、发光关系线 | 统一中性表面、精确选中指示 |
| 所有分组都用圆角卡片包起来 | Section + 间距 + 必要分隔 |
| 将低对比文字称作“高级灰” | 符合对比度的 text-muted |
| 照抄截图外部暗角、风景与环境投影 | 原生窗口边缘 + 平坦工作内容 |
| 用 opacity 一键完成 disabled/弱化 | 明确的状态文字和语义 Token |
| 缩小正文或点击区来塞入更多功能 | 折叠、滚动、溢出和单工作区退化 |
| 页面级改第三方库皮肤 | 统一 Adapter |
| AI 自动改正文并把结果当确定事实 | 明确建议状态、作者确认和可恢复操作 |
