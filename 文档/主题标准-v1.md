# 主题标准 v1

**状态：正式设计 ｜ 标准版本：1.0.0 ｜ 日期：2026-10-15**

本标准规定主题作者如何描述配色，以及宿主如何识别、补齐、应用和校验配色。内置主题和自定义主题采用同一格式并平级管理，明暗只作为属性。正式设计不等于全部功能已发布；已实现范围与待实现功能见[主题管理设计](需求设计/主题管理.md)。

## 1 主题由什么组成

主题只有一层按视觉用途和交互状态命名的颜色表。例如，`text.primary` 表示主要文字，`surface.content` 表示主要内容承载面，`state.selectedForeground` 表示选中状态前景。不同插件实现共同使用这些角色，标准不预设编辑器、文件树或其他组件存在。

一个主题包可以包含多套主题，例如同一风格的浅色、深色版本。应用内保留一个主题管理服务，主题包向它登记配色贡献，不各自替换全局服务。

| 对象 | 含义 | 负责的内容 |
| --- | --- | --- |
| 主题包 | 作者交付和用户安装的单位 | 包身份、发行版本、兼容范围、主题文件路径 |
| 主题 | 用户选择的一套具体配色 | 主题身份、展示名称、明暗属性、颜色表 |
| 颜色登记表 | 全部实现共同遵循的视觉契约 | 通用颜色名称、用途、变量映射、默认值、成对取色与状态规则 |

配色组合只引用这层颜色名，规定“这个背景应该搭哪个前景”，不提供第二份色值，也不允许主题作者覆盖组合规则。v1 不接受组件、页面或插件专属的颜色命名空间。

本文将颜色变量表称为 **A**，对比度校验规则称为 **B**。主题作者只给 A 填写色值；宿主补齐默认值后执行 B，低于目标时提供警告。搭配组合、交互状态规则和分类辨识辅助检查也由标准维护，作者不能覆盖。

v1 主题覆盖纯色配色、遮罩颜色和阴影颜色。字体、字号、密度、圆角、尺寸、布局、图片和动效继续由现有设计系统管理。蓝色强调和微冷中性风格属于内置主题的设计，作者可以选用其他色系。

## 2 如何制作一套主题

作者按用途修改通用颜色。下面的主题展示基础配色，以及状态提示、内容高亮、放置反馈、链接、反色表面和分类配色；剩余项由登记表补齐。

```json
{
  "schemaVersion": 1,
  "id": "example.ink.dark",
  "name": "墨色写作",
  "type": "dark",
  "colors": {
    "surface.content": "#171A23",
    "text.primary": "#E8EAF0",
    "accent.foreground": "#C9AAFF",
    "text.reading": "#ECE2CE",
    "state.selectedBackground": "#3B3158",
    "state.selectedForeground": "#F5EDFF",
    "status.warningBackground": "#352B1E",
    "status.warningForeground": "#EBD3A2",
    "highlight.background": "#40331F",
    "highlight.foreground": "#F5E2BC",
    "highlight.activeBackground": "#59451D",
    "highlight.activeForeground": "#FFF3D6",
    "drop.allowedBackground": "#30283F",
    "drop.allowedForeground": "#E3D1FF",
    "drop.allowedBorder": "#BFA0EC",
    "link.foreground": "#C9AAFF",
    "link.hoverForeground": "#DECCFF",
    "link.pressedForeground": "#EDE2FF",
    "link.visitedForeground": "#E0AED0",
    "link.visitedHoverForeground": "#EFCAE3",
    "link.visitedPressedForeground": "#F7DFEE",
    "surface.inverse": "#ECE2CE",
    "text.inverse": "#24202D",
    "category.1.background": "#2E2840",
    "category.1.foreground": "#C9AAFF"
  }
}
```

`text.reading` 影响所有使用阅读正文角色的内容；不能把它解释成某个编辑器的专属颜色。未填写的选中悬停前景默认引用 `state.selectedForeground`，因此也会采用这里的浅色前景。

配套文件：

- [颜色角色登记表](主题标准-v1/颜色角色登记表.md)：面向作者查看用途、默认值和变量映射。
- [机器颜色登记表](../src/plugins/theme/color-registry.json)：颜色、默认值、组合与校验规则的唯一编辑源，作者表和主题 Schema 从这里生成。
- [主题文件 Schema](主题标准-v1/theme.schema.json)与[包清单 Schema](主题标准-v1/manifest.schema.json)：供编辑器和校验工具检查 JSON 字段。
- 实际内置主题：[深色](../src/plugins/builtin-themes/dark.theme.json)、[浅色](../src/plugins/builtin-themes/light.theme.json)，直接作为完整主题参考，不另存配色副本。
- [墨色主题包示例](主题标准-v1/examples/ink/manifest.json)：演示只覆盖少量颜色。
- [配色使用示例](主题标准-v1/配色使用示例.md)：解释颜色如何取用，以及叠加状态下的预期结果。

## 3 颜色角色与命名

颜色名称采用“用途分组.具体用途”的形式，例如 `surface.content`、`state.selectedHoverForeground`。名称中的大小写有意义，固定写法以登记表为准。

| 分组 | 视觉用途 | 使用边界 |
| --- | --- | --- |
| `surface` | 六类中性承载面，以及反色承载面 | `inverse` 必须成套使用反色前景，不加入中性表面上下文 |
| `text` | 主要、次要、辅助、占位、禁用、阅读正文、实色操作文字、反色文字 | 表示文字职责；`inverse` 只配反色面 |
| `border` | 分隔、装饰、必要识别边界、反色面内部边界 | 中性必要边界用 `strong`，反色面用 `inverse`；装饰不能承担唯一识别功能 |
| `state` | 悬停、按下、选中、选中悬停、选中按下、失焦选中、禁用、禁用选中 | 每态都定义成套背景与前景 |
| `action`、`danger` | 实色主操作、实色危险操作 | 各自的前景配默认、悬停和按下背景 |
| `status` | 成功、警告、错误、信息的前景、提示背景与校验边界 | 单独的状态前景用于中性面；`*Background/Foreground/Border` 必须按反馈或校验组合使用 |
| `accent`、`focus`、`caret` | 强调文字、状态指示、键盘焦点、文本输入光标 | 焦点按实际邻接面选择 `ring` 或 `inverseRing`；特殊文本面上的光标沿用最终前景 |
| `selection` | 文字选区的背景和前景 | 与持续选中对象的 `state.selected*` 分开 |
| `highlight` | 普通内容标记、当前定位的内容标记 | 可用于搜索命中；文字选区优先，当前标记与普通标记分开 |
| `drop` | 允许／禁止放置的反馈，以及精确插入位置 | 独立提示区域保留目标原有选中状态，不把普通悬停等同于放置许可 |
| `link` | 未访问／已访问链接的默认、悬停、按下前景 | 独立色仅配中性表面；特殊配色区域内继承最终前景并保留下划线 |
| `category` | 六个无顺序、无成败含义的类别槽 | 每槽背景、前景、边界成套；槽号不代表固定色相、等级或具体业务对象 |
| `overlay`、`shadow` | 遮罩、柔和阴影、较深阴影 | 只定义颜色，标准管理几何 |

每项登记 `id`、`description`、`cssVariable`、`alphaAllowed` 和深浅两套 `defaults`。`defaults` 可以是具体色值，也可以是 `{ "ref": "另一颜色名称" }`，表示缺项时引用该颜色解析后的结果。引用关系仅由宿主标准维护。

历史 CSS 变量作为兼容映射保留，例如 `surface.content` 映射到历史变量 `--ui-surface-workspace`。历史变量名字不增加区域专属语义，也不是 CSS 选择器规则。完整映射见登记表；变量声明不代表具体 UI 已完成成对取色接入。

颜色集合封闭，未知名称报错。新增角色必须表达可复用的视觉用途或状态，通过统一标准治理；不能因安装了某个插件就添加它的专属配色项。所有界面绘制都应取用这套角色，内容图片和封面素材保留本身色彩；表达界面状态的图标使用主题前景。

### 3.1 提示、高亮等配色场景

A 共 **108 项**，其中下列六类用途占 52 项。完整默认值、CSS 映射及透明度规则统一记录在颜色登记表中。

| 场景 | 变量 | 数量 |
| --- | --- | --- |
| 状态提示与校验边界 | `status.{success,warning,danger,info}Background/Foreground/Border` | 12 |
| 内容高亮 | `highlight.background/foreground/activeBackground/activeForeground/activeBorder` | 5 |
| 放置反馈 | `drop.allowedBackground/Foreground/Border`、`drop.forbiddenBackground/Foreground/Border`、`drop.insertionIndicator` | 7 |
| 链接状态 | `link.foreground/hoverForeground/pressedForeground/visitedForeground/visitedHoverForeground/visitedPressedForeground` | 6 |
| 反色表面 | `surface.inverse`、`text.inverse`、`border.inverse`、`focus.inverseRing` | 4 |
| 多类别区分 | `category.1.background/foreground/border` 至 `category.6.background/foreground/border` | 18 |

表中的花括号和斜线表示名称展开，不能原样写入主题。场景名称用于说明用途，不要求存在特定组件；例如同一套 `highlight.*` 可由正文、列表预览或其他内容实现使用。

## 4 成对取色与搭配规则

登记表的 `paintSets` 定义配色组合，仅包含对颜色角色的引用。主题文件仍只填写 `colors`，不接受 `paintSets`、局部覆盖表或选择器。组合名称表达视觉用途和状态，不表示某类组件。

| 用途或状态 | 背景 | 配套前景或指示 | 规则 |
| --- | --- | --- | --- |
| 中性内容 | 从六项 `surface.*` 中选择实际承载面 | 主要、次要、辅助、占位、阅读正文、强调或状态前景 | 仅选登记表允许的搭配，不能在这里使用实色操作文字 |
| 普通悬停、按下 | 对应 `state.hover/pressed` 背景 | 同态前景 | 背景和前景一起切换 |
| 选中、选中悬停、选中按下、失焦选中 | 对应 `state.selected*` 或 `state.inactiveSelected*` 背景 | 同态前景与 `accent.indicator` | 保留选中指示，不混用普通悬停的前景 |
| 禁用、禁用选中 | 对应 `state.disabled*` 背景 | 同态前景与 `state.disabledBorder` | 不产生悬停或按下反馈；禁用选中仍保留选中标记 |
| 实色主操作 | `action.background/hoverBackground/pressedBackground` | `action.foreground` | 三态都与同一主操作前景配对 |
| 实色危险操作 | `danger.background/hoverBackground/pressedBackground` | `danger.foreground` | 不借用主操作前景或背景 |
| 文字选区 | `selection.background` | `selection.foreground` | 不沿用原正文颜色，以免选区不可读 |
| 可见键盘焦点 | 实际邻接的承载表面 | `focus.ring` | 独立外环，不替换背景前景，也不移除选中标记 |
| 文本光标 | 实际文本承载表面 | 中性面用 `caret.foreground`；高亮、选区和反色文本面用区域最终前景 | 避免独立色与特殊背景失去对比 |
| 状态提示 | 对应 `status.*Background` | 同用途 `*Foreground` 与 `*Border` | 成套取色；与实色危险操作分开 |
| 校验边界 | 保留原承载面 | 对应 `status.*Border` | 仅替换边界；限 `validationSurface`，焦点环独立 |
| 内容高亮 | `highlight.background` 或 `activeBackground` | 同态前景；当前标记另加 `activeBorder` | 不混用两态；文字选区优先 |
| 放置反馈 | `drop.allowedBackground` 或 `forbiddenBackground` | 同态前景与边界 | 独立提示区域，不覆盖目标原状态 |
| 链接 | 保留六类中性承载面 | 对应 `link.*` 前景 | 只改变前景；特殊配色区域内继承该组合前景 |
| 反色内容 | `surface.inverse` | `text.inverse`、需要时的 `border.inverse` | 不与普通文字色混搭 |
| 分类标记 | 同槽 `category.N.background` | 同槽 `foreground` 与 `border` | 图形或数据线可只取同槽前景并置于中性面 |

进入选中或实色操作组合后，该组合直接承载的文字和普通图标使用其前景，不能继续继承中性文字或任意状态色。成功、警告等含义继续通过文字和图标形状表达，不能只靠颜色。独立内容高亮、文字选区或反馈区域可嵌套，但必须完整绘制自身背景与前景，不能只借其中一色。选中指示使用组合规定的指示色。

`contexts.surface` 是实现显式指定的中性承载面，`contexts.foreground` 是允许的中性前景角色，缺省为主要文字；它们选择现有角色，不创建新色值。`border` 表示需要绘制边界时的颜色，不要求每个对象都加框；靠边界识别的可操作对象使用 `border.strong`，普通结构分隔使用 `border.divider`。

扩展上下文 `validationSurface` 表示校验边界内侧的实际底色，允许中性面与非禁用通用交互背景；`adjacentSurface` 表示焦点环实际邻接的中性、交互、提示、高亮、放置反馈或分类底色。上下文仅在组合引用时必须提供，不能把反色面填入这两个上下文。反色焦点由独立的 `inverseFocus` 组合定义。链接、校验、焦点和插入线组合的背景字段表示校验底色，不表示额外涂底。

焦点环在承载表面上绘制，与对象自身填充保持可见间隔，并对实际邻接色检查至少 3:1。不能只改变文字色代替焦点环。禁用但仍允许聚焦以说明原因的对象，同样保留可见焦点；普通原生禁用对象不能聚焦时自然没有焦点环。

## 5 状态顺序与跨实现接入

状态是实现提供的语义标记，不由主题解析器查询 HTML。按登记表 `stateRules.priority` 顺序匹配，命中后使用完整组合：

1. 禁用且选中 → 禁用选中组合。
2. 禁用 → 禁用组合，抑制悬停与按下反馈。
3. 选中且按下 → 选中按下组合。
4. 选中且悬停 → 选中悬停组合。
5. 选中但选择上下文失焦 → 失焦选中组合。
6. 其余选中 → 选中组合。
7. 其余按下 → 采用普通、主操作或危险操作的按下组合。
8. 其余悬停 → 采用相应用途的悬停组合。
9. 其余情况 → 采用相应用途的默认组合。

短暂悬停、按下反馈优先于失焦选中的底色，选中指示仍保留。`selectionActive` 表示所属选择上下文是否活跃，不要求对象自身获得键盘焦点。`focusVisible` 单独控制焦点环，始终与上述状态正交叠加。

持续选中状态的优先级高于实色主操作或危险操作的填充用途：即使实现传入 `action` 或 `danger`，选中时也采用完整的通用选中组合。操作含义通过文字和图标形状保留，不混入另一组合的前景；取消选中后再按原操作用途取色。

插件根据自身内容选择视觉用途、承载面和语义状态。DOM 实现通过宿主提供的 CSS 变量取值；Canvas 等实现从同一份已解析角色表取值；独立视图由宿主传入同一主题快照，并在主题变化时更新。主题不包含这些渲染代码。

两种不同编辑实现都可以使用主要内容承载面、阅读正文、通用光标和文字选区。不同目录选择实现使用同一套选中状态。这些是用途映射示例，不新增专属规则。宿主不按标签、CSS 类名或插件 ID 自动推断配色；公共组件、开发约定和后续校验负责帮助实现遵循契约。

### 5.1 六类场景的叠加规则

`stateRules` 管理可操作对象的通用状态，`usageRules` 管理六类扩展用途；它们都属于标准数据，不放入作者主题文件。实现先区分对象本身与独立内容／提示区域，再在各区域内应用规则。带状态的扩展用途按 `usageRules.priority` 首次命中选择组合；`paint: null` 表示无额外配色，具体含义按下表处理。未知状态标记和非布尔值均报错。

| 场景 | 叠加或优先级 |
| --- | --- |
| 提示与校验 | 独立提示取完整组合；对象校验只改边界，选中和焦点保留。禁用时不叠加校验边界，说明放在邻近提示中。实色操作或反色对象使用独立反馈区域 |
| 内容高亮 | 文字选区 > 当前定位高亮 > 普通高亮；选择结束后恢复标记。当前高亮必须绘制边界并配当前标记。高亮、选区内的输入光标取该区域最终前景 |
| 放置反馈 | 禁用或未拖放时 `null`（隐藏）；禁止放置 > 精确插入位置 > 允许放置。目标原有选中与焦点保留，完整反馈另绘制独立区域；插入线使用中性提示带 |
| 链接 | 特殊组合内部 `inheritForeground=true` 时 `null`（继承其最终前景）；否则禁用 > 已访问按下 > 已访问悬停 > 已访问默认 > 未访问按下 > 未访问悬停 > 默认。激活行为仍受禁用控制；始终保留下划线 |
| 反色表面 | 普通内容成套使用反色组合；内部交互对象进入通用状态时完整切换。焦点依据实际邻接面选择 `inverseFocus` 或 `focusExtended`，与内部状态独立。反色文本光标取 `text.inverse` |
| 类别配色 | 静态标记成套保留类别色。可操作对象进入悬停、按下、选中、禁用时采用通用状态组合，以名称／形状保留类别身份；独立静态标记可保留类别组合 |

链接的 `visited` 由实现提供；原生浏览器历史按浏览器隐私限制处理，不要求脚本读取访问历史。多个类别使用六个稳定槽，类别 ID 与槽号的映射由实现保存，不因排序改变；超出六类可复用槽，必须补充名称、图案或形状。分类颜色不能被赋予成功、失败或高低等级含义。

所有焦点环均须与对象填充留出可见间隔。`stateRules.focus` 表达“焦点不能被背景状态吞掉”；真正绘制时仍按实际邻接面选组合，不能因对象本身用了反色背景就直接使用反色焦点色。

## 6 主题文件契约

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `schemaVersion` | 是 | 固定为数字 `1`，表示 v1 文件结构 |
| `id` | 是 | `发行者.包名.主题名`，例如 `example.ink.dark`；ID 保持稳定，展示名称改变不改变 ID |
| `name` | 是 | 展示名称，1 至 80 字符；不得为空白或包含控制字符 |
| `type` | 是 | 只能是 `light` 或 `dark`；用于标准缺省值、原生外观及系统策略匹配，不是主题层级 |
| `colors` | 是 | 仅包含登记过的名称与颜色字面量；每个颜色项可省略，空对象表示完全采用该类型的标准默认配色 |
| `$schema` | 否 | 作者工具的 Schema 提示，宿主忽略此字段，不联网获取资源 |

包 ID 为 `发行者.包名`，主题 ID 必须以包 ID 加一个主题段构成。每段只允许小写英文字母、数字和连接词用的短横线，以字母开头；例如 `example.ink.dark`。`lodestory` 发行者命名空间保留给宿主内置包。

色值只接受 `#RRGGBB` 或 `#RRGGBBAA`，大小写均可。末尾 `AA` 表示透明度：`00` 为完全透明，`FF` 为完全不透明。背景、文字、边界、状态、焦点和操作颜色只允许不透明色；透明度仅开放给 `overlay.scrim` 与四项 `shadow.*`。不透明角色使用八位色值时，末尾必须为 `FF`。

主题文件不能包含 CSS 片段、`var()`、`url()`、颜色函数、脚本或主题之间的继承关系。JSON 必须是 UTF-8 标准 JSON；重复字段名、注释、尾逗号和未声明字段均视为错误。

`--ui-color-scheme` 由 `type` 派生。阴影按柔和、较深两种视觉用途定义，偏移、模糊和扩散尺寸由标准固定，作者只调整四个阴影色。宿主按 `shadowRecipes` 组合回现有复合阴影变量；任何浮动实现都可选用这两种配方。

## 7 包清单与归属

v1 包使用 ZIP 容器，扩展名为 `.lodestory-theme`，根目录必须包含 `manifest.json`。包内只允许清单和清单列出的主题 JSON 文件；源目录中的 Schema、说明和校验脚本不放进安装包。

```text
ink.lodestory-theme
  manifest.json
  ink-dark.theme.json
```

```json
{
  "schemaVersion": 1,
  "kind": "theme",
  "id": "example.ink",
  "name": "墨色主题",
  "publisher": "example",
  "version": "1.0.0",
  "compatibility": {
    "themeStandard": { "min": "1.0.0", "maxExclusive": "2.0.0" },
    "lodestory": { "min": "0.1.0", "maxExclusive": "0.2.0" }
  },
  "contributes": {
    "themes": [{ "path": "ink-dark.theme.json" }]
  }
}
```

`kind: "theme"` 明确这是主题数据包，不要求第三方 JavaScript 入口或执行权限。主题名称、ID 和明暗属性只在主题文件中声明，清单只列路径，避免两份元信息相互冲突。包 ID 第一段必须等于 `publisher`；本地包中的发行者字段是作者声明，不代表已验证身份。

安装器必须额外检查包 ID 与发行者一致、主题 ID 属于当前包、所有主题 ID 与路径唯一、兼容区间有效，以及包的真实来源。外部导入一律拒绝占用 `lodestory` 命名空间；只有宿主随安装提供的内置来源可登记该命名空间，不能根据包自报的字段授予内置身份。这些关联与来源检查不由单文件 Schema 替代。

路径采用包内相对路径，以 `/` 分段，仅使用小写英文字母、数字、短横线和下划线，并以 `.theme.json` 结尾。绝对路径、空路径段、`.`、`..`、反斜杠、链接文件和归一化后重复路径均被拒绝。每包 1 至 32 个主题；清单最多 64 KiB，每主题最多 256 KiB，解包后的总内容最多 5 MiB。安装器还需检查压缩包真实内容、路径边界和重复文件。

宿主按包记录主题归属。一个包的登记、撤销、更新只影响它贡献的主题，不能覆盖其他包。安装表示主题进入目录，选择表示应用其中一套配色，两种状态分别管理。更新先检查暂存包再提交，失败保留旧版本；停用或卸载被选中的主题前先回退内置配色。

## 8 缺省与优先级

解析某个颜色时，依次执行：

1. 使用当前主题明确填写的色值。
2. 缺项时，读取登记表中该角色对应 `type` 的默认值。
3. 默认值是引用时，递归解析所引用角色；引用目标也优先使用当前主题显式值。

例如，主题只填写 `state.selectedForeground`，未填写的选中悬停前景默认引用它，选中按下前景再引用选中悬停前景，最终都跟着改变。显式填写某个通用状态前景可以改变该状态在全部实现中的表现，不能仅改变某个组件。颜色不能从上一套主题遗留，也不从另一个可卸载的主题包取得。

所有颜色项都可省略；元信息、`type` 和 `colors` 字段必须存在。内置主题显式列出默认常量，其余通用前景通过默认引用补齐。作者希望某个派生色始终跟随被引用的角色时，应省略该派生项。

登记表在发布前检查重复名称、重复 CSS 映射、引用缺失、引用环、默认类型和透明度。宿主启用主题时须完整解析全部角色，再整体应用，不能逐项拼接出中间配色。后续局部改色功能按以下规则接入：按主题 ID 保存，优先级高于主题文件；不修改已安装包。

## 9 可读性与校验结果

普通文字、占位提示和选区文字的目标对比度至少为 4.5:1；必要的控件边界、光标与焦点指示至少为 3:1。禁用状态、装饰分隔线和阴影不强制使用这些阈值。基础要求沿用[UI 设计规范](UI设计规范.md)。

登记表中的 `contrastPairs` 是 B，覆盖 350 组允许的对比关系：中性文字、通用状态、操作与文字选区，以及状态提示、校验边界、内容高亮、放置反馈、链接六态、反色组合和六个分类槽。禁用前景及边界以 `minRatio: null` 明确豁免，不能通过整个对象降低透明度模拟禁用。

提示、高亮等场景的文字与各自填充至少为 4.5:1；必要边界、插入线和焦点至少为 3:1。分类前景同时可作文字，因此对同槽填充及全部中性面均采用 4.5:1。提示、放置反馈、当前高亮及分类边界检查自身填充与外侧中性面；反色填充还检查与外围中性面的 3:1。当前高亮有明确边界，不要求普通与当前高亮的底色彼此达到 3:1。特殊文本面的光标采用该区域已经校验的最终前景。

`distinctionChecks` 是 B 的分类辨识辅助检查：把六个分类前景归一化为 RGB 后，两项完全相同时警告；大小写和不透明 `FF` 后缀不影响判断。它不把“不相等”视为人眼或色觉差异下可辨识，也不设未经论证的通用色差门槛。相邻分类使用边界或中性间隔，并配名称、图案、线型或形状；真实页面仍须验收。

校验在完整解析后计算，不能只检查主题文件里填写的几项。只改背景而保留前景是合法的部分主题；若最终搭配不够清晰，警告报告实际颜色对，不自动替换色值。禁止使用登记表没有允许的前景背景混搭；新的合法搭配须补登记和校验关系。

| 结果 | 行为 |
| --- | --- |
| 格式、字段、路径、版本或引用错误 | 拒绝登记，指出具体文件和字段 |
| 标准配对对比度低于阈值 | 显示可读性警告和对应颜色对；允许用户继续预览或使用，不自动改作者配色 |
| 分类前景完全重复 | 显示辨识警告和对应槽号；允许继续使用，要求页面提供非颜色区分方式 |
| 系统强制颜色模式启用 | 系统颜色覆盖主题的必要交互颜色，用户偏好保留 |

对比度检查只覆盖登记的组合；仍须检查实际页面的嵌套表面、浮层、选区和焦点。符合数据格式不等于页面完成视觉验收。

## 10 版本与兼容规则

| 版本 | 含义 | 变化规则 |
| --- | --- | --- |
| `schemaVersion: 1` | JSON 文件结构主版本 | 不兼容的结构变化才升级 |
| 标准版本 `1.0.0` | 颜色含义、搭配、状态、默认规则及解析契约 | 发布后主版本改变既有含义；次版本增加可选角色；补丁修正不改变既有含义的说明或校验缺陷 |
| 包 `version` | 作者发行版本 | 作者调整配色或内容时更新，与标准版本独立 |

版本采用三段非负整数 `主.次.补丁`，v1 不接受预发行后缀。兼容区间使用结构化 `min` 与 `maxExclusive`：包含下界、不包含上界，两端必须有序。宿主同时满足文件结构、主题标准区间和应用版本区间后，才能登记包。

本文确立标准 `1.0.0` 的设计契约。应用声明完整支持该标准后，删除角色、改变含义或调整既定状态优先级都属于不兼容变化。

新增颜色必须有完整默认值，使新宿主能解析旧主题。旧宿主遇到新颜色时拒绝，并给出兼容错误；作者使用新角色时应同步提高标准最低版本。未知核心颜色不静默忽略，以便发现拼写错误。包更新若删除已选主题 ID，须按既定回退规则处理。

兼容区间是必要条件，宿主还必须明确声明自己完整实现的主题标准版本：全部登记角色、缺省解析和本标准的应用规则接入后，才能声明支持 `1.0.0`。仅应用版本号命中区间不能放行，未声明标准能力的宿主拒绝登记。

当前应用已实现基础主题管理，尚未实现完整的主题包安装与标准能力声明。示例中的应用区间用于协议核验，发布主题包时须以首个完整支持该标准的实际应用版本作为下界；不表示现有 0.1.0 已支持安装。核验脚本使用显式的模拟宿主版本和标准能力，不将仓库当前版本当作已实现能力。

## 11 明暗属性与选择策略

`type` 是具体主题的明暗属性；跟随系统是用户如何选择主题的策略，不存在 `type: "system"`。

```ts
type ThemePreference =
  | { mode: "fixed"; themeId: string }
  | { mode: "system"; lightThemeId: string; darkThemeId: string };
```

固定模式保持具体主题 ID，系统外观改变不覆盖它。系统模式保存一浅一深两个主题 ID，类型必须与槽位匹配；系统改变时选择对应主题。对应主题不可用时，采用同类型内置主题；无法识别类型或系统外观时采用内置深色。

偏好存储、旧数据迁移、主题恢复和窗口同步的具体行为见[主题管理设计](需求设计/主题管理.md)。

## 12 维护与核验

[机器登记表](../src/plugins/theme/color-registry.json)是标准的唯一数据源，由主题管理插件维护；[内置主题插件](../src/plugins/builtin-themes/builtinThemesPlugin.ts)引用并贡献实际配色文件。文档不保存它们的重复 JSON 副本。角色登记表及主题 Schema 由 [generate-theme-docs.mjs](../scripts/generate-theme-docs.mjs) 生成，包清单 Schema 独立维护。

修改标准数据或内置主题后，在仓库根目录执行：

```sh
pnpm generate:theme
pnpm generate:theme-docs
pnpm check:theme-standard
```

`generate:theme` 更新 SDK 颜色类型、内置主题 CSS 与首屏脚本；`generate:theme-docs` 更新作者登记表和主题 Schema；[verify-theme-standard.mjs](../scripts/verify-theme-standard.mjs) 核对字段、引用、搭配覆盖、阈值、状态优先级、作者示例、包归属、兼容区间及错误输入。

核验直接读取实际内置主题，并保留与改造前配色的回归比对。透明度转为八位十六进制时按最近整数取 `AA`，允许量化误差不超过 `0.5 / 255`；阴影几何保持一致。低对比度只警告、分类重复归一化、缺省引用和组合叠加均有对应检查。

工程核验用于维护标准，不是运行时安装器。ZIP 解包、落盘事务、真实窗口、实际焦点邻接面及视觉辨识仍须由对应实现与页面验收覆盖。
