# 主题配色使用示例

**状态：正式设计配套示例 ｜ 标准版本：1.0.0 ｜ 日期：2026-10-15**

这些例子说明颜色用途与搭配，不要求插件采用特定组件或 HTML 结构。主题管理器已输出相关变量，具体交互的接入范围见[主题管理设计](../需求设计/主题管理.md)。

主题作者只修改 [墨色主题示例](examples/ink/ink-dark.theme.json) 的 `colors`。它已覆盖下列六类场景；未填写的颜色按登记表补齐。`paintSets`、`usageRules` 和 B 的规则由宿主维护，不写入主题文件。

## 1 状态提示与校验边界

例如，一段“内容尚未保存”的警告提示：

| 部位 | 颜色 |
| --- | --- |
| 提示背景 | `status.warningBackground` |
| 文字与图标 | `status.warningForeground` |
| 需要绘制的边界 | `status.warningBorder` |

这套搭配为 `feedbackWarning`。成功、错误、信息提示分别使用对应的同用途组合，不能直接把 `status.warning` 涂成背景。

若只是标识一个输入值错误，使用 `validationDanger`：保留输入对象原有文字与背景，只采用 `status.dangerBorder`。实际内侧底色通过 `validationSurface` 传入。

**叠加示例：**对象已选中且获得键盘焦点时，选中背景和指示继续保留，错误边框在内，焦点环在外；不能用错误边框替代焦点环。对象禁用后停止绘制校验边界，仍需说明的错误放到邻近提示区域。

## 2 搜索与内容高亮

| 情况 | 组合 | 颜色 |
| --- | --- | --- |
| 普通内容标记或其他搜索命中 | `highlight` | `highlight.background` + `highlight.foreground` |
| 当前定位的命中 | `highlightActive` | `highlight.activeBackground` + `highlight.activeForeground` + `highlight.activeBorder` |
| 用户选中了其中的文字 | `selection` | `selection.background` + `selection.foreground` |

**叠加示例：**搜索得到三个命中，当前在第二个；第二个使用当前高亮组合，并提供序号或“当前”标记。用户拖选第二个命中的文字后，被选中的文字范围改用文字选区组合；取消文字选择后恢复当前高亮。

这些颜色也能用于预览或其他内容中的标记。若有输入光标经过高亮或选区，使用该区域最终文字前景，避免光标消失。

## 3 放置反馈

| 输入状态 | 组合 | 表现 |
| --- | --- | --- |
| 尚未拖放，或目标禁用 | 无 | 不显示目标反馈 |
| 正在拖放，但目标不允许放置 | `dropForbidden` | 禁止反馈背景、文字与边界，附禁止图形或说明 |
| 允许放置且需要精确插入位置 | `dropInsertion` | 中性提示带上的 `drop.insertionIndicator`，附箭头或位置说明 |
| 允许放置，无精确插入位置 | `dropAllowed` | 允许反馈背景、文字与边界 |

`allowed=false` 与 `insertion=true` 同时出现时，采用禁止反馈，不绘制允许插入线。

**叠加示例：**被拖入的目标原本处于选中状态，目标仍使用通用选中配色；允许或禁止反馈放在独立提示区域。目标的选中标记、文字与键盘焦点不会被覆盖。

## 4 链接的访问与交互状态

| 情况 | 中性表面上的前景 |
| --- | --- |
| 未访问，默认 | `link.foreground` |
| 未访问，悬停／按下 | `link.hoverForeground` / `link.pressedForeground` |
| 已访问，默认 | `link.visitedForeground` |
| 已访问，悬停／按下 | `link.visitedHoverForeground` / `link.visitedPressedForeground` |
| 禁用 | `text.disabled`，停止激活及悬停／按下反馈 |

链接背景保持所在的中性表面，不因悬停而自动绘制普通对象的整块悬停背景；始终有下划线，必要时用线型或粗细提示交互。

**叠加示例：**链接文字被选中时，使用文字选区的前景；链接位于反色提示或分类标记内时，继承该组合前景。实现传入 `inheritForeground=true`，空配色结果表示“继承”，不表示“隐藏链接”。禁用行为仍然有效。访问状态使用实现可取得的信息，不能绕过浏览器的访问历史隐私限制。

## 5 反色表面

例如，在浅色界面上绘制一个深色说明区域：

| 部位 | 颜色 |
| --- | --- |
| 背景 | `surface.inverse` |
| 文字、普通图标、内部链接 | `text.inverse` |
| 必要内部边界 | `border.inverse` |

**焦点示例：**焦点环位于该深色区域内部、邻接深色底面时，使用 `focus.inverseRing`；如果焦点环包在整个区域外面，实际邻接的是浅色页面，则使用普通 `focus.ring`。决定因素是环旁边的颜色。

反色区域内部若有可操作对象，进入选中或禁用状态时使用完整通用组合；焦点继续按邻接面决定。反色文字的输入光标取 `text.inverse`，文字选区仍使用完整 `selection` 组合。

## 6 多类别区分

标准提供 `category.1` 至 `category.6` 六个无顺序槽位，每槽包含 `background`、`foreground`、`border` 三个颜色。数字不表达等级，也不绑定蓝色、红色等固定色相。

例如，三条故事线分别映射到槽 1、2、3：

| 绘制用途 | 取色 |
| --- | --- |
| 带底色的分类标记 | 同槽的背景、前景和边界 |
| 中性面上的分类文字、图形或数据线 | 同槽的 `foreground` |
| 可操作分类对象的悬停、按下、选中或禁用 | 完整通用状态组合，保留类别名称或形状 |

重新排序时，这三条故事线仍对应原来的槽，不能按新列表位置换色。类别 ID 与槽号的映射由 UI 实现保存，主题作者只决定槽内色值。

相邻分类填充以边界或中性间隔分开，同时展示名称、图案或形状。超出六类可复用槽，但须有非颜色区分方式。分类色不用于表示成功、失败或紧急程度。

## 7 校验行为

标准要求先补齐全部 A 色值，再执行 B；当前可用工程核验脚本检查，运行时警告尚未接入：

- 状态提示文字与背景、高亮文字与背景、链接与中性背景、反色文字与背景、分类文字与填充等，检查 4.5:1 目标。
- 必要边界、放置指示线和焦点检查 3:1 目标；禁用角色按登记表豁免。
- 六个分类前景完全重复时提示槽号；不同的十六进制写法会先归一化，不能借大小写或 `FF` 后缀绕过。
- 低对比度或分类重复只产生警告，不拒绝主题，也不替作者改色。未知变量、错误格式或覆盖标准规则仍拒绝登记。

静态检查通过后，仍需在实际页面确认搜索命中区别、拖放位置、焦点邻接面以及色觉差异下的类别辨识。此示例说明预期行为，不代表当前应用已实现这些交互。
