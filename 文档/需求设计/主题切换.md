# 主题切换

**状态：欢迎页主题设置已接入，运行验收待完成 ｜ 日期：2026-09-28**

## 1. 功能定位

主题切换是应用级外观设置，为作者提供不同环境下的界面配色。遵循[UI 设计规范](../UI设计规范.md)中“简约、大气、时尚、具备设计感”的要求，两套主题使用相同的布局、排版和组件体系。

主题适用于欢迎页、项目工作空间及应用内的辅助窗口。切换项目、关闭项目或重新启动应用后，保留作者的主题偏好。

## 2. 主题模式

| 模式 | 行为 | 定位 |
| --- | --- | --- |
| 深色 | 始终使用深色配色 | 延续现行 UI 规范的微冷中性深色风格 |
| 浅色 | 始终使用浅色配色 | 明亮、清爽，以白色和浅灰表面搭配克制的蓝色强调 |
| 跟随系统 | 根据操作系统当前的浅色或深色外观决定配色，并随系统变化更新 | 无需反复手动切换 |

首次启动默认选择**深色**，与现行设计保持一致；“跟随系统”由作者主动选择。无法识别系统外观时使用深色，不改变已保存的“跟随系统”模式。

首期不包含自定义配色、主题商店、按项目设置主题或按时间自动切换。

## 3. 设置入口与操作

- 欢迎页与项目工作空间的设置入口均可进入“设置 → 外观 → 主题”。
- 使用一组单选项展示“深色、浅色、跟随系统”，同时提供简洁的配色预览；选中状态通过文字、选中标记和边界共同表达。
- 选择后立即应用并自动保存，无需确认、重启或重新打开项目。
- “跟随系统”旁显示当前实际外观，例如“当前为深色”；实际外观变化后仍保持该选项被选中。
- 支持鼠标和键盘操作；切换后焦点保持在当前选项，不关闭设置页面。

## 4. 切换范围与写作连续性

| 对象 | 切换规则 |
| --- | --- |
| 页面与停靠面板 | 背景、文字、图标、边界和交互状态统一切换 |
| 输入框、按钮、文件目录树、标签页 | 各状态使用对应主题的语义颜色 |
| 菜单、提示、对话框及独立窗口 | 与主界面保持同一主题，包括挂载在页面外的浮层 |
| 编辑器 | 默认文稿背景、正文、光标、选区和辅助标记同步切换 |
| 原生标题栏与系统对话框 | 在平台支持范围内与应用实际主题协调；无法完全控制的部分使用平台原生外观 |
| 插图、封面及内容图片 | 保留素材本身的颜色 |

切换只改变外观，不改变字号、行距、界面密度、圆角、布局和面板宽度。欢迎页继续采用 Spacious，工作空间继续采用相应页面的密度预设。

切换时保留打开的文件、未保存内容、光标、选区、滚动位置、撤销记录和输入法状态，不刷新页面或重新创建编辑器。

若后续提供独立的文稿阅读配色：默认随应用主题；作者明确选择的阅读配色单独保存，并作为完整的背景与文字组合保留，避免只保留背景造成文字不可读。

## 6. 主题状态与应用方式

区分**选择的模式**和**当前实际主题**：

| 状态 | 可选值 | 是否保存 |
| --- | --- | --- |
| themeMode | dark / light / system | 保存作者偏好 |
| resolvedTheme | dark / light | 根据偏好与系统外观计算，不单独保存 |

解析规则：dark 对应 dark；light 对应 light；system 对应当前系统外观，无法获取时对应 dark。

共享主题层负责读取偏好、解析主题、监听系统变化和通知窗口。组件只引用语义变量，不自行监听系统外观。

根节点使用 data-ui-theme="dark" 或 data-ui-theme="light" 切换颜色变量，同时设置对应的 color-scheme，并协调平台原生窗口外观。跟随系统是偏好模式，不作为第三套颜色变量。

主题变量只覆盖颜色与材质；密度、字体和尺寸继续由现有设计系统管理。不得通过整体反色滤镜生成浅色主题，或用全局 transition: all 切换外观。

## 7. 保存、启动与窗口同步

- 偏好保存在本机用户级应用设置中，独立于小说目录，不进入项目文件和 Git 版本管理。
- 同一用户的欢迎页、项目窗口和辅助窗口共享该偏好；新窗口直接继承当前模式与实际主题。
- 改变模式时同步通知已打开的窗口，避免出现部分窗口深色、部分窗口浅色。
- 启动时在首个完整界面显示前读取偏好并解析主题；载入背景与最终界面主题协调，避免错误主题闪烁。
- 仅在 themeMode 为 system 时响应系统外观变化；手动选择深色或浅色后，系统变化不覆盖作者选择。
- 每次选择自动保存。设置缺失、格式损坏或取值未知时回退为深色，应用正常启动。
- 保存失败时，本次会话继续使用作者选择，并在设置页面提示“主题设置未能保存，下次启动可能恢复原设置”，提供重试；不弹出阻断写作的对话框。

## 8. 可读性与可访问性

- 普通文字及占位提示与背景对比度至少 4.5:1；必要控件边界、图标和焦点指示至少 3:1。禁用状态与纯装饰边线按现行规范处理。
- 本方案色值的数学核对中，两套主题的常规文字、交互文字与状态文字在上述中性表面上的最低对比度分别约为 4.56:1、4.62:1；必要控件边界最低约为 3.18:1、3.62:1；实色操作按钮文字最低约为 4.69:1。
- 以上计算只验证列出的颜色组合，不代表实际页面已通过验收；新增背景、透明叠加和其他状态组合需按实际呈现重新检查。
- 遵循系统减少动态效果与强制颜色设置；强制颜色模式下使用系统色与可见焦点，保持偏好记录。
- 主题切换不使用整页闪烁、缩放、旋转等过渡。首期采用即时替换，保留已有必要的控件交互反馈。

## 9. 验收要求

1. 欢迎页、工作空间、编辑器及所有浮层在深色与浅色下颜色完整，无遗漏、混用或不可读内容。
2. 两套主题均保持简约、舒展的视觉效果，不因浅色新增密集描边或投影。
3. 选择任一模式后立即生效，重启后保持；小说目录与版本记录没有外观设置变更。
4. 跟随系统时实时响应系统外观；手动选择主题时不受系统变化影响。
5. 多窗口同步，新开窗口继承；启动和打开窗口无错误主题闪烁。
6. 切换后文件内容、输入法输入、编辑历史、光标、选区、滚动位置及面板状态保持。
7. 键盘操作、焦点、文字选区、禁用与错误状态在两套主题中可识别，对比度符合要求。
8. 设置读取或保存失败时按既定规则降级，不阻断启动和写作。
9. 按 UI 规范检查规定窗口尺寸与缩放比例，并分别核验 macOS、Windows 的原生外观协调情况。
