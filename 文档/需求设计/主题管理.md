# 主题管理设计

**状态：正式设计，基础管理已实现 ｜ 日期：2026-10-16**

本文规定主题管理的职责、选择行为、应用流程及实现边界。颜色语义、文件格式和校验规则统一由[主题标准 v1](../主题标准-v1.md)规定，布局、字体、密度与组件形态遵循 [UI 设计规范](../UI设计规范.md)。

## 1 设计目标

应用提供一个主题管理器，统一管理所有配色。内置主题和自定义主题使用同一数据格式、登记入口与解析过程，按主题 ID 平级排列；`dark`、`light` 只是主题属性，不形成父子层级或继承关系。

内置的「Lodestory 深色」和「Lodestory 浅色」是默认随应用提供的两个普通主题项。主题管理插件在自己的选择配置中引用它们的 ID，指定首次启动和主题不可用时的回退选择；任何已登记主题都可承担这些职责。

主题设置属于用户级应用偏好，所有项目共用，不写入小说目录或项目版本记录。切换只改变配色，不改变字体、密度、布局、内容图片或写作数据。

## 2 对象与职责

| 对象 | 职责 | 实现位置 |
| --- | --- | --- |
| 主题定义 | 声明 ID、名称、明暗属性和部分或完整的标准颜色值 | [SDK ThemeDefinition](../../packages/sdk/src/theme.ts) |
| 内置主题 | 与自定义主题相同格式的独立配色数据 | [深色](../../src/plugins/builtin-themes/dark.theme.json)、[浅色](../../src/plugins/builtin-themes/light.theme.json) |
| 内置主题插件 | 依赖 `themeKey`，与自定义插件一样调用 `registerTheme`，停用时撤销登记 | [builtinThemesPlugin.ts](../../src/plugins/builtin-themes/builtinThemesPlugin.ts) |
| 选择配置 | 仅指定首次默认主题 ID 和深浅回退主题 ID，不含配色 | [theme-config.json](../../src/plugins/theme/theme-config.json) |
| 颜色标准数据 | 定义通用角色、缺省值与 B 校验规则，归主题管理插件维护 | [color-registry.json](../../src/plugins/theme/color-registry.json) |
| 颜色解析器 | 校验主题数据，按标准补齐全部颜色，生成 CSS 变量及阴影 | [resolveTheme.ts](../../src/plugins/theme/resolveTheme.ts) |
| 主题目录与选择逻辑 | 统一登记、撤销、查询、选择和缺失回退，不访问平台 API | [themeManager.ts](../../src/plugins/theme/themeManager.ts) |
| 平台适配 | 保存偏好、应用 DOM 变量、监听系统外观、同步窗口 | [themeStore.ts](../../src/plugins/theme/themeStore.ts) |
| 主题管理插件 | 向插件内核提供服务，管理同步资源与 Provider 生命周期 | [themePlugin.ts](../../src/plugins/theme/themePlugin.ts) |
| 设置页面 | 从服务读取主题目录、展示预览和修改选择 | [ThemeSettingsPage.tsx](../../src/plugins/settings/ThemeSettingsPage.tsx) |

主题包是后续安装和发行的单位，可以包含多套平级主题。配色贡献者向管理器登记数据，不创建或替换另一套全局主题服务。

主题业务源码全部位于 `src/plugins`：管理逻辑及标准位于 `theme`，内置配色及其贡献插件位于 `builtin-themes`；共享契约位于 SDK。管理器与设置页均不直接导入内置配色插件，应用的 [appPlugins.ts](../../src/app/appPlugins.ts) 只负责装配插件，调用无参的 `createThemePlugin()`；主题管理插件自行读取同目录下的 `theme-config.json`。

## 3 选择策略与快照

主题身份使用稳定的 `id`。例如，两套 `type: "dark"` 的主题仍可按不同 ID 独立选择。

```ts
type ThemePreference =
  | { mode: "fixed"; themeId: string }
  | { mode: "system"; lightThemeId: string; darkThemeId: string };
```

| 选择策略 | 行为 |
| --- | --- |
| 固定主题 | 始终选择指定 ID，系统外观变化不覆盖用户选择 |
| 跟随系统 | 保存一浅一深两个主题 ID，系统变化时选择对应项；每个槽位均可指定属性匹配的自定义主题 |

“跟随系统”是一种选择策略，不是第三套主题，也不存在 `type: "system"`。

`ThemeConfig.defaultThemeId` 指定首次选择，`fallbackThemeIds.dark/light` 指定回退 ID，并作为默认系统槽位。当前应用分别配置 `lodestory.builtin.dark` 和内置深浅 ID；这些值由主题管理插件的 `theme-config.json` 维护，解析与选择逻辑不写死具体 ID。无法识别系统外观时按深色处理，仍保留系统策略。

`ThemeSnapshot` 区分用户选择和当前实际结果：

| 字段 | 含义 |
| --- | --- |
| `preference` | 用户选择的策略及主题 ID |
| `theme` | 实际应用的主题，含完整颜色与变量；启动准备前或目录为空时为 `null` |
| `themes` | 所有已登记主题的平级列表 |
| `fallbackThemeIds` | 配置的深浅回退 ID，供设置页初始化系统槽位；对应项可被普通撤销 |
| `unavailableThemeId` | 当前请求的主题不可用时记录其 ID，否则为 `null` |
| `persistenceError` | 最近一次偏好保存失败 |
| `windowError` | 原生窗口外观同步失败 |

主题记录和快照不可变。状态未变时返回相同快照，发生变化时通知订阅者。

## 4 登记、撤销与回退

SDK 通过共享的 `themeKey` 暴露 `ThemeService`：

| 接口 | 行为 |
| --- | --- |
| `getSnapshot()` | 获取目录、选择与实际主题 |
| `subscribe(listener)` | 订阅变化，返回取消订阅函数 |
| `registerTheme(definition)` | 解析并登记主题，返回撤销函数；重复 ID 拒绝，不覆盖已有主题 |
| `setPreference(preference)` | 设置选择；主动选择的 ID 必须已登记，系统槽位属性必须匹配 |
| `retry()` | 重试保存当前偏好及原生窗口同步 |

登记不改变用户偏好。所有配色插件（包括内置）声明依赖 `themeKey`，激活时登记，停用时调用撤销函数；完整用法见 [SDK 文档](../../packages/sdk/README.md)。

管理器激活时目录为空，只开放统一登记服务。默认和回退配置只保存 ID；初始插件全部激活后，管理器检查默认 ID 已登记、两个回退 ID 的明暗属性正确，再应用选择。缺失或不匹配会使启动失败并回滚，不能靠特殊配色通道绕过登记。

内置与自定义贡献拥有相同生命周期：停用时撤销自己的登记，部分登记失败时也撤销之前已成功的项。管理器运行时允许卸载内置配色插件；依赖关系始终是“贡献者依赖管理器”。

从本机保存或其他窗口恢复偏好时，允许 ID 暂未登记，以适应贡献者晚于管理器启动的情况。界面启动后，请求的主题不可用时应用回退主题，保留原偏好，并在设置页提示。主题重新登记后自动恢复原选择。

系统策略按当前系统属性回退。固定策略按本次会话已知的主题属性回退；启动时尚不知道该主题属性，则按深色回退。配置的回退项也不可用时，按登记顺序选择同属性的其他项，再选择任一剩余项。目录为空时 `theme` 为 `null`，清除管理器写入的变量及主题标识，由静态首屏样式维持可读界面；偏好仍保留。重复撤销无效，旧撤销函数不能删除同 ID 的新登记。

## 5 设置页面

设置入口为“设置 → 外观 → 主题”。页面遍历服务中的主题列表，统一展示名称、深浅属性和真实配色预览，不按来源或类型划分等级。

- 主题卡片按 ID 单选，选中后立即应用并自动保存。
- 预览使用该主题补齐后的完整变量，不受当前全局主题影响。
- 选择“跟随系统”后，分别设置系统为浅色和深色时使用的主题；候选项按属性匹配。
- 当前状态展示实际主题名称；主题不可用时说明回退结果，目录为空时显示“暂无可用主题”。
- 缺少任一明暗属性的主题时，禁用系统策略及槽位选择，避免提交不完整的配对。
- 支持键盘操作和可见焦点，选中通过标记与边界共同表达。
- 保存或原生窗口同步失败时显示说明及重试入口，不阻断写作。

当前页面提供已登记主题的选择，不包含主题包导入、编辑或市场入口。

## 6 应用与同步

颜色解析依次使用当前主题显式值、标准对应属性的缺省值、标准缺省引用。缺省值不从其他主题继承，也不能残留上一套主题的颜色。解析器先完成全部角色，再应用完整变量集合。

DOM 根节点设置 `data-ui-theme-id` 标识实际主题，`data-ui-theme` 和 `color-scheme` 表达明暗属性。界面通过标准映射的 CSS 变量绘制；Canvas 等实现可读取快照中的完整角色表。主题包不携带渲染代码或 CSS 选择器。

原生窗口只需要明暗属性：固定策略传入实际主题的 `type`；系统策略解除固定外观，再读取系统结果。原生调用串行执行，过期的异步结果不能覆盖新选择；停止同步后不能继续更新快照。

同源窗口通过 `storage` 事件和 `BroadcastChannel` 同步选择。保存失败时仍可广播本次会话选择及错误状态。各窗口须各自登记相同的主题贡献，目录数据不通过偏好广播分发。

启动按以下顺序执行：

1. UI 插件提供 `uiKey`；主题管理插件创建空目录，提供 `themeKey`，登记 `ThemeProvider` 与其 `prepare` 回调。
2. 内置和自定义主题插件全部通过 `registerTheme` 登记配色，页面插件完成页面登记。
3. 内核发送 `pluginsReady`；UI 插件按包装顺序等待各 `UiWrapper.prepare` 完成。主题管理器在此校验 ID、恢复有效选择、应用 DOM 配色并等待首次原生同步。
4. 准备成功后才创建 React 根视图。准备失败按启动错误回滚所有插件；原生外观同步失败仍通过快照报告，可进入界面重试。

登记阶段可以读取目录和偏好，`theme` 保持 `null`，不会因主题登记先后而反复绘制中间配色。UI 插件只认识通用的准备回调，不依赖主题业务；也不依赖多个事件监听者的订阅先后顺序。模块导入和插件工厂调用不修改 DOM、不启动监听。

停用或激活失败时先移除 UI 包装，再清理系统、存储、广播、原生监听和驱动 DOM 的订阅；延迟返回的监听也必须清理。重新挂载创建新目录，从保存的偏好恢复选择，所有主题均由各贡献插件重新登记。原生窗口调用队列跨重挂载保持串行，避免旧请求晚完成后覆盖新外观。

## 7 保存与首屏

偏好保存为 `localStorage["lodestory.theme-preference"]` 中的 JSON。新键缺失时读取旧键 `lodestory.theme-mode`：

| 旧值 | 恢复结果 |
| --- | --- |
| `dark` | 固定选择配置的深色回退 ID |
| `light` | 固定选择配置的浅色回退 ID |
| `system` | 系统策略，使用配置的浅深回退 ID |
| 缺失或无效 | 固定选择配置的默认 ID |

迁移先在内存中完成，下一次成功保存时写入新键。新键存在但无效时回退默认选择；存储不可用不阻断启动。保存失败仍应用本次会话的主题，并暴露可重试错误。

[首屏脚本](../../public/theme-bootstrap.js)和[内置主题 CSS](../../src/styles/theme-colors.css)由内置主题插件中的实际配色数据生成，在 React 初始化前应用内置配色。其生成入口为 [generate-theme-assets.mjs](../../scripts/generate-theme-assets.mjs)，不手工维护另一套色值。这些生成产物保留在浏览器静态资源与样式目录，工程生成、核验脚本保留在 `scripts`。生成脚本与运行时共同读取 `src/plugins/theme/theme-config.json`，按 ID 选择首屏默认和回退配色，并检查引用存在、属性匹配。当前构建只收集内置配色；若配置改用自定义 ID，也须将相应数据纳入首屏构建输入。

当前首屏只识别内置主题。保存的自定义 ID 在静态首屏使用回退配色，所有初始贡献登记完成后，运行时首次应用便直接使用它；自定义配色的首屏缓存仍待实现，因此暂不承诺自定义主题启动时无回退闪现。

1. 欢迎页、工作空间、浮层及辅助窗口完整取用标准颜色；强制颜色模式与可见焦点有效。
2. 切换保留打开的文件、未保存内容、光标、选区、滚动位置、撤销记录与输入法状态，不重建编辑器。
3. 真实多窗口、系统外观变化及各平台原生窗口协调正常；配置失败可恢复。
4. 实际背景、嵌套区域、文字选区和焦点邻接面的可读性达标，分类和状态同时提供非颜色标记。
