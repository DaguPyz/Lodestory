# 全局右键菜单

**状态：公共组件及首期区域已实现，浏览器验证通过；原生平台验收待完成 ｜ 日期：2026-09-29**

## 1. 功能定位

应用提供统一的右键菜单机制，不同区域根据右键目标显示对应的菜单列表。菜单的外观与交互遵循[UI 设计规范](../UI设计规范.md)，菜单内容和执行动作由各业务区域提供。

采用“公共菜单组件 + 区域触发器 + 上下文菜单配置”的方案，基于项目现有的 `@base-ui/react/context-menu` 封装。每个窗口同时只打开一个顶层业务菜单；子菜单属于同一次菜单会话。

右键菜单提供已有动作的快捷入口，与按钮、更多操作菜单和快捷键复用相同的业务处理。所有动作均保留可见或键盘可访问的入口。

### 1.1 组件设计约束

1. **独立、可配置**：菜单组件作为独立公共模块，菜单项、显示与禁用条件、业务上下文和执行回调均由调用方传入，公共组件内部不写入具体业务菜单。
2. **全项目可复用**：任意页面、面板、列表条目、对话框和浮层均可接入；支持现有 DOM 元素和自定义组件作为触发区域，不改变原有布局。首期接入清单不限制组件适用范围。
3. **高内聚、低耦合**：菜单展示、定位、事件隔离、键盘、焦点和打开状态在公共模块内维护；对象校验、文件操作和项目状态由业务适配层处理，通过配置和回调连接。

## 2. 响应区域识别

### 2.1 区域边界

每个支持自定义菜单的区域通过公共区域组件接入，内部使用 `ContextMenu.Root` 和 `ContextMenu.Trigger` 声明触发范围，并传入菜单配置与业务上下文。

响应流程：

1. 浏览器根据鼠标位置确定目标 DOM 元素，派发 `contextmenu` 事件。
2. 事件沿父节点向上冒泡，由最近的菜单区域处理。点击条目内部的图标、文字或留白，均属于该条目。
3. 区域组件取得当前对象的稳定标识，例如项目 ID、文档 ID、作品根目录和相对路径，生成菜单项。
4. 显示该区域菜单，并关闭上一顶层菜单。右键位置只用于菜单定位，业务区域由 DOM 边界确定。

目录树的目录条目、文档条目与树内空白处分别声明范围；标签条目与标签栏空白处分别声明范围。目录条目的触发器覆盖自身行，不覆盖整棵子树；子目录和文档拥有独立上下文。

### 2.2 嵌套与默认行为

- 嵌套区域优先响应最内层区域，处理后停止冒泡，避免父区域同时打开菜单。
- 内层区域明确选择原生菜单或没有可展示的菜单项时，也不能触发外层业务菜单。
- 仅在确认显示自定义菜单时调用 `preventDefault()`；原生编辑区域和未配置区域保留默认行为。
- 输入框、`textarea`、`contenteditable` 默认使用原生响应，也可由所在业务显式配置自定义菜单；响应方式由配置决定。原生响应区域具有独立边界，外层菜单不能接管。
- 菜单浮层自身及其子菜单由菜单组件处理，不参与页面区域匹配。模态对话框打开时，底层页面不能响应右键。

## 3. 首期区域与菜单

首期使用现有业务能力，默认菜单如下；动作行为分别沿用[文件目录树与新建文档](文件目录树.md)、[编辑功能](编辑功能.md)和[项目索引存储](欢迎页/项目索引存储.md)。

| 响应区域 | 菜单项 | 上下文与执行规则 |
| --- | --- | --- |
| 欢迎页最近项目条目 | 打开项目、重新定位目录、从最近项目移除 | 操作右键命中的项目；目录不可用时禁用“打开项目”，允许重新定位和移除；移除只修改索引 |
| 目录树根目录及目录条目 | 新建文档、展开或折叠 | 新建默认保存到右键命中的目录；根据当前展开状态显示“展开”或“折叠” |
| 目录树文档条目 | 打开文档 | 打开或切换到右键命中的文档 |
| 目录树内容空白处 | 新建文档 | 默认保存到作品根目录 |
| 已打开的文档标签 | 保存、关闭 | 操作右键命中的标签，即使该标签当前未激活；关闭沿用保存与失败保护 |
| 标签栏空白处、未打开文档的编辑区 | 新建文档 | 沿用现有新建入口的默认目录规则 |
| 文稿标题及非输入的文稿区域 | 保存 | 保存当前文稿 |
| 正文输入区域、搜索框及对话框输入框 | 平台原生编辑菜单 | 保留复制、粘贴、撤销、重做和输入法行为 |

右键打开菜单本身不打开文件、不切换当前编辑标签、不改变目录展开状态。通过菜单执行动作后再更新相应界面；新建对话框的默认目录直接取本次右键上下文。

首期不增加新建目录、重命名、删除文件、关闭其他标签或版本管理动作；这些动作随对应业务需求接入公共菜单。欢迎页现有“更多操作”入口继续可用，并与右键菜单复用重定位和移除动作。

正文及输入框首期保留原生菜单；后续自定义编辑菜单接入时，需通过编辑器接口执行动作，并验证选区、撤销记录、剪贴板权限和中文输入法行为。

## 4. 菜单配置与上下文

| 配置 | 用途 |
| --- | --- |
| 触发区域 | 传入子元素或通过组合接口复用现有 DOM、自定义组件 |
| 响应方式 | 选择自定义菜单或保留原生行为 |
| 业务上下文 | 调用方定义的泛型数据，可选；项目 ID、文档路径等只在对应业务中定义 |
| 菜单配置 | 支持静态菜单项列表，或根据当前上下文生成菜单项的函数 |
| 菜单项 ID 与名称 | 标识动作并展示可读名称 |
| 显示与禁用条件 | 根据目标状态、加载状态和业务能力决定菜单项是否显示、是否可执行 |
| 执行动作 | 调用已有业务处理；支持异步结果和错误反馈 |
| 可选展示信息 | 图标、分组、快捷键提示和子菜单 |

公共接口不要求调用方提供项目 ID、文档 ID 或固定的业务区域类型。新增业务可以传入自己的上下文类型与菜单配置，无需修改公共组件或增加业务分支。

分隔线在过滤隐藏项后整理，不出现连续分隔线或首尾分隔线。没有可展示项时不显示空菜单；已展示但暂时不可执行的动作使用禁用状态。快捷键提示只显示实际已绑定的快捷键。

业务适配层在打开时固定本次菜单的目标标识，执行前核对当前项目、目标是否仍存在以及动作是否可用；公共菜单只调用配置中的回调。不能因菜单打开期间标签切换、列表重排或项目切换而操作其他对象。

保存、新建、打开和关闭均复用现有业务入口，保留路径校验、串行保存及失败保护。异步动作防止重复提交；失败按原业务位置提供错误和重试入口。菜单关闭不取消已经明确执行的业务动作。

## 5. 公共实现与生命周期

| 模块 | 职责 |
| --- | --- |
| 公共菜单组件 | 封装 Base UI 的菜单结构、主题、密度、定位、子菜单、禁用状态与键盘交互 |
| 区域组件 | 声明 DOM 范围、响应方式、菜单配置和上下文，隔离嵌套事件 |
| 窗口级菜单管理 | 协调当前打开的顶层菜单，以及关闭、页面切换和组件卸载 |
| 业务处理层 | 校验目标与操作条件，执行已有动作并返回结果 |

各区域复用同一组件封装，可各自挂载 `ContextMenu.Root`，由窗口级管理层协调打开状态。菜单内容经 `Portal` 渲染到统一浮层容器；由 Base UI 负责定位和菜单内交互，公共封装补齐窗口级协调与应用快捷键。

新增区域只需接入区域组件并提供菜单配置；公共层不根据页面类名或条目显示文字判断业务对象。

### 5.1 依赖边界

- 公共模块统一放在 `src/components/context-menu/`，仅依赖 React、Base UI、共享设计系统和通用工具；不导入具体页面、项目或文档业务类型、业务状态管理及 Tauri 业务接口。
- 业务页面或适配层引用公共模块，负责组装菜单配置、读取业务状态、校验目标和执行动作；公共模块通过回调通知调用方。
- 窗口级管理层在应用窗口入口接入一次，仅维护菜单实例标识、打开状态与关闭能力。页面或项目切换通过通用关闭接口通知管理层，管理层不读取页面路由或项目状态。
- 配置、上下文与回调可在组件更新时替换；注册、事件监听、浮层和关闭状态在公共模块内自动清理，业务页面不重复编写菜单生命周期逻辑。

### 5.2 生命周期

点击菜单外部、按 Esc、切换到另一右键区域、页面或项目切换、目标卸载、窗口失焦时关闭菜单。触发区域滚动或窗口尺寸变化时关闭菜单，菜单自身滚动不触发该规则。按菜单项执行动作后关闭菜单；展开子菜单时保持当前会话。

## 6. 定位、主题与键盘

- 鼠标触发时以 `clientX/clientY` 为视口锚点；接近边缘时自动调整方向或位置，内容过高时菜单内部滚动。
- 距窗口边缘至少 16px；常规宽度 224–384px、圆角 12px，窄窗口下以可用宽度为上限，其他尺寸使用 UI 规范的密度预设。
- 浮层显式继承触发区域的密度，颜色与阴影使用共享主题变量；切换深色、浅色后保持当前菜单内容和目标。
- 可聚焦的触发区域支持 `Shift+F10` 和菜单键；键盘触发时以当前聚焦对象为目标，菜单定位在该对象附近。
- 菜单内支持方向键、Enter、Home/End 和 Esc；禁用项不能执行，子菜单使用左右方向键进入与返回。
- 菜单关闭且未执行跳转、对话框或其他焦点动作时，恢复到触发区域；目标已卸载时移到所在区域的合理入口。执行动作后由业务流程决定焦点。
- 中文输入合成期间不抢占快捷键、Enter 或 Esc；保留文本光标、选区、滚动位置和撤销历史。

## 7. 验收要求

1. 各响应区域显示自己的菜单；点击条目内部图标、文字和留白时，操作目标相同。
2. 在未激活标签或未打开文档上右键，菜单始终针对命中对象；打开菜单本身不切换文稿。
3. 嵌套区域只打开最内层菜单；目录子项不误触发父目录菜单，空白区域使用自己的默认上下文。
4. 全窗口同时只有一个顶层业务菜单；换区域、切页、目标卸载、失焦及触发区域滚动时正确关闭。
5. 四个窗口边角、长菜单和不同缩放下，菜单完整可见，无容器裁切或遮挡模态对话框。
6. 显示、禁用和异步防重复条件有效；菜单打开后目标失效时不会操作其他对象。
7. 右键目录后新建到该目录；保存与关闭标签沿用自动保存和失败保护；移除最近项目不删除磁盘文件。
8. 鼠标、菜单键、`Shift+F10`、方向键、Enter 和 Esc 可完成操作，关闭后焦点符合规则。
9. 正文、搜索框和对话框输入框保留原生编辑行为，外层自定义菜单不抢占选区、撤销记录或中文输入。
10. 深色、浅色与各密度下样式一致，菜单内外的业务动作和错误处理一致；分别核验 macOS、Windows 的实际行为。
11. 使用静态配置与上下文生成函数均可展示菜单；修改配置后无需修改公共组件，显示、禁用和执行回调按配置生效。
12. 在不含项目或文档数据的普通元素、自定义组件、对话框与 Portal 浮层中均可接入，布局保持原样；输入区域可以显式配置原生或自定义响应。
13. 公共模块无页面、项目或文档业务依赖；新增一种业务上下文无需改动公共模块，页面不重复实现定位、键盘、焦点或菜单关闭逻辑。
