# 大纲设计

状态：核心设计思路已确认。时间线列表通过项目存储插件的通用字节文件能力保存到作品目录；列表数据格式、编码和路径规则由大纲插件负责。画布及编辑已有条目资料的界面尚未实现，画布内部的数据结构与保存方式后续单独设计。

## 功能定位

大纲用于梳理整个故事的脉络：以故事实际发生的时间为主轴，将一个个事件依次组织起来，并关联人物、地点、地图和世界设定。

**整个设计空间是一张以线性时间轴为主干、可以向外展开故事细节与世界设定的无限画布。**

大纲、人物、地点和地图的设计都围绕这一共同画布展开，逐步构建完整的故事与世界观。

导航列表中的一条记录代表一份完整的时间线梳理，其中可以包含多个事件；新项目从空列表开始，不自动填入示例故事。

## 已确认的设计原则

### 时间线是必需的主干

大纲按照故事实际发生的时间，由早到晚线性梳理。时间线是整个大纲的基础组织结构，不是可有可无的展示选项。

正文如何使用倒叙、插叙或其他叙事方式，由作者自行处理，不属于本功能的设计范围；大纲不另外维护正文的讲述顺序。

### 通过事件展开故事

时间线上的事件承载具体故事内容，围绕以下信息展开：

| 要素 | 回答的问题 |
| --- | --- |
| 时间 | 什么时候发生？ |
| 地点 | 在哪里发生？ |
| 人物 | 哪些人物参与？ |
| 事件内容 | 发生了什么？ |

这些信息帮助作者梳理和查找事件。是否必填、如何关联以及怎样标识同一事件，留待数据设计确定，本文不将四项信息的组合规定为唯一标识。

### 同一时刻允许多个事件并列

同一时刻，不同人物、不同地点可以发生不同事件。这些事件在相同时间位置并列呈现，不强行排列出不存在的先后关系；整个大纲仍沿时间向前推进。

例如，下表中的两个“第二天黎明”发生在同一时刻：

| 时间 | 事件 | 关联人物与地点 |
| --- | --- | --- |
| 第一天午后 | 王子被囚禁 | 王子、城堡 |
| 第二天黎明 | 主角调查王子的下落 | 主角、城内 |
| 第二天黎明 | 反派集结军队 | 反派、城外 |
| 第二天夜晚 | 主角展开营救 | 主角、王子、城堡 |

此例仅说明时间顺序与同时发生的关系，不规定时间字段的存储格式。

### 人物、地点与世界设定向外展开

作者可以围绕同一份大纲，从不同关联查看故事：

- 沿时间线，查看整个故事如何一步步发展。
- 展开一个事件，查看时间、地点、参与人物和具体内容。
- 沿人物关联，查看该人物经历了哪些事件。
- 沿地点关联，查看该地点发生过什么，并进一步展开地图及相关世界设定。

这些展开都围绕时间线组织，在同一无限画布中完成梳理与设计。画布提供向外展开的空间，同时保留故事的时间先后关系。

## 插件接入约束

以下是依据仓库架构原则确定的实现边界，不代表相应能力已经存在。

| 方面 | 约束 |
| --- | --- |
| 归属 | 扩展现有 `outline-design` 插件，拥有列表条目格式、校验、展示及新建和删除交互。后续事件、时间组织及画布业务另行设计；人物、地点和地图资料由各自所属功能管理，具体是否拆分独立插件按职责与替换需求确定。 |
| 协作 | 复用 `layoutKey`、`workbenchKey`、`contextMenuKey` 和 `projectStorageKey`。大纲通过 `ProjectStorageService.getFiles(sessionId)` 读取和写入共享字节文件，不依赖 `documentsKey`；大纲自己定义 UTF-8、列表 JSON 和目录规则。跨插件访问人物、地点等资料时，由资料所属插件提供公开契约。 |
| 接入 | 导航入口和画布工作内容通过布局服务的 `registerContent` 按用途登记，由布局决定呈现位置。默认实现通过配置或 `appPlugins.ts` 显式选择，入口不编排业务连接。 |
| 生命周期 | 大纲模型和项目存储服务属于单个工作台项目会话；项目存储插件管理共享字节缓冲、自动保存、冲突和离开前保存，大纲不另建保存定时器或退出流程。 |
| 验收 | 确认列表通过公开 SDK 契约接入，通用保存和失败处理由项目存储插件统一管理；更换兼容字节文件服务无需修改列表消费者，也不影响正文编辑。事件时序、并列及画布关联展开留待后续功能单独验收。 |

初始化失败时释放已创建的部分资源并撤销贡献；切换项目或停止插件前，先完成保存或明确保留未保存状态。保存失败时保留用户内容并阻止会丢失内容的离开操作。停止时先让组件结束对服务的使用，再释放订阅及其他会话状态。暂时离开工作台应保留项目会话中的编辑状态。

## 当前实现状态

现有 [`outline-design`](../../src/plugins/outline-design/outlineDesignPlugin.tsx) 插件通过布局服务贡献“大纲设计”导航面板，并通过 SDK 获取工作台、公共右键菜单和项目存储能力。[面板](../../src/plugins/outline-design/OutlineDesignPanel.tsx)显示时间线列表；空白处可右键新建，条目可右键新建或删除。

固定模拟数据已移除。列表从作品目录读取，并将新建和删除写入 `.lodestory/outline-design/timelines/<uuid>.json`；重开项目后可再次读取。项目存储提供会话内共享字节快照和读写状态，不解释编码、UUID 文件名、业务目录或 JSON；这些规则由 `outline-design` 插件负责。当前尚未实现画布、事件编辑器和编辑已有条目资料的界面；列表保存结构与接入细节见[时间线列表数据存储](大纲设计/时间线数据存储.md)。

这些进展不意味着应用已经支持运行中任意安装或卸载功能插件。

## 后续需要细化的内容

- 时间如何表达，包括精确时间、相对先后、时间范围及尚未确定的时间。
- 事件的粒度、标识，以及事件与人物、地点之间的关联规则。
- 人物、地点、地图与世界设定在画布中的编辑范围、展开和收起方式。
- 画布导航、缩放与定位方式，以及画布位置和事件时间的操作关系。
- 为已有时间线条目补充资料编辑界面，并决定是否需要手动排序。
- 画布内部的数据结构、保存位置及人物等实体的公开关联契约后续单独设计，不沿用本轮列表文件来承载它们。
