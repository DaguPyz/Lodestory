# 大纲设计

状态：时间线列表、通用画布和数值横轴已接入。`timeline` 拥有时间线元信息、数值轴与保存流程，`outline-design` 通过公开 SDK 展示入口。原点表示故事起点，起点数值、刻度间隔与单位可设置。事件、卡片、连线及人物地点关联仍为后续设计。

## 功能定位

大纲用于梳理整个故事的脉络：以故事实际发生的时间为主轴，将一个个事件依次组织起来，并关联人物、地点、地图和世界设定。

**整个设计空间是一张以线性时间轴为主干、可以向外展开故事细节与世界设定的无限画布。**

大纲、人物、地点和地图的设计都围绕这一共同画布展开，逐步构建完整的故事与世界观。

导航列表中的一条记录代表一份完整的时间线梳理，其中可以包含多个事件；新项目从空列表开始，不自动填入示例故事。

## 已确认的设计原则

### 时间线是必需的主干

大纲按照故事实际发生的时间，由早到晚线性梳理。时间线是整个大纲的基础组织结构，不是可有可无的展示选项。

正文如何使用倒叙、插叙或其他叙事方式，由作者自行处理，不属于本功能的设计范围；大纲不另外维护正文的讲述顺序。

### 通过事件展开故事

时间线上的事件承载具体故事内容，围绕以下信息展开：

| 要素 | 回答的问题 |
| --- | --- |
| 时间 | 什么时候发生？ |
| 地点 | 在哪里发生？ |
| 人物 | 哪些人物参与？ |
| 事件内容 | 发生了什么？ |

这些信息帮助作者梳理和查找事件。是否必填、如何关联以及怎样标识同一事件，留待数据设计确定，本文不将四项信息的组合规定为唯一标识。

### 同一时刻允许多个事件并列

同一时刻，不同人物、不同地点可以发生不同事件。这些事件在相同时间位置并列呈现，不强行排列出不存在的先后关系；整个大纲仍沿时间向前推进。

例如，下表中的两个“第二天黎明”发生在同一时刻：

| 时间 | 事件 | 关联人物与地点 |
| --- | --- | --- |
| 第一天午后 | 王子被囚禁 | 王子、城堡 |
| 第二天黎明 | 主角调查王子的下落 | 主角、城内 |
| 第二天黎明 | 反派集结军队 | 反派、城外 |
| 第二天夜晚 | 主角展开营救 | 主角、王子、城堡 |

此例仅说明时间顺序与同时发生的关系，不规定时间字段的存储格式。

### 人物、地点与世界设定向外展开

作者可以围绕同一份大纲，从不同关联查看故事：

- 沿时间线，查看整个故事如何一步步发展。
- 展开一个事件，查看时间、地点、参与人物和具体内容。
- 沿人物关联，查看该人物经历了哪些事件。
- 沿地点关联，查看该地点发生过什么，并进一步展开地图及相关世界设定。

这些展开都围绕时间线组织，在同一无限画布中完成梳理与设计。画布提供向外展开的空间，同时保留故事的时间先后关系。

## 当前插件接入

| 方面 | 约束与实现 |
| --- | --- |
| 归属 | `timeline` 统一拥有列表元信息、当前选择、数值轴设置、视口和编辑流程。`outline-design` 提供导航列表与操作入口，通过公开契约消费时间线。 |
| 协作 | 大纲依赖 `timelineKey`、`layoutKey`、`workbenchKey`、`contextMenuKey`；时间线依赖 `layoutKey`、`workbenchKey`、`projectStorageKey`、`canvasKey`。时间线定义自己的 UTF-8、JSON 和目录规则，项目存储只管理字节。 |
| 接入 | 大纲通过 `registerContent` 贡献 navigation，时间线贡献 main。默认插件由 `appPlugins.ts` 显式选择；正文标签和状态依据已有布局订阅显示。 |
| 生命周期 | 时间线模型与视口属于工作台项目会话，每条时间线保留独立视口。删除、会话结束或停用时释放；视口不跨会话持久化。未提交表单参与离开检查，统一字节保存仍归项目存储。 |
| 验收 | 大纲只调用 SDK；替换兼容的时间线、画布或布局实现无需修改消费者。检查左右数值计算、缩放精度、设置恢复、保存失败保留输入及项目间隔离。 |

初始化失败时清理已创建资源；停用时先撤回 UI，再释放订阅、模型和视口。保存失败保留用户内容并阻止会丢失内容的离开操作。

## 当前实现状态

导航列表中的一条记录代表一份完整时间线。新项目从空列表开始，不填入示例；列表元信息继续使用 `.lodestory/outline-design/timelines/<uuid>.json` 的七字段格式，由 `timeline` 接管读写，既有文件不搬动。详见[时间线列表数据存储](大纲设计/时间线数据存储.md)。

数值横轴类似坐标系 X 轴：世界坐标 `x=0` 表示故事起点，起点显示数值由用户决定；按基础刻度间隔向左递减、向右递增。单位是用户定义的文字，不解析日历，不自动换算单位。缩放只改变视野和刻度显示密度，数值映射保持不变。轴设置独立保存于 `.lodestory/timeline/axes/<uuid>.json`；无设置文件的旧时间线使用默认值，首次修改时创建。

通用 [`canvas`](../../src/plugins/canvas/README.md) 提供 25%–400% 缩放、指针锚点缩放、滚轮平移和空格/中键拖动。数值轴使用纯色画布背景；每条时间线在项目会话内保留独立视口，平移缩放不写入项目文件。具体职责与存储见[时间线插件](../../src/plugins/timeline/README.md)。

事件卡片、事件时间数据、连线和画布关联展开尚未实现。以上进展不代表应用支持运行中任意安装或卸载插件。

## 后续需要细化的内容

- 事件如何绑定当前数值轴，以及精确时间、时间范围和未知时间的表达；不把单位文字当成已实现的历法。
- 事件的粒度、标识，以及事件与人物、地点之间的关联规则。
- 人物、地点、地图与世界设定在画布中的编辑范围、展开和收起方式。
- 画布位置与事件时间的操作关系，以及视口是否需要跨项目会话持久化。
- 为已有时间线条目补充资料编辑界面，并决定是否需要手动排序。
- 事件数据结构、保存位置及人物等实体的公开关联契约后续单独设计，不沿用列表文件或数值轴设置文件来承载它们。
