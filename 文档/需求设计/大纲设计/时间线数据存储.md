# 时间线列表数据结构与保存位置

状态：时间线列表的读取、新建和删除已接入项目存储插件。项目存储只管理项目相对路径上的字节缓冲及持久化；`timeline` 自己定义列表目录、文件名、UTF-8 编码和 JSON 格式。大纲仅通过公开时间线 SDK 提供列表入口。本文只描述列表条目，不描述通用画布交互或画布内事件。

## 保存位置

每条列表记录对应一个 JSON 文件，磁盘位置和现有格式保持不变：

```text
<作品目录>/
  .lodestory/
    outline-design/
      timelines/
        <uuid>.json
```

- 数据跟随作品目录复制、迁移和备份，不放入最近项目索引或浏览器 `localStorage`。
- 文件名使用时间线插件生成的规范小写 UUID；修改标题不会改变 ID。项目存储不解释 UUID 或这套目录规则。
- 列表读取 `.json` 普通文件。目录不存在视为成功读取的空列表；目录权限或读取错误需显示为错误，不能伪装成空列表。
- 不维护额外索引。时间线插件校验文件内容，再按 `createdAt` 升序和 `id` 升序显示。每条记录独立保存；数值轴设置使用独立文件，不扩展本格式。

## 文件结构

```ts
type TimelineListFileV1 = {
  format: "lodestory.timeline-list-entry";
  schemaVersion: 1;
  id: string;         // UUID，与文件名一致
  title: string;      // trim 后 1～60 个 Unicode 码点
  summary: string;    // 可空，最多 200 个 Unicode 码点
  createdAt: string;  // 创建条目的 UTC RFC 3339 时间
  updatedAt: string;  // 条目资料更新时间
};
```

| 字段 | 规则 |
| --- | --- |
| `format`、`schemaVersion` | 标识列表条目及结构版本；未知版本保留原字节并拒绝修改。 |
| `id` | 唯一标识条目，必须与文件名一致，不以标题、数组下标、绝对路径或 session ID 代替。 |
| `title`、`summary` | 只保存作者输入；空梗概写为空字符串，不写入界面提示语。 |
| `createdAt`、`updatedAt` | 由时间线插件维护。它们不表示磁盘保存状态。 |

创建时仅写入这七个字段，两个时间戳相同。当前尚无编辑已有条目资料的界面。时间线模型校验字段集合、版本、ID、长度和时间戳；字符长度按 JavaScript Unicode 码点计数（`[...text].length`），不按 UTF-16 代码单元或用户感知的字素簇计数。

## 字节存储与格式边界

`ProjectStorageService.getFiles(sessionId)` 返回会话内共享的 `ProjectFiles`。时间线插件通过 `list(".lodestory/outline-design/timelines")` 取得目录条目，再用 `read(path)` 读取文件；列表和文件内容都从项目存储返回的快照派生。项目存储只认识不透明字节、相对路径和普通文件系统状态，不规定编码、JSON 解析、UUID 文件名或大纲目录。

`timeline` 负责 UTF-8 编码和解码，解码使用 fatal 模式；无效 UTF-8、符号链接和不规范的 `.json` 文件名显示为局部问题并保留原文件。JSON 解析和业务字段校验也由时间线插件负责。发现损坏内容时不会把它替换为空列表数据，也不会写回修复后的内容；一个文件的问题不应阻止其他有效条目显示。

创建使用一次 `create(path, bytes, {createParents: true, acceptIdentical: true})` 调用，路径为 `.lodestory/outline-design/timelines/<uuid>.json`。创建成功前不关闭表单或显示新条目；失败时保留草稿、UUID 和创建时间，重试使用同一份内容。删除通过 `delete(path)` 执行，成功后才移除行，失败保留行并可重试。当前列表不提供已有条目内容编辑，因此时间线插件不会调用 `write` 修改条目。项目存储拥有共享字节缓冲、保存队列、自动保存、冲突保护和离开保存，时间线插件不另建这些流程。

正文和大纲使用同一个项目存储服务和统一字节文件命令。documents 管理正文打开项与选择，并由其自己的文档适配层解释正文文本；时间线插件单独解释列表 JSON。新接入没有改写既有项目文件位置或数据格式。旧的文档文本读写命令已移除，现有正文及大纲路径通过 `read_project_file`、`create_project_file`、`save_project_file`、`delete_project_file` 和 `list_project_directory` 等通用命令读写。

## 展示与存储的区别

当前新建表单只收集名称和梗概。列表不把“时间待定”和“0 个事件”等占位值写入文件。数值横轴已由时间线插件实现，起点数值、刻度间隔和单位独立保存在 `.lodestory/timeline/axes/<uuid>.json`。事件、时间范围、人物地点引用、卡片和连线尚未实现，也不写入本列表文件。当前选择、视口中心与缩放、滚动位置和菜单状态只存在于会话内，不属于持久化内容。

## 插件归属与生命周期

| 方面 | 归属 |
| --- | --- |
| 列表目录、UUID 文件名、UTF-8、JSON 格式、业务校验、新建和删除 | `timeline` |
| 导航列表与新建/删除交互入口，通过 SDK 操作时间线 | `outline-design` |
| 项目路径对应的唯一字节缓冲、文件读写、保存队列、冲突及离开保存 | `project-storage` |
| 正文打开列表、关闭、选择和正文字符编码 | `documents` |
| 通用视口坐标、平移、缩放和画布手势 | `canvas` |
| 项目会话、统一离开检查 | `workbench` |

时间线插件声明 `projectStorageKey` 并在项目会话开始时获取 `ProjectFiles`；它声明 `canvasKey` 并按时间线 ID 创建视口。面板隐藏时保留模型与视口；删除条目、会话结束或插件停止时释放对应视口。视口中心和缩放只在该项目会话内保留，不写入项目文件。初次目录读取失败不会阻止项目打开，但视图显示错误并允许重试；单文件读取失败或数据损坏通过 issue 显示。旧会话的异步结果不得改变新会话视图。未提交的创建草稿在显式取消或创建成功前保留，失败时也保留用户输入。

## 验收

- 空项目和缺少时间线目录时显示空列表，不生成样例。
- 新建后关闭并重新打开项目，名称与梗概可读；文件仍位于上述既有路径。
- 正文编辑与时间线读写共用项目存储字节服务；时间线不进入正文标签、不改变 `activeId`。
- 初次读取失败可以重试；文件坏 UTF-8、坏 JSON、未知版本和非普通文件不会被覆盖，其他有效条目仍能显示。
- 创建失败保留表单和 ID；删除失败保留行；成功后才更新列表。
- 列表文件不包含 `period`、`eventCount`、事件或画布数据；画布视口也不触发额外文件写入。
