# 工作台工具栏插件

## 定位与边界

`workbench-toolbar` 提供编辑工作台顶部的工具栏 UI 和交互：应用品牌与工程菜单、返回欢迎页、外观设置、禁用的搜索占位、面板切换、专注模式和布局内容菜单。它把工具栏登记为布局的 `actions` 内容，由布局决定工具栏区域的位置和排列。

工具栏负责操作入口与交互状态；工作台、UI 和布局服务分别执行项目、页面导航和内容显隐。专注模式是工具栏把若干布局显隐操作组合起来的行为。布局协议不增加专注状态、专注方法或专用内容字段。

插件声明：

```ts
{
  id: "workbench-toolbar",
  requires: [workbenchKey, uiKey, layoutKey],
  provides: [],
}
```

本插件不提供新的 SDK 服务，不持有工程文件、文档内容或保存状态，不执行离开检查。

## 提供的界面

| 工具栏内容 | 行为与接入 |
| --- | --- |
| 品牌与当前工程菜单 | 从工作台快照读取项目名称；菜单提供返回欢迎页与外观设置入口。 |
| 返回欢迎页 | 调用 `workbench.closeProject()`；工作台的统一离开检查拒绝时，保留当前页面和会话。 |
| 外观设置 | 调用 `ui.openPage(appPages.settings)`；工作台暂时离页时保留当前会话及专注状态。 |
| 搜索占位 | 保留当前禁用状态，不执行搜索。 |
| 面板切换与布局内容菜单 | 读取布局的 `contents`、`shownIds` 快照，按内容 ID 调用 `show(id)` 或 `hide(id)`；菜单不列出工具栏自身。 |
| 专注模式 | 在插件自己的会话模型中记录状态和恢复清单，通过布局现有的 `show/hide` 隐藏或恢复内容。 |

工具栏内容以一项 `actions` 登记：

```tsx
layout.registerContent({
  id: "workbench-toolbar.main",
  title: "工作台工具栏",
  role: "actions",
  render: ({active}) => (
    <WorkbenchToolbar workbench={workbench} layout={layout}
      models={models} active={active} />
  ),
});
```

工具栏本身负责按钮、菜单、图标和交互反馈；布局只负责把 `actions` 内容放到其定义的区域并传递 `active`。`active` 为 false 时，工具栏关闭临时菜单并暂停快捷键等交互。

## 与工作台、UI 和布局协作

**工作台服务**提供当前项目、会话和忙碌状态。工具栏订阅 `workbench.getSnapshot()`，据此显示当前工程并在 `busy` 时停用会发起操作的控件。它通过 `workbench.closeProject()` 请求返回欢迎页，保存和离开检查仍由工作台及文档管理插件执行。

专注模式状态按 `session.id` 保存在工具栏注册的工作台参与者模型中。参与者只负责 `start` 时建立状态、在真正切换或关闭项目的 `dispose` 时恢复内容并释放资源；不实现 `beforeLeave`。切到设置页属于暂时离页，不调用 `dispose`，所以返回后仍是原专注状态。

**UI 服务**提供页面导航和独立包装层。设置入口调用 `ui.openPage(appPages.settings)`，继续经过工作台导航守卫。工具栏另通过 `ui.addWrapper` 挂载恢复入口：仅当工作台当前活跃、非 busy 且 `workbench-toolbar.main` 被隐藏时，显示“显示工具栏”操作；它调用 `layout.show("workbench-toolbar.main")`。因此即使其他调用方隐藏了工具栏，仍可从工具栏以外的位置恢复。

**布局服务**只提供通用的内容目录、显示状态和 `show(id)`/`hide(id)`。工具栏订阅布局快照生成面板状态和完整内容菜单；它不读取默认布局实现，也不向 `@lodestory/sdk/layout` 增加专用 API。默认布局继续负责 actions 区域的排布、面板和导航入口的通用展示、标题栏关闭与切换，以及响应式折叠。

## 专注模式行为

工具栏按当前工作台会话维护 `{focusMode, restoreIds}` 状态，其中 `restoreIds` 是进入专注模式前，布局快照中已显示的 navigation 和 auxiliary 内容 ID。

1. 进入专注模式时，读取一次布局快照，记录当前已显示的 navigation/auxiliary ID，再逐项调用 `layout.hide(id)`。main、actions、status 以及布局自身的左侧竖向图标栏不纳入恢复清单。
2. 主动退出时，先结束专注状态并取出恢复清单，再对其中仍然登记且尚未显示的内容调用 `layout.show(id)`，避免把自己的恢复过程识别成外部操作。
3. 从工具栏菜单主动显示或隐藏面板时，先退出专注并恢复原清单，再执行用户刚选择的显示或隐藏操作。
4. 专注期间，若布局快照新增了可见的 navigation/auxiliary 内容，工具栏结束专注并清空旧清单，以新的布局选择为准；新增显示可能来自外部操作，也可能来自窗口尺寸变化，现有快照不区分来源。工具栏自身进入和退出时产生的显隐变化由插件内部识别，不误判为外部操作。
5. 会话结束时，对仍登记的受控内容恢复显示，再清除专注状态和订阅。进入设置页时保留该状态。

专注模式只恢复进入时记录的内容显隐选择，不承诺精确还原默认布局的自动折叠偏好。布局自身的左侧竖向图标栏不隐藏；专注状态由工具栏持有，布局快照中没有专注状态字段。

## 生命周期与失败处理

- 插件启动时依次登记工作台参与者、`workbench-toolbar.main` 和用于恢复工具栏的 UI 包装层；每项登记都立即保存撤销函数。
- 工作台忙碌时关闭菜单并停用会改变项目或布局状态的交互；忙碌状态结束后根据快照恢复可用状态。
- 设置页等暂时离开只令布局内容 `active` 为 false，保留 React 实例和按会话的专注状态。
- 真正切换或关闭项目时，参与者恢复仍登记的受控内容并清理该会话模型。此过程不询问保存，也不重复工作台离开检查。
- 插件停用时先撤销 UI 包装层和布局内容，停止视图使用；再撤销参与者，恢复受控内容并清理会话订阅。各撤销函数重复调用安全。

专注恢复时跳过已撤销内容；用户操作同样先核对内容仍存在。插件按依赖生命周期先停止视图消费，再清理会话资源；此时布局服务仍然有效，之后才由宿主停用布局服务。

## 实现范围

本次将原编辑功能包中的项目操作入口迁入工具栏，并将默认布局顶部已有的品牌、工程菜单、设置、搜索占位、面板按钮、专注模式和布局内容菜单迁入工具栏。默认布局保留自身侧栏结构、导航和辅助面板标题栏、关闭与切换、main 内容切换及响应式排布。当前工作台工具栏及布局不包含参考资料占位；参考资料功能的形式待后续设计。

正文编辑器继续由 `body-editor` 提供；本设计不改变正文编辑器选择，也不扩展后续 Quill/Milkdown 格式编辑器方案。

## 验证

- 工具栏插件测试覆盖依赖与 `workbench-toolbar.main` 登记、工作台项目操作、设置导航、禁用搜索占位、布局菜单及隐藏工具栏恢复入口。
- 专注模式测试覆盖初始导航/辅助内容记录、逐项隐藏与恢复、已撤销 ID、工具栏显隐菜单先退出再执行、外部新增显示时终止专注、设置页暂离保留，以及项目会话结束时恢复并清理。
- 页面集成验收检查顶部内容由工具栏贡献、默认布局仍可独立更换，以及左侧图标栏、导航切换和响应式折叠行为保持可用。
