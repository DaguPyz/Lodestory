# 工作台插件

## 定位与边界

工作台是编辑页面的调度器：接收当前项目，创建和结束项目级会话，并协调布局与功能插件。它本身按应用生命周期注册一次；文档、工程树和其他功能所需的项目资源，则在每次打开项目时创建，并在离开项目时释放。

工作台通过 `layoutKey` 提供的 `View` 挂载编辑页面。布局插件决定已登记内容如何排列；功能插件提供实际业务能力。工作台只公开当前项目与会话生命周期，不持有文档、文件树等功能数据，也不导入这些插件的实现。

公共契约位于 [`@lodestory/sdk/workbench`](../../packages/sdk/README.md#工作台服务)。应用级插件登记遵循现有插件生命周期：`activate` 时取得工作台服务并登记参与者，`deactivate` 时撤销登记。参与者的 `start` 则每次打开项目调用一次，返回的资源属于该项目会话。

## 公共模型

```ts
type WorkbenchProject = {
  readonly id: string;
  readonly name: string;
  readonly path: string;
};

type WorkbenchSession = {
  readonly id: string;
  readonly project: WorkbenchProject;
};

type WorkbenchSnapshot = {
  readonly session: WorkbenchSession | null;
  readonly active: boolean;
  readonly busy: boolean;
  readonly loading: WorkbenchLoading | null;
};
```

`session.id` 标识一次打开项目产生的会话，关闭后再次打开同一路径也会生成新 ID；对当前项目重复打开、从设置返回都沿用原会话。`active` 表示工作台页面是否在前台；`busy` 表示进入、离开检查或项目切换正在进行。`loading` 给出初始化完成数、总数、当前阶段及失败信息；订阅者收到不可变快照，用于更新项目相关视图和交互状态。

## 工作台服务

工作台插件通过 `workbenchKey` 提供服务：

```ts
type LeaveReason = "suspend" | "switch" | "close" | "shutdown";
type Awaitable<T> = T | Promise<T>;

type WorkbenchParticipant = {
  readonly id: string;
  readonly label?: string;
  start(session: WorkbenchSession): Awaitable<{
    beforeLeave?(reason: LeaveReason): Awaitable<boolean>;
    dispose(): Awaitable<void>;
  }>;
};

type WorkbenchService = {
  openProject(project: WorkbenchProject): Promise<boolean>;
  closeProject(): Promise<boolean>;
  retryProject(): Promise<boolean>;
  returnProject(): Promise<boolean>;
  getSnapshot(): WorkbenchSnapshot;
  subscribe(listener: () => void): () => void;
  registerParticipant(participant: WorkbenchParticipant): () => Promise<void>;
};
```

`openProject` 在离开检查通过后进入工作台，返回 `true` 表示页面已提交；项目会话随后在后台准备，完成或失败由快照报告。已有会话时按 `switch` 检查后切换，旧会话保留到新会话准备成功。`closeProject` 按 `close` 检查后结束会话并返回欢迎页。初始化失败时保持锁定，`retryProject` 重试，`returnProject` 返回原项目或欢迎页。导航被拒绝返回 `false`，导航错误通过拒绝 Promise 报告。`getSnapshot` 读取当前状态，`subscribe` 订阅状态变化。参与者应在 `pluginsReady` 前完成登记；撤销登记函数返回 `Promise<void>`，可重复调用。工作台已挂载时，撤销先停止 UI，再等待项目资源清理；撤销期间保持 busy，不能与窗口关闭检查并发访问资源。

参与者每次打开项目创建项目级资源，并返回离开检查和清理函数。`beforeLeave` 返回 `false` 表示拒绝离开；抛错也视为检查失败并阻止离开。`dispose` 只在项目真正结束时调用。

## 离开与导航规则

| 原因 | 触发场景 | 参与者处理 | 会话结果 |
| --- | --- | --- | --- |
| `suspend` | 工作台暂时切到设置等页面 | 检查能否暂时离开 | 保留会话与资源，返回时继续使用 |
| `switch` | 当前工作台替换为另一个项目 | 检查能否切换，然后结束旧会话 | 新项目创建新会话 |
| `close` | 关闭项目并返回欢迎页 | 检查能否关闭，然后结束会话 | 当前会话清空 |
| `shutdown` | 关闭应用窗口 | 检查能否退出，然后结束会话 | 应用获准关闭 |

所有会离开当前工作台的入口都经过同一条异步离开检查：UI 的 `open`、`back`、同一页面上的项目替换，以及原生窗口关闭请求。UI 依次等待已登记的导航守卫；守卫可返回一个审批对象，UI 在所有守卫同意后同步调用 `commit`，提交页面变化，再等待 `complete` 清理旧资源。若后续守卫拒绝或导航失效，UI 逆序调用先前审批的 `cancel`，释放已准备的资源。导航在审批完成前不执行；任一参与者拒绝或检查失败时，导航被取消，当前项目继续保留。由 `openProject` 或 `closeProject` 发起的项目切换/关闭应复用同一次检查，不能重复询问参与者。

离开检查开始时 `busy` 变为 `true`。此时功能视图应阻止新的用户编辑操作；检查所等待的保存和已启动的保存任务仍须继续运行。检查完成或失败后更新快照并清除 `busy`。暂时离开时将 `active` 设为 `false`，但不调用 `dispose`；返回工作台时恢复 `active`，沿用同一会话。

正常关闭窗口先拦截原生关闭请求，等待 `shutdown` 检查；检查允许后再释放会话并继续关闭，拒绝时窗口保持打开。异步检查期间应避免重复执行同一导航或关闭请求。保存检查失败时保留窗口；会话已提交关闭后发生的资源清理错误会被报告，并继续关闭窗口，避免留下已经卸载 UI 的空窗口。

## 生命周期、顺序与失败回滚

1. 应用启动时 `config` 插件先提供 `configKey`；UI 插件登记页面启动配置。工作台插件提供 `workbenchKey` 并登记编辑页面，功能插件在 `activate` 中登记参与者。页面全部登记后，UI 才读取配置确定初始页面。
2. `openProject` 在路径确认和离开检查后生成会话并显示工作台；布局在初始化期间不可操作，右下角展示真实完成项数。
3. 工作台按登记顺序调用参与者 `start(session)`；依赖排序让 project-storage 先登记共享存储，再由 documents 创建文档工作区。工程管理等待文件树首次读取；所有参与者准备成功后解除锁定。正文内容仍在打开具体文档时读取。
4. 项目切换、关闭或退出时，先按登记顺序检查所有 `beforeLeave(reason)`；全部通过后按 `start` 的逆序调用 `dispose()`。
5. 任一 `start` 失败时，工作台先停止视图使用候选资源，再按逆序清理已启动的参与者，保留旧会话并提供重试和返回。参与者的 `start` 若在返回清理函数前失败，必须自行释放尚未暴露给视图的临时资源。

检查失败时不得释放任何参与者资源，也不得清空或替换当前会话。清理过程中的错误应被报告；工作台仍需尝试清理其余参与者，避免一个清理错误跳过其他资源。

## 当前编辑插件的迁移

[`workbenchPlugin.tsx`](../../src/plugins/workbench/workbenchPlugin.tsx) 是应用级 `workbench` 插件：提供 `workbenchKey`、登记编辑页面和导航守卫，并在 Tauri 窗口关闭时调用 `shutdown`。它挂载 [`WorkbenchPage.tsx`](../../src/plugins/workbench/WorkbenchPage.tsx)，页面按会话挂载布局 `View`。

启动首页归配置插件管理。UI 使用 `ui.initialPage` 配置项，并在全部页面登记后读取；首版基础值为 `welcome`，因此工作台页面先登记也不会改变默认首页。配置协议和存储边界见[配置插件设计](配置插件.md)。

[`bodyEditorPlugin.tsx`](../../src/plugins/body-editor/bodyEditorPlugin.tsx) 导出 `createBodyEditorPlugin`，插件 ID 为 `body-editor`，依赖 workbench、documents 与 layout 服务。它登记 `body-editor.main`；`writing-status` 插件登记 `writing-status.status`。正文插件按会话创建正文展示模型；正文内容和保存状态来自项目存储，打开列表与当前选择由 documents workspace 管理。[`workbench-toolbar` 插件](工作台工具栏插件.md)依赖 workbench、ui 与 layout，登记顶部 actions 内容并按会话保存专注模式状态；它不参与保存或离开检查。

工程树与新建文档交互由独立 [`projectManagementPlugin.tsx`](../../src/plugins/project-management/projectManagementPlugin.tsx) 提供，登记为 `project-management.files` 的 navigation 内容，并按会话管理目录与对话框状态。各功能插件的布局登记和会话职责见[布局插件设计](布局插件.md)、[工作台工具栏插件设计](工作台工具栏插件.md)、[工程管理插件设计](工程管理插件.md)和[正文编辑插件设计](正文编辑插件.md)。

[`documentsPlugin.ts`](../../src/plugins/documents/documentsPlugin.ts) 依赖工作台与项目存储服务，按会话创建文档工作区，管理打开项、选择及文档操作流程。它不依赖布局或 UI；文档打开/创建/保存失败后的界面定位通过 SDK 的 `documentRevealRequested` 事件通知正文编辑与工程管理插件。项目文件字节缓冲和落盘由 project-storage 管理，documents 内部适配层负责正文文本转换。文档服务和事件 payload 见[文档管理插件设计](文档管理插件.md)。工程管理插件接收 `documentCreateRequested` 并通过自己的 UI 包装层显示新建对话框，接入规则见[工程管理插件设计](工程管理插件.md)。

工程树与新建对话框由独立工程管理插件管理，正文编辑组件及其 React Context 由 `body-editor` 私有持有。两个插件不共享 Context；工程管理、正文编辑、文档、项目存储和布局通过 SDK 服务与事件协作。正文内容由 project-storage 持有，documents 管理打开项与当前选择。

## 验证范围

- SDK 构建与导出测试确认 `@lodestory/sdk/workbench` 的类型、共享 `workbenchKey` 与运行时导出。
- 工作台测试覆盖状态订阅、参与者顺序、拒绝离开、项目切换、暂时离页保留、逆序清理及启动失败回滚。
- UI 导航测试覆盖 `open`、`back`、同页项目替换和关闭窗口等待异步检查；拒绝时确认原页面与项目仍保留。
- 正文编辑测试确认离开检查期间正文只读并停用保存快捷键，已接受的保存继续完成；文档保存失败时正文仍显示错误与重试入口。
- 文档插件测试确认项目会话隔离、已接受操作完成后统一保存、失败时拒绝离开，以及会话释放后旧工作区失效。
