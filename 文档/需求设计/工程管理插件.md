# 工程管理插件

## 定位

工程管理插件展示和组织当前工程内的文件与目录，并提供新建文档交互。它包含完整的工程文件树 UI、目录加载与重试、目录选择、新建对话框和文件树右键菜单。目录选择、展开状态和对话框状态按工作台会话保存在插件内部。

工程管理插件不拥有正文内容或保存状态；项目存储管理项目路径字节缓冲，`documents` 管理打开文档列表和选择，并提供正文文本视图。工程管理插件也不决定树所在的位置；它将树登记为布局的 `navigation` 内容，由布局插件决定如何展示。工程管理插件没有对其他插件公开的业务服务，因此不新增 SDK key。

## 插件依赖与能力

```ts
{
  id: "project-management",
  requires: [workbenchKey, documentsKey, layoutKey, uiKey],
  provides: [],
}
```

插件在 `activate` 时订阅文档创建与显示事件，登记一个布局内容，并通过 UI 包装层独立挂载工程管理对话框。它在工作台参与者的 `start(session)` 中，为该会话取得 documents workspace、创建目录树与交互模型并开始读取目录；`dispose` 使进行中的目录读取结果失效并释放会话状态，底层 Tauri 调用本身不会被取消。工程管理插件不实现离开保存检查；documents 处理已接受的文档操作，project-storage 锁定并保存共享内容。

## 工程树与目录数据

工程树由 `ProjectManagementView.tsx` 导出的 `ProjectFiles` 组件和内部 `ProjectTree` 渲染，并以如下描述登记给布局：

```tsx
layout.registerContent({
  id: "project-management.files",
  title: "工程文件",
  role: "navigation",
  render: ({active}) => <ProjectFiles workbench={workbench} models={models} active={active} />,
});
```

树只显示当前工程中受支持的 Markdown 与文本文件及目录。递归读取、排序、忽略规则和路径安全校验沿用[文件目录树与新建文档](文件目录树.md)中的现有行为。`projectFilesApi.ts` 与树条目类型属于工程管理插件内部实现，不导出成跨插件协议。

树节点使用相对于工程根目录的路径。单击文件只选中节点，不打开或切换正文，可直接按 F2 重命名；双击、键盘激活或右键“打开文档”时调用 `workspace.open(path)` 打开正文。点击目录会使目录节点获得焦点，并展开或折叠；目录也可作为新建位置。文档正在打开时也可请求重命名，确认后的文件操作会等待已开始的打开操作。加载失败时显示错误与重试入口。读取结果带会话与请求序号校验，旧工程的迟到响应不能覆盖当前树状态。

插件从 workspace 快照中的 `activeId` 找到当前文档，再把该文档的 `path` 传给树用于标识当前文稿并展开父目录。树的选中项独立维护，因此单击其他节点不会改变当前文稿。文档 ID 是不透明标识；树不编码、解码或猜测文档路径。

## 新建文档接入

其他界面通过 SDK 的 `documentCreateRequested` 事件请求新建交互，payload 带 `sessionId` 和可选的 `parentPath`。工程管理插件只响应当前会话的请求，并通过 UI 包装层挂载的 `ProjectDialogs` 展示自己的新建对话框。此挂载不依赖正文或导航内容是否可见，因此从其他插件发起的新建请求也能打开对话框。

用户确认后，工程管理插件调用当前会话的 `workspace.create(parentPath, name)`。创建成功后关闭对话框并刷新目录；文档服务负责创建物理文件、将文档加入打开列表并发布显示请求。失败时保留对话框输入并显示错误。默认目录、文件名与后缀规则沿用[文件目录树与新建文档](文件目录树.md)。

正文空状态和文稿标签栏通过同一个创建事件接入；工程树内部直接请求自己的新建交互。其他功能插件不直接依赖工程管理插件内部组件。该事件只请求界面交互；确认后的创建操作仍通过 documents workspace 完成。

## 显示文档时同步树

文档服务在打开或创建成功，以及离开检查保存失败需要定位正文时，发布 `documentRevealRequested({sessionId, documentId})`。`body-editor` 核对当前会话、workspace 中目标文档仍存在且仍为当前文档，然后展示 `body-editor.main`；即使工作台忙碌或 workspace 被阻塞，也先展示保存错误，等内容 active 且工作台和 workspace 恢复可交互后再聚焦。正文编辑模型用 reveal 版本变化确保重复请求和阻塞期间的请求在恢复后仍能触发聚焦。工程管理插件同时核对会话，并从当前 workspace 快照中查找该 ID 对应文档的路径，更新选中目录并展开父目录；若当前目录快照中缺少该路径，则刷新目录。它不从 ID 推导路径，也不代替正文插件调用 `layout.show`。

## UI 与布局边界

布局只接收 `project-management.files` 这一项内容及其 `active` 状态。布局负责面板、抽屉、尺寸与隐藏行为；工程管理插件负责树的结构、行交互和加载状态。`active` 为 false 时暂停树的快捷键等交互，保留树的会话状态。

新建对话框由 `ProjectDialogs` 通过 `ui.addWrapper` 加入 UI 根层，独立于布局内容。工程管理插件负责注册和撤销这个包装层，以及订阅、事件和布局登记；停用时释放自己的贡献并结束项目会话状态。

`projectManagementPlugin.tsx`、`projectManagementModel.ts`、`ProjectManagementView.tsx`、`ProjectTree.tsx`、`NewDocumentDialog.tsx`、`projectFilesApi.ts` 与 `project-management.css` 都位于 `src/plugins/project-management/`。正文、文稿标签、空态与写作状态由 `body-editor` 提供；项目操作入口、布局操作和专注模式由 `workbench-toolbar` 提供。跨插件协作只使用 SDK 的 `documentsKey`、`layoutKey`、`workbenchKey`、`uiKey` 与文档事件，不导入对方插件内部模块或共享 Context。

## 范围

首版包含文件树浏览、目录选择、刷新和重试、新建文档对话框、打开文档及右键菜单。物理删除、重命名、移动、新建目录和外部文件变化监听不在本次拆分范围内；文档关闭也不会删除物理文件。

## 测试覆盖与验收

- `project-management.test.mjs` 覆盖目录读取失败与恢复、并发读取只采用最新结果、通过 workspace 路径解析不透明文档 ID、缺失文件触发目录刷新、项目离开期间已接受的新建完成并刷新，以及会话释放后忽略迟到结果并清理订阅。
- `project-files.test.mjs` 覆盖桌面目录读取命令和目录错误提示。
- `project-management-plugin.test.mjs` 覆盖依赖声明、`project-management.files` 的 `navigation` 登记、导航隐藏时 UI 根包装层仍挂载新建对话框、忽略旧会话的新建请求，以及部分激活失败后的清理。
- 页面与布局集成测试确认正文空状态和文稿标签栏发送新建请求，打开或创建文档时工程树按文档路径同步选择；布局登记正文/状态、工程树与工作台工具栏。
- UI 验收检查在导航内容隐藏时仍可从正文空状态或文稿标签栏打开新建对话框。
- 文件目录树 UI 验收覆盖展开、折叠、目录选择、文件打开、新建、错误重试和右键操作；documents 管理打开项和文档流程，正文对应的字节缓冲、自动保存与统一离开落盘由 project-storage 负责。
