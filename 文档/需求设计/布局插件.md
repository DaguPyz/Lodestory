# 工作台布局插件

## 定位与边界

编辑页面由布局与功能内容组合。布局实现决定内容如何排列、展示和折叠；功能插件提供内容，通过用途登记，不指定左右位置、网格列或布局 DOM。

公共协议位于 [`@lodestory/sdk/layout`](../../packages/sdk/src/layout.ts)。同一次装配选择一个提供 `layoutKey` 的布局插件。默认实现为 [`default-layout`](../../src/plugins/default-layout/defaultLayoutPlugin.tsx)，从现有编辑页面抽出顶部操作区、导航栏、中央区域、辅助面板和底部状态区。其他实现可把导航改为右侧面板或抽屉，无需修改内容登记。

`ui` 继续管理应用页面导航与唯一的 React root。工作台插件登记编辑页面并挂载布局提供的 `View`；布局不创建 root、不登记编辑页面，也不拥有项目、文档或保存流程。项目会话、页面生命周期和统一离开检查见[工作台插件设计](工作台插件.md)。

## 用途登记

| role | 用途 | 当前贡献 |
| --- | --- | --- |
| `main` | 当前主要工作内容 | 正文编辑插件的文稿标签与正文 |
| `navigation` | 查找、选择工作对象 | 工程管理插件的工程文件树 |
| `auxiliary` | 辅助当前工作 | 编辑功能包中的参考资料占位 |
| `actions` | 操作入口 | 编辑功能包中的项目名称、返回与设置等操作 |
| `status` | 状态信息 | 正文编辑插件的保存状态与当前字符数 |

这些用途不是五个固定屏幕位置。每种用途允许多项内容；兼容布局必须提供展示全部已登记内容的入口，不能静默丢弃不认识的业务 ID。功能内容使用主题标准的颜色变量，布局同样遵守主题标准。

登记结构：

```ts
type LayoutContent = {
  readonly id: string;
  readonly title: string;
  readonly role: LayoutRole;
  readonly order?: number;
  readonly render: (context: { readonly active: boolean }) => ReactNode;
};
```

- `id` 在一个布局服务中唯一，建议以功能插件 ID 为前缀。
- `title` 用于内容入口、面板标题和无障碍名称。
- 同用途内按 `order` 升序排列，默认 0；同值按 ID 的字符串顺序排列，不依赖插件激活顺序。
- 登记时复制并冻结描述，校验失败不产生部分登记。登记不会调用 `render`。
- `render` 返回 React 元素；需要 Hook 时返回 `<Component />`，不直接调用组件函数。
- `active` 同时取决于页面是否在前台及该内容是否展示。为 false 时，内容应暂停快捷键、关闭临时交互浮层；文档自动保存由业务自行管理。

## 提供的能力

| 能力 | 约定 |
| --- | --- |
| `View({active})` | 稳定的 React 组件，由工作台页面挂载；首版一个服务供一个工作台页面使用 |
| `registerContent(content)` | 启动期间登记内容，返回撤销函数；重复 ID、空 ID/标题、未知用途、无效排序和非函数 render 抛错 |
| `show(id)` | 展示内容，必要时展开容器或选择标签；不切换应用页面，也不承诺聚焦业务编辑器 |
| `hide(id)` | 隐藏内容，保留已挂载的组件实例及重新展示入口 |
| `getSnapshot()` | 返回不可变的 `{contents, shownIds}`；状态未变化时返回同一对象 |
| `subscribe(listener)` | 订阅状态变化，返回可重复调用的取消函数 |

`contents` 包含按用途、order、ID 排序的完整登记目录；默认实现的用途排序为 main、navigation、auxiliary、actions、status。`shownIds` 表示布局内部的展示状态。进入设置页不会清空它，但所有内容的 `active` 都变为 false。`show`/`hide` 在准备完成后调用，未知 ID 抛错；停用后的旧服务访问抛错。

组件隐藏和撤销是不同操作：隐藏保留实例；撤销结束登记并销毁对应组件，必须先结束对该插件资源的使用。

## 功能插件接入

```tsx
import type {Plugin} from "@lodestory/sdk";
import {layoutKey} from "@lodestory/sdk/layout";

export function createExamplePlugin(): Plugin {
  let remove: (() => void) | undefined;
  return {
    id: "example",
    requires: [layoutKey],
    provides: [],
    activate(context) {
      const layout = context.get(layoutKey);
      remove = layout.registerContent({
        id: "example.navigation",
        title: "示例导航",
        role: "navigation",
        render: ({active}) => <ExampleNavigation active={active}/>,
      });
    },
    deactivate() {
      remove?.();
      remove = undefined;
    },
  };
}
```

`ExampleNavigation` 是功能插件自身的组件。它通过自身服务或 Context 获取业务数据。布局协议不传递项目路径、文档内容等业务参数。

工作台页面通过 `context.get(layoutKey)` 取得服务，并渲染 `<View active={active}/>`。应用装配入口只选择布局插件；工作台和功能插件只导入 SDK 能力，不导入默认布局实现。

## 当前编辑页面接入

`body-editor` 在 activate 中登记 `body-editor.main`（main）与 `body-editor.status`（status）；`editor-features` 只登记 actions 与 auxiliary；独立的 `project-management` 插件登记工程文件树 navigation。工作台插件登记编辑页面并挂载布局。每项成功后立即保存撤销函数，后续登记失败时撤销已完成的贡献。迁移后的职责与会话流程见[正文编辑插件设计](正文编辑插件.md)、[工作台插件设计](工作台插件.md)和[工程管理插件设计](工程管理插件.md)。

文档服务在项目会话中创建文档工作区并负责保存保护；工程管理参与者持有本会话的目录树与新建对话框状态，正文编辑参与者订阅同一文档工作区。布局的 `View` 位于工作台页面中，布局实现不依赖任何功能插件的私有状态。工程树点击文件后通过文档服务打开；文档服务发布显示事件，正文编辑插件展示自己的 main 内容，工程管理同步树选择。离开前保存失败时正文编辑插件仍展示正文，使错误与重试入口可见。

正文、文稿标签、空态与状态内容的样式位于 [`body-editor.css`](../../src/plugins/body-editor/body-editor.css)；项目操作与参考占位使用编辑功能包自己的样式；工程树与新建对话框样式位于工程管理插件自己的样式表。页面排列和响应式样式位于默认布局的 [`layout.css`](../../src/plugins/default-layout/layout.css)。工程树和参考内容不接收 overlay、停靠位置或布局关闭回调；这些由布局负责。

正文编辑与状态栏由 `body-editor` 提供；`editor-features` 仍提供项目操作与参考资料占位，`project-management` 提供 navigation。文档工作区由 documents 插件按工作台会话创建，正文编辑模型和工程树模型也各按会话创建。查找替换、阅读排版等其他编辑能力仍是后续功能规划，本文不表示它们已经实现或拆成独立插件。

## 默认布局的展示策略

- navigation 与 auxiliary 分别默认放在左右面板，main 位于中央；同用途的多项内容通过入口或选择器切换。actions 放在顶部，status 放在底部，可同时展示多项。
- 所有内容随工作台首次挂载；切换内容、折叠面板或切换页面只隐藏，组件保持在原来的 React 位置。每项内容单独包裹错误边界，一项渲染失败不影响其他项。
- 工作台宽度低于 54rem 时导航默认折叠；低于 74rem 时辅助面板默认折叠。显示时改为覆盖面板，窄屏不会同时打开两个覆盖面板。
- 显式隐藏的内容不会因窗口放大而自动重新显示。专注模式暂时隐藏侧栏并保留原选择，退出后恢复；主动展示导航或辅助内容会退出专注模式。
- 顶部“布局内容”菜单列出全部登记项，包含主内容、操作和状态项，始终可以恢复被隐藏的内容。导航切换入口在很窄的窗口移到顶部。
- 面板展开、选择和专注模式属于布局服务，进入设置或切换项目时保留；文档会话仍按项目 ID 和路径建立独立实例。

## 启动、撤销与替换

1. 布局插件提供 `layoutKey`，登记一个透明 UI 包装层。包装层只参与准备和清理，不新增 DOM。
2. 功能插件声明依赖，在 activate 中登记内容；编辑插件再登记页面。
3. 初始插件全部激活后，UI 调用包装层 prepare，布局按完整目录确定初始显示项，并封闭新增登记入口。
4. UI 创建根视图，进入编辑页面时挂载布局与内容。
5. 贡献者停用时调用撤销函数。撤销函数幂等，旧登记的撤销函数不能影响后续同名登记。布局停用先停止 UI，再释放目录和监听。

当前 UI 不支持运行中增删页面或重新挂载。撤销已经准备好的布局内容会先停止整棵 UI 树，与现有页面贡献的清理行为一致；不是一次普通隐藏。首版替换布局是在下一次装配时换成另一个提供 `layoutKey` 的插件，不支持运行中热切换，也不承诺跨布局实现保留 DOM、选区与撤销栈。文档内容和保存状态始终属于业务。

## 验证

- SDK 类型与运行时导出测试覆盖 layout 子路径、共享 key 和不可变快照类型。
- [`layout-plugin.test.mjs`](../../tests/layout-plugin.test.mjs) 覆盖登记校验、排序、不可变描述、展示切换、响应式、专注模式、幂等撤销、停用失效、编辑接入、替换提供者及部分激活回滚。
- 原有页面导航与文档自动保存、写入串行化、保存失败和冲突保护测试继续执行。
- `/tests/fixtures/project-index.html?layout=alternative` 使用一个独立测试布局，纵向排列同一组编辑内容；它不导入默认布局实现。
- `/tests/fixtures/project-index.html?layout=probes` 为每种用途增加第二项有输入状态的内容，可验证切换、隐藏后实例和内容保留，以及页面 active 的传递。
- 在普通项目测试页验证宽窄窗口、创建/编辑/保存、专注模式、设置页返回；`?scenario=save-error` 验证保存失败仍保留文稿并阻止离开。测试页使用内存 IPC，不修改真实文档。
