# 文档管理插件

## 定位

文档管理插件以项目内的物理文档为业务对象，以打开后的文档和选择状态为运行时对象。它管理打开项、当前选择及打开、关闭和新建等文档流程，并通过 SDK 向其他插件提供服务。项目存储插件拥有共享字节缓冲和持久化；documents 的文件适配层负责把正文文本编码、解码为 UTF-8。关闭一个文档只会从打开列表移除它，不会删除磁盘文件。

它不管理目录树、新建对话框、光标、滚动位置或布局。独立的工程管理插件负责列出和选择目录、提供新建交互；正文编辑功能负责编辑器界面。两者通过同一个文档工作区读写文档。

公共协议位于 [`@lodestory/sdk/documents`](../../packages/sdk/src/documents.ts)，由 [`documentsPlugin.ts`](../../src/plugins/documents/documentsPlugin.ts) 实现。它依赖 `workbenchKey` 和 `projectStorageKey`：前者提供会话生命周期，后者提供共享字节文件缓冲与持久化；documents 内部适配层负责正文文本编码，不依赖 UI、布局或具体编辑界面。

## 实现归属

文档业务实现集中在 `src/plugins/documents/`：`createDocumentWorkspace.ts` 管理项目会话中的打开文档集合并实现 SDK 工作区接口，`documentFiles.ts` 把正文字符串映射到项目存储字节，`documentsPlugin.ts` 通过 `projectStorageKey` 取得共享文件服务；其他插件只通过 SDK 协议访问工作区，不导入这些内部模块。物理文件缓冲、自动保存和冲突处理由 `src/plugins/project-storage/` 中的项目存储插件负责。

正文编辑侧的 `src/plugins/body-editor/useDocumentWorkspace.ts` 是 React 接入层，负责把 SDK 工作区快照订阅给编辑组件，不拥有第二份文档内容或选择状态。`src/plugins/project-management/projectFilesApi.ts` 管理目录列表数据、树条目与目录错误文本；工程管理插件据此展示物理目录，并通过 documents workspace 打开或创建文档。目录列表、文档业务和物理内容存储分别由各自职责的接口处理。

因此，documents workspace 拥有打开项和当前选择；项目存储插件拥有共享字节缓冲、保存队列、自动保存和磁盘冲突保护，documents 适配层拥有正文 UTF-8 转换；工程管理插件拥有目录树、目录选择和新建对话框状态；正文编辑插件拥有编辑视图、光标、滚动和标签展示等本地 UI 状态，布局状态由布局插件管理。SDK 协议是插件之间唯一的文档接口，`src/documents/` 不再作为实现目录或兼容入口存在。

## 服务协议

```ts
type DocumentSaveState = "saved" | "pending" | "saving" | "error";

type OpenDocument = Readonly<{
  id: string;
  path: string; // 相对于项目根目录
  fileName: string;
  content: string;
  saveState: DocumentSaveState;
  saveError: string | null;
}>;

type DocumentSnapshot = Readonly<{
  documents: readonly OpenDocument[];
  activeId: string | null;
  openingPath: string | null;
  creating: boolean;
  blocked: boolean;
  error: string | null;
}>;

type DocumentWorkspace = {
  getSnapshot(): DocumentSnapshot;
  subscribe(listener: () => void): () => void;
  open(path: string): Promise<boolean>;
  create(parentPath: string, name: string): Promise<OpenDocument | null>;
  select(id: string): boolean;
  update(id: string, content: string): boolean;
  close(id: string): Promise<boolean>;
  save(id: string): Promise<boolean>;
  saveAll(): Promise<boolean>;
  clearError(): void;
};

type DocumentsService = {
  getWorkspace(sessionId: string): DocumentWorkspace | null;
};
```

`documentsKey` 是全局服务 key；每次工作台会话启动时创建一个独立 workspace。相同会话 ID 多次读取会得到同一个对象；会话释放后服务返回 `null`，旧对象也不再接受修改。快照深只读，底层内容未改变时保持引用稳定。`activeId` 指向当前选中文档；界面可用它从 `documents` 派生当前文档。正文文本本身来自项目存储服务的同路径共享缓冲。

`open(path)` 从项目存储取得字节，由 documents 适配层按 UTF-8 解码并选择文档；已打开的文件直接复用，不覆盖未保存内容。迟到的读取结果不能抢回较新的选择。`create(parentPath, name)` 通过项目存储创建 UTF-8 文本文件并加入打开列表，返回真实文件名和项目内相对路径。`update` 将正文字符串编码后交给共享字节缓冲；项目存储负责 700 毫秒自动保存。`close` 先请求保存；失败时文档会保留并重新选中。`save` 和 `saveAll` 返回 `boolean` 表示是否成功；打开或创建失败写入快照 `error`，保存失败写入对应文档的 `saveError`。新建、打开等预期失败不会抛出，分别返回 `null` 或 `false`。

```ts
import type { Plugin } from "@lodestory/sdk";
import { documentsKey } from "@lodestory/sdk/documents";
import { workbenchKey } from "@lodestory/sdk/workbench";

let removeParticipant: (() => Promise<void>) | undefined;
export const exampleDocumentViewPlugin: Plugin = {
  id: "example-document-view",
  requires: [documentsKey, workbenchKey],
  provides: [],
  activate(context) {
    const documents = context.get(documentsKey);
    const workbench = context.get(workbenchKey);
    removeParticipant = workbench.registerParticipant({
      id: "example-document-view",
      start(session) {
        const workspace = documents.getWorkspace(session.id);
        if (!workspace) throw new Error("The document workspace is unavailable.");
        const stop = workspace.subscribe(() => {
          const snapshot = workspace.getSnapshot();
          const current = snapshot.documents.find(document => document.id === snapshot.activeId);
          // 使用 current.content 和 current.saveState 更新正文与保存状态。
        });
        // 编辑时：workspace.update(document.id, nextContent)
        return {dispose: stop};
      },
    });
  },
  async deactivate() { await removeParticipant?.(); },
};
```

实际插件按工作台参与者生命周期取得 workspace，因此视图应从自己对应的会话取值；UI 在会话切换时不能保留旧会话句柄。

## 新建与显示事件

文档服务不打开任何界面。SDK 提供两个带会话 ID 的事件，让业务动作和界面提供方解耦：

| 事件 | Payload | 处理方式 |
| --- | --- | --- |
| `documentCreateRequested` | `{ sessionId, parentPath? }` | 工程管理插件确认当前会话后展示自己的新建对话框；用户确认后调用 `workspace.create`。 |
| `documentRevealRequested` | `{ sessionId, documentId }` | 正文编辑插件确认当前会话、目标仍存在且仍是当前文档后，通过 `layoutKey` 显示正文；工程管理插件同步文件树选择并按需刷新目录。 |

文档插件在成功打开/创建文档和保存失败需要定位文档时发布显示请求。事件监听错误会被记录，但不会回滚已经完成的文件或文档状态变更。`project-management` 接收新建请求并同步树选择，`body-editor` 负责正文展示；两者都核对事件中的会话 ID。正文编辑即使在工作台忙碌或 workspace 被阻塞时也先展示目标正文和保存错误，待工作台恢复可交互后再聚焦。文档 ID 是 workspace 内的不透明标识，工程管理插件先从 workspace 快照查出文档路径，不从 ID 推导路径。

## 生命周期与离开检查

文档插件在激活时登记一个工作台参与者。每个项目会话的 `start(session)` 创建自己的 workspace；创建失败会由工作台回滚已经启动的参与者。

离开检查开始后，workspace 的 `blocked` 变为 `true`，拒绝新的修改、打开和创建。documents 排空已接受的文档操作，并通过项目存储保存已打开文档；项目存储参与者锁定共享字节缓冲、排空写入并保存所有项目文件。保存成功才允许项目切换、关闭或退出。保存失败会拒绝离开并保留原会话和未保存内容；documents 可发布显示失败文档的请求。工作台忙碌状态解除后，用户可以继续编辑或重试。

暂时离开到设置等页面会保留工作区；真正切换或关闭项目时，工作台先停止旧会话视图，再调用参与者的 `dispose`。documents 释放打开项和选择；项目存储在等待已接受的写入后释放共享缓冲及自动保存资源。旧 workspace 和存储句柄不能继续影响新会话。

强制停用也会等待已接受的操作和保存结束。如果项目存储仍无法保存，停用会报告错误并在错误快照中保留未保存缓冲。这是当前进程中的数据保留，不提供崩溃后的磁盘恢复。状态订阅或显示通知失败不会卡住保存，也不会回滚已经写入的文件。

## 插件接入顺序

应用装配 `workbench`、`project-storage` 和 `documents`；依赖排序保证项目存储先于 documents 激活，之后激活的工程管理、正文编辑与工具栏等插件可使用已登记的服务。各自登记工作台参与者；打开项目时，工作台分别准备共享存储、documents workspace、工程树、正文编辑和工具栏会话状态。离开时，documents 管理文档工作区的操作检查并委托打开文档保存，project-storage 负责共享缓冲与资源的统一落盘；所有检查通过后按参与者逆序销毁会话视图和资源。工程管理、正文编辑和工具栏插件不另建保存定时器。

`body-editor` 与 `project-management` 通过 documents SDK 工作区操作文档；目录列表 API、工程树、目录选择和新建对话框归 `project-management`。正文打开项与 `activeId` 的唯一来源是 documents workspace，项目路径字节内容的唯一缓冲和落盘来源是项目存储；正文编辑插件只维护会话视图所需的本地状态。本文只定义首版文档管理边界，不包含磁盘删除、重命名、移动文件或目录操作。
