# 正文编辑插件

## 定位与边界

`body-editor` 提供工作台的正文编辑界面，包括文稿标签、正文输入、空态、保存反馈和写作状态。它依赖工作台、文档与布局 SDK 服务，不向其他插件提供服务 key；正文内容、已打开文档和当前选择始终由 `documents` 插件持有。

插件声明如下：

```ts
{
  id: "body-editor",
  requires: [workbenchKey, documentsKey, layoutKey],
  provides: [],
}
```

正文插件私有的 React Context 和会话视图模型只供自身组件使用。其他插件通过 SDK 的 `documentsKey`、`layoutKey`、`workbenchKey` 和文档事件协作，不导入正文插件内部模块。

## 提供的内容

| 内容 | 行为 |
| --- | --- |
| `body-editor.main` | 显示已打开文档标签、当前正文，或没有打开文档时的新建入口；提供保存、关闭、切换和保存失败重试。 |
| `body-editor.status` | 显示当前文稿保存状态、字符数与基础阅读信息。 |

正文输入首版继续使用受控 `textarea`，沿用浏览器原生编辑菜单。状态栏当前按非空白字符计数，Markdown 标记也计入；它不代表纯正文词数。保存状态、保存错误和文稿内容均直接读取 documents workspace。

正文插件把 main 与 status 分别登记到布局服务，布局决定展示位置和可见状态。插件只在 main 内容中安装正文快捷键；布局传入的 `active` 为 false 时停止快捷键和临时交互。切换标签使用隐藏非当前文稿的方式保留已挂载输入框及其本地编辑状态。

## 文档工作区接入

文档插件为每个工作台会话创建 documents workspace 后，正文插件的参与者通过 `documents.getWorkspace(session.id)` 取得该会话的同一个工作区，并在会话期间订阅快照。正文插件本地模型只保存当前会话需要的视图信息和工作区句柄，不复制文档正文或当前选择。

正文和标签通过 workspace 快照显示文稿。编辑调用 `workspace.update(id, content)`，切换标签调用 `workspace.select(id)`，关闭调用 `workspace.close(id)`，手动保存调用 `workspace.save(id)`；保存快捷键调用 `workspace.saveAll()`。自动保存、保存串行化和离开前保存检查都由 documents 插件执行。`busy` 或 workspace 的 `blocked` 为 true 时，正文设为只读并停用保存快捷键；已接受的保存仍由 documents 插件继续完成。

正文空态和标签栏的新建入口发送 `documentCreateRequested({sessionId, parentPath?})`。工程管理插件确认当前会话后展示自己的新建对话框，并在用户确认后调用 `workspace.create`；正文插件不直接依赖工程管理组件。

## 文档显示与恢复焦点

文档服务在打开或创建文档成功，以及离开检查保存失败需要定位正文时发送 `documentRevealRequested({sessionId, documentId})`。正文插件依次核对事件会话仍是工作台当前会话，以及该文档仍存在并仍是 workspace 的 `activeId`。通过检查后调用 `layout.show("body-editor.main")`，并更新本地 reveal 版本。

显示与聚焦分开执行：收到有效请求时，即使工作台忙碌、文档 workspace 被阻塞或 main 当前隐藏，也先展示正文，使保存错误可见；等 main 为 active 且工作台不 busy、workspace 不 blocked 后再恢复焦点。reveal 版本让阻塞期间的请求在状态恢复后仍触发聚焦。

## 生命周期

- 隐藏正文或切换标签时保留编辑实例；正文组件根据布局的 `active` 暂停快捷键。
- 离开检查期间，正文只读，但文档插件继续处理已接受的保存。检查失败后保留当前会话、正文和错误重试入口。
- 真正关闭或切换项目时，工作台释放正文插件的会话参与者；正文插件清理本地模型和订阅。离开检查与保存仍由 documents 插件统一负责。
- 正文插件停用时撤销 `body-editor.main`、`body-editor.status` 登记，并撤销工作台参与者。

## 与其他编辑功能的边界

`editor-features` 目前只提供项目操作栏与参考资料占位，登记 actions 和 auxiliary 内容。它不依赖 documents，不登记工作台参与者，也不使用正文插件的内容 ID 或 Context。工程文件树与新建文档交互由 [`工程管理插件`](工程管理插件.md) 提供，布局排列和显隐由 [`布局插件`](布局插件.md) 管理。

本次正文插件保留 `textarea`，不新增 `editorKey`，也不接入 Quill 或 Milkdown。富文本和 Markdown 格式适配器仍是[后续编辑器替换方案](编辑器插件化集成方案.md)；当前设计不承诺异常退出后的崩溃恢复。

实现文件位于 `src/plugins/body-editor/`，包括 `bodyEditorPlugin.tsx`、`bodyEditorModel.ts`、`BodyEditorContext.tsx`、`BodyEditorView.tsx`、`DocumentTabs.tsx`、`Manuscript.tsx`、`EditorStatusBar.tsx`、`useDocumentWorkspace.ts`、内容 ID 定义与样式。
