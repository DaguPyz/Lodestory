# 编辑器插件化集成方案

## 1. 目标与范围

本文讨论后续正文编辑器的替换，不代表 Quill、Milkdown 已接入。当前独立的 `body-editor` 插件仍使用 `textarea`，负责正文、标签栏、空态、保存反馈与状态栏，见[正文编辑插件](正文编辑插件.md)。工作台的页面布局现已通过独立布局插件提供，正文通过 `main` 用途登记，见[布局插件设计](布局插件.md)。正文编辑器的接口与布局接口分别负责内容编辑和页面排布，不应合并。

后续方案计划使用 Quill 编辑富文本，使用 Milkdown Crepe 编辑 Markdown；本轮正文插件拆分不实施这些格式编辑器。工程文件树和新建文档交互已属于独立的工程管理插件；本文只讨论后续正文编辑器的替换。编辑器作为可注册、可替换的插件接入现有文档工作区；插件内部集中处理第三方库、工具栏、编辑状态与序列化。宿主与插件只通过明确的接口协作，不读取第三方编辑器实例。

这里的“可拔插”指编译期注册和按需加载：替换已有格式的编辑器只改注册表与对应插件，不改工作台、保存流程或其他插件。项目会话由[工作台协议](工作台插件.md)管理，编辑器只读写当前会话提供的文档工作区。若新增文件格式，还需在文件创建与后端允许列表中登记；不包含运行时安装任意第三方代码。

## 2. 现有约束

- `src/plugins/body-editor/Manuscript.tsx` 当前使用受控 `textarea`，`BodyEditorView.tsx` 按文档标签同时挂载各文稿、隐藏非活动文稿。正文参与者在每个项目会话中创建 `bodyEditorModel`，并取得 documents 插件创建的工作区；`BodyEditorContext.tsx` 仅提供正文插件内部的私有 Context 与交互组件。
- `documents` 插件持有文档内容并负责 700 ms 自动保存、同文件串行写入、保存失败保护和外部修改冲突检查。`useDocumentWorkspace` 是编辑插件的 React 接入层，通过 SDK 工作区订阅状态，不拥有文档数据。
- Tauri 后端当前只识别 `.md`、`.markdown`、`.txt`，新建文档默认 `.md`。
- 状态栏目前按非空白字符统计 `document.content`，Markdown 标记也计入；后续格式编辑器需要提供纯文字统计，不能直接统计富文本序列化字符串。
- 文稿正文已有原生右键菜单约定；编辑器接入时不得让外层业务菜单抢占选区或输入法。

## 3. 分层和依赖方向

```text
body-editor 的布局 main 内容 / Manuscript
（以下 EditorHost 与格式插件为后续方案，未实现）
        ↓
EditorHost（格式路由、加载、错误、焦点、统计）
        ↓ EditorPlugin 接口
插件注册表 ──→ QuillPlugin / MilkdownCrepePlugin
        ↓ 内容变更回调
useDocumentWorkspace（编辑插件的 React 接入层）
        ↓ @lodestory/sdk/documents
documents 插件：DocumentSession → createDocumentWorkspace → documentApi → Tauri 文档读写

工程管理插件的文件树 → projectFilesApi（工程管理插件）→ Tauri 目录读取
```

| 层 | 职责 | 禁止依赖 |
| --- | --- | --- |
| 编辑器宿主 | 根据文件格式选插件；传入初始内容与展示状态；接收内容和纯文字统计；通过文档 SDK 工作区读写 | Quill、Milkdown 类型和编辑器内部 DOM；文档插件私有实现 |
| 插件注册表 | 声明插件 ID、支持格式和动态加载函数；在单一入口注册 | 文档保存、页面状态 |
| 格式编辑器插件 | 初始化与销毁第三方实例、工具栏、格式转换、选区、输入法与样式 | 正文插件的私有 Context、`DocumentSession`、Tauri 命令 |
| documents 插件 | 保存原始内容字符串、脏状态、自动保存、串行写入和冲突保护；通过 SDK 暴露文档工作区 | 第三方编辑器实例及格式按钮；目录列表与 `TreeEntry` |
| 工程管理插件 | 通过内部 `projectFilesApi` 读取目录列表、显示文件树并提供新建交互；通过 documents workspace 打开或创建文档 | 文档内容和保存状态；正文编辑器内部实现 |

宿主和格式插件通过 `EditorPlugin` 协议**显式耦合**：宿主依赖协议，插件实现协议。格式插件通过编辑器接入层更新 SDK 文档工作区；保存由 documents 插件负责。格式插件不直接读取文档插件内部状态，也不直接调用 Tauri。

## 4. 格式编辑器最小插件协议（后续方案）

```ts
type EditorFormat = "markdown" | "plain-text" | "rich-delta";

type EditorMetrics = {
  characterCount: number;
  selectionCount: number;
};

type EditorHandle = {
  focus(): void;
};

type EditorProps = {
  documentId: string;
  format: EditorFormat;
  initialContent: string;
  active: boolean;
  onChange(content: string): void;
  onMetricsChange(metrics: EditorMetrics): void;
  onReady(handle: EditorHandle | null): void;
};

type EditorPlugin = {
  id: string;
  formats: readonly EditorFormat[];
  load(): Promise<{ default: React.ComponentType<EditorProps> }>;
};
```

- `initialContent` 只在该文档实例创建时装载；宿主的保存状态更新不能反向重设编辑器内容。真正的外部重新加载以新的文档版本或显式替换动作处理，并在有未保存修改时先解决冲突。
- `onChange` 只上报用户导致的内容变化，不把初始化和纯 UI 状态变化写回磁盘。输出必须是可持久保存的完整字符串，不是增量事件。
- `onMetricsChange` 提供去掉编辑器格式后的正文与选区字数，状态栏直接展示；它不参与保存。
- `onReady` 用于标签切换后的聚焦，卸载时传入 `null` 清除句柄；替代查询 `editor-document-input-*` 的固定 DOM ID。格式按钮和撤销栈留在插件内部。
- 文档格式与插件的映射只定义在注册表中；格式没有可用插件或插件加载失败时展示错误与重试，保留原始内容，不自动改用其他编辑器保存。

## 5. 文件格式与路由

| 文件类型 | 插件 | 持久内容 | 工具栏 |
| --- | --- | --- | --- |
| `.md`、`.markdown` | Milkdown Crepe | 原生 Markdown 字符串 | Markdown 允许的格式与结构 |
| `.txt` | Quill 纯文本模式 | 纯文字字符串 | 关闭无法保存的加粗、字号、对齐等富文本动作 |
| 富文本文档，扩展名暂定 `.lode` | Quill 富文本模式 | 带版本号的 Delta JSON 字符串 | 加粗、斜体、字体、字号、对齐、列表等已启用格式 |

富文本文档建议存为 `{ "format": "quill-delta", "version": 1, "ops": [...] }`。Quill 的 Delta 能记录文本与格式；`.txt` 不能保存这些样式，不能把富文本编辑结果静默写入 `.txt`。富文本扩展名与存储格式在实施前确认；无论选择哪种格式，都必须在创建、识别、打开、保存和插件路由处一致。

新建文档界面提供 Markdown、富文本、纯文本选项，默认保持 Markdown。新建富文本文档时写入合法的空 Delta 封装，不能沿用现有的空文件初始化。后端扩展支持的文件类型，但继续把内容作为字符串读写并执行现有的原文比较与原子保存。版本号不认识、JSON 损坏或插件缺失时只展示恢复入口，不覆盖原文件。

## 6. 两个插件内部设计

### QuillPlugin

1. 仅在插件模块中导入 Quill 与其主题 CSS；富文本模式解析并校验 Delta，初始化时装入内容。纯文本模式装入普通文本并限制可用格式。
2. 插件内配置工具栏、允许的格式、字体和字号。只在用户编辑事件中读取完整内容：富文本模式使用 `getContents()` 序列化，纯文本模式使用 `getText()` 并处理 Quill 自动补足的末尾换行。
3. 订阅内容与选区事件，分别调用 `onChange` 和 `onMetricsChange`；初始化和外部装载不触发保存。卸载时移除监听与实例 DOM。
4. 不把 Quill Delta、工具栏命令或主题类名暴露给 `Manuscript` 和文档会话。

### MilkdownCrepePlugin

1. 在插件内部创建 Crepe 实例和 React 所需的 Provider；从 Markdown 字符串初始化，按需启用工具栏、列表、表格、代码块等功能。
2. 通过 `markdownUpdated` 上报完整 Markdown；使用 `getMarkdown()` 读取当前内容。初始化、外部替换与销毁期间阻止回写循环；卸载时销毁实例和监听。
3. Markdown 的字体、字号和正文宽度属于阅读显示设置，由样式变量控制；不作为 Markdown 内联格式保存。
4. 图片上传需由宿主提供资源保存能力和可持久引用的路径；该能力接通前隐藏上传入口，避免生成失效的临时地址或大段内嵌数据。
5. 打开既有 Markdown 只初始化编辑器，不因解析或序列化自动保存；对 Crepe 无法安全往返处理的语法，在插件内提供源码编辑降级入口，避免静默丢失原文。

两个插件分别维护自己的样式作用域和工具栏；页面顶部的项目级 `EditorToolbar` 不承载第三方格式按钮。使用动态导入，打开相应文件时才加载库代码。

## 7. 运行流程与生命周期

1. 打开文件：现有 `readDocument` 读取原始字符串；注册表按扩展名解析格式；`EditorHost` 动态加载插件，并把内容只装载一次。
2. 编辑：插件把完整字符串传给 `workspace.update(id, content)`；`DocumentSession` 继续安排自动保存。格式变化属于内容变化；光标、滚动和浮层变化不触发保存。
3. 切换标签：已打开文档的插件实例继续挂载，只隐藏非活动文稿，以保留各自选区、滚动和撤销历史；活动实例就绪后通过 `EditorHandle.focus()` 聚焦。
4. 手动保存、关闭文稿、离开项目、窗口关闭：仍调用当前文档工作区的 `save`/`saveAll`；离开项目或应用时由工作台参与者执行保存检查，失败时保留标签和未保存内容。
5. 插件加载或解析失败：显示错误与重试；会话中的原文保持不变，禁止把空编辑器内容回写原文件。
6. 中文输入合成期间不重建实例，不因 `onChange` 回流重设内容；正文继续保留原生右键编辑行为。

## 9. 后续验收条件

1. `.md/.markdown` 打开 Crepe，富文本文档打开 Quill，`.txt` 内容不会被富文本格式污染；缺失插件不覆盖文档。
2. 富文本加粗、字体、字号和对齐在保存、关闭、重启后保持；Markdown 的标题、列表、表格、代码块在再次打开后保持。
3. 输入、格式操作与撤销能触发自动保存；移动光标、切换标签和初始化不会产生误保存。
4. 多标签切换保留输入焦点、选区与撤销历史；中文输入法、复制粘贴和原生右键菜单正常。
5. 保存失败、外部文件修改和插件初始化失败均保留未保存内容；原有关闭保护有效。
6. 状态栏统计的是正文纯文字，不是 Markdown 标记或 Delta JSON。
7. 替换已有格式的插件只涉及插件目录和注册表；宿主与文档会话不导入 Quill、Milkdown 类型。新增文件格式时同步更新后端文件允许列表。
8. 使用现有 Markdown 样本验证打开和再次保存后的内容；遇到不支持的语法时保留原文并允许源码编辑，不因打开文件产生修改状态。
