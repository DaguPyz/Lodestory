# 配置插件

## 目标与边界

配置是可被多个功能插件使用的应用能力，不由 `app` 直接读取或传递业务参数。独立 `config` 插件提供 `configKey`；应用目录装配它，拥有配置项的插件负责声明配置和应用配置。

SDK 只定义配置值、配置项、服务接口和共享 key，不绑定存储介质。插件不应自行读写配置文件或 localStorage；需要持久化时通过 `ConfigService` 操作。本仓库首版由配置插件读取基础文件，并保存用户覆盖。

配置服务首版只处理应用级配置；项目独有设置暂不在此协议内。主题偏好仍由主题插件管理，暂不迁移到配置插件。

## SDK 协议

公共契约位于 [`@lodestory/sdk/config`](../../packages/sdk/README.md#配置服务)，基础类型为 `ConfigValue`、`ConfigItem<T>` 和 `ConfigService`，服务 key 为 `configKey`。

```ts
type ConfigItem<T extends ConfigValue> = {
  readonly id: string;
  readonly defaultValue: T;
  readonly effect: "live" | "restart";
  readonly validate: (value: unknown) => value is T;
};

type ConfigService = {
  register<T extends ConfigValue>(item: ConfigItem<T>): () => void;
  getSnapshot<T extends ConfigValue>(item: ConfigItem<T>): ReadonlyConfig<T>;
  set<T extends ConfigValue>(item: ConfigItem<T>, value: T): Promise<void>;
  reset<T extends ConfigValue>(item: ConfigItem<T>): Promise<void>;
  subscribe<T extends ConfigValue>(item: ConfigItem<T>, listener: () => void): () => void;
};
```

值限于可序列化 JSON：`null`、布尔、有限数字、字符串、数组及普通对象。不接受函数、`undefined`、循环引用或特殊原型对象。配置 ID 使用 `插件名.配置名`，必须唯一。

`register` 只在初始插件激活阶段开放；重复 ID、无效默认值或无效基础值会使登记失败，失败不留下半成品。撤销函数幂等，不删除已保存的用户值。`getSnapshot` 只对已登记项开放，返回深只读值；有效值未变化时保持相同引用。`subscribe` 对单项变化发出通知，返回幂等取消函数。

`set` 和 `reset` 返回 Promise，并按调用顺序执行。`set` 校验并复制新值，保存成功后才更新有效值和通知监听者；校验或持久化失败会拒绝，不改变当前有效值。`reset` 删除用户覆盖，恢复基础值或声明默认值，也只有删除持久化成功后才发布变化。监听回调失败应单独报告，不能回滚已成功保存的值。

## 插件声明与使用

所属插件导出声明，供消费者导入同一个对象；消费者不能再次登记相同 ID。配置校验负责值类型和范围，业务条件（例如被选择的页面是否存在）由所属插件验证。

```ts
export const fontSizeConfig: ConfigItem<number> = {
  id: "editor.fontSize",
  defaultValue: 18,
  effect: "live",
  validate: (value): value is number =>
    typeof value === "number" && Number.isInteger(value) && value >= 12 && value <= 40,
};

export const editorPlugin: Plugin = {
  id: "editor",
  requires: [configKey],
  provides: [],
  activate(context) {
    const config = context.get(configKey);
    const removeRegistration = config.register(fontSizeConfig);
    const apply = () => applyFontSize(config.getSnapshot(fontSizeConfig));
    apply();
    const unsubscribe = config.subscribe(fontSizeConfig, apply);
    // deactivate 时先 unsubscribe，再 removeRegistration。
  },
};
```

在 `activate` 中读取其他插件拥有的配置时，除 `configKey` 外还要通过 `requires` 声明配置所属方提供的能力，确保声明方先完成登记。配置声明的 `effect` 只记录生效时机：`live` 由插件订阅并应用；`restart` 由插件在启动时读取。配置服务只保存和发布值，不直接修改 UI、主题或其他业务状态。

## 存储与优先级

配置插件独立读取 [`src/plugins/config/config.json`](../../src/plugins/config/config.json) 作为应用基础配置。用户覆盖保存在 localStorage 键 `lodestory.config-overrides`。有效值从高到低为：

1. 用户覆盖值；
2. 应用基础配置；
3. `ConfigItem.defaultValue`。

配置文件缺少某项时继续查下一层。无效用户值会上报具体配置项，并回退到有效的基础值或默认值；配置文件中的无效值在该项登记时应明确失败，不能静默以默认值掩盖打包错误。启动读取到损坏的用户覆盖数据时报告并按可用配置回退，不在启动阶段擅自覆盖原数据。

存储实现属于本应用，不写入 SDK 契约。SDK 单元和外部宿主可以用内存或其他存储实现同一服务接口。

## 启动首页接入

UI 插件在 SDK 导出 `uiInitialPageConfig`：

```ts
{
  id: "ui.initialPage",
  defaultValue: null,
  effect: "restart",
  validate: (value) => value === null || typeof value === "string",
}
```

`null` 表示使用首个登记页面。首版 `config.json` 将其设为 `welcome`，即使工作台页面更早登记，默认启动仍进入欢迎页。UI 在全部页面完成登记后读取配置；配置指向不存在的页面时启动失败并回滚，防止运行在没有有效首页的状态。修改该项只保存为下次启动值，不会立即跳转。

应用目录把 `config` 放在首位，再按原顺序装配其他插件。UI 自己登记 `uiInitialPageConfig` 并读取配置服务；`app` 调用 `createConfigPlugin()`、`createUiPlugin()`，不负责业务配置或启动首页参数。

## 首版范围

- 提供配置声明、有效值读取、修改、恢复、订阅和持久化失败语义。
- 通过 `ui.initialPage` 验证配置服务与 UI 启动流程。
- 不迁移现有主题偏好，不改造 `theme-config.json` 的归属。
- 暂不提供配置 UI、项目级配置、配置导入导出或热重载。

测试应覆盖 SDK key/type 导出、优先级、用户值校验回退、持久化失败不发布、UI 启动页覆盖与校验、运行中修改不即时导航，以及应用无参装配。
