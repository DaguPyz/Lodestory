# 项目存储插件

## 定位

项目存储插件为工作台项目会话提供按路径共享的字节缓冲和持久化。它管理读取、写入队列、自动保存、冲突保护、离开前保存及会话清理；不定义文本编码、JSON 格式、业务目录布局，也不管理正文标签、当前选择、目录树或具体业务流程。

公开契约位于 [`@lodestory/sdk/project-storage`](../../packages/sdk/src/project-storage.ts)，实现位于 `src/plugins/project-storage/`。插件依赖 `workbenchKey`，以 `projectStorageKey` 提供 `getFiles(sessionId)`。documents 与 outline-design 都通过这一能力访问同一项目路径上的字节服务，各自负责解释自己的数据。

## 状态归属

| 状态或流程 | 拥有者 | 说明 |
| --- | --- | --- |
| 项目相对路径的唯一字节缓冲、保存状态和写入队列 | project-storage | 同一会话内，同一路径共用一个缓冲；快照字节为只读数值数组。 |
| 文件读取、创建、写入、保存、删除和目录枚举 | project-storage | 仅处理字节和路径，不推断字符串编码或文件格式。 |
| 自动保存、保存错误、冲突保护和离开保存 | project-storage | `write` 修改共享缓冲并安排自动保存；保存以已读取字节作冲突基线。 |
| 字节转字符串和业务目录规则 | 使用方插件 | documents 解释正文文本；outline-design 解释其 JSON 与 `.lodestory` 路径。 |
| 正文打开项、关闭、选择和正文业务操作 | documents | 通过 `DocumentWorkspace` 接入项目存储，不另建正文内容缓冲。 |
| 文件树和目录选择 | project-management | 管理文件树展示与交互，不拥有文件内容。 |
| 项目会话及统一离开检查 | workbench | 所有项目参与者均检查并处理会话生命周期。 |

## SDK 契约

```ts
type ProjectStorageService = {
  getFiles(sessionId: string): ProjectFiles | null;
};

type ProjectFiles = {
  getSnapshot(): ProjectFileSnapshot;
  subscribe(listener: () => void): () => void;
  read(path: string): Promise<ProjectFile | null>;
  create(path: string, bytes: ProjectFileData, options?: {
    createParents?: boolean;
    acceptIdentical?: boolean;
  }): Promise<ProjectFile | null>;
  write(path: string, bytes: ProjectFileData): boolean;
  save(path: string): Promise<boolean>;
  saveAll(): Promise<boolean>;
  delete(path: string, options?: {discardChanges?: boolean}): Promise<boolean>;
  list(path: string): Promise<ProjectDirectoryListing | null>;
  createDirectory(path: string, options?: {recursive?: boolean}): Promise<boolean>;
  clearError(): void;
};
```

同一会话重复调用 `getFiles` 会取得同一个服务；会话结束或正在退出时返回 `null`。`ProjectFile` 包含相对路径、文件名、只读 `bytes`、dirty 标记、保存状态和保存错误。`ProjectFileSnapshot` 汇总当前缓冲、阻塞状态和服务错误。`list(path)` 返回 `exists`、直接子项和局部 issues；缺少目录是 `exists: false`，与权限或读取错误分开。目录项公开 `file`、`directory`、`symlink` 或 `other` 类型。

字节数组是存储契约的边界。调用方需要自行选择编码、格式和目录布局；项目存储不会把 Markdown 或 JSON 变成字符串，也不会按 `.md`、`.lode` 或其他扩展名推断内容。`create` 可按调用方指定选项创建父目录，且在发布成功前先完成持久化；`acceptIdentical` 只允许相同字节的重试成功，不覆盖不同内容。`read` 刷新干净缓冲，保留 dirty 或 saving 缓冲；`write` 更新共享缓冲并由项目存储安排自动保存。

消费者一般在自己的工作台参与者中获取服务并清理订阅：

```ts
import {projectStorageKey} from "@lodestory/sdk/project-storage";
import {workbenchKey} from "@lodestory/sdk/workbench";

const storage = context.get(projectStorageKey);
const workbench = context.get(workbenchKey);
const removeParticipant = workbench.registerParticipant({
  id: "example.storage-consumer",
  start(session) {
    const files = storage.getFiles(session.id);
    if (!files) throw new Error("Project storage is unavailable.");
    const unsubscribe = files.subscribe(() => {
      const snapshot = files.getSnapshot();
      // 由当前业务插件解释 bytes，并展示对应的读写状态。
    });
    return {dispose: unsubscribe};
  },
});
```

## 宿主文件桥接

当前统一字节命令为 `read_project_file`、`create_project_file`、`save_project_file`、`delete_project_file`、`list_project_directory` 和 `create_project_directory`。它们接收项目相对路径和字节数组，执行路径、符号链接与 expected-bytes 冲突检查，不识别 `.md`、`.lode`、时间线或其他业务字段。`ProjectFiles` 提供的 `list` 是通用目录枚举，具体插件决定应显示或读取哪些条目。

正文与 outline-design 使用同一个 `ProjectFiles` 服务。documents 自己定义如何将正文文件字节解释为字符串；outline-design 自己定义 UTF-8、`.lodestory/outline-design/timelines/<uuid>.json` 路径及 JSON 校验。项目存储只提供路径文件操作，也不自动创建上述业务目录。

迁移没有改写既有项目文件名、内容、磁盘格式或相对路径。项目存储把这些文件映射到共享字节缓冲，不会自动转码。outline-design 列表继续使用原来的 `.lodestory/outline-design/timelines/<uuid>.json` 位置和 JSON 结构。宿主仍保留 `list_documents` 作为工程文件树查询，其余正文和大纲文件的读取、创建、保存与删除统一通过字节文件命令完成。配置与主题偏好仍保存在 `localStorage`，最近项目索引仍在应用配置目录，不属于本次项目存储迁移。

## 生命周期与失败处理

项目存储作为工作台参与者，在项目会话开始时准备 `ProjectFiles`。离开检查开始后，存储拒绝新的修改，排空已接受的读取、创建和写入，再保存待写缓冲。冲突或写入失败会阻止项目离开并保留当前会话内容及错误。使用方插件可通过工作台参与者协调自己的未提交表单与流程。

暂时隐藏面板不会释放项目存储。项目会话结束前，工作台先停止视图，再释放共享存储服务；自动保存计时器、订阅和缓冲都在存储会话范围内清理。旧会话异步结果不得改变新会话状态。保存失败时的进程内恢复快照不构成应用崩溃后的恢复保证。

读取失败必须与空目录区分。项目存储报告服务错误和目录 issues，业务插件负责以符合自身功能的方式呈现；非法 UTF-8 或 JSON 的解释也由使用方负责。存储不会把损坏内容改写为空内容。

## 验收

- 正文与 outline-design 对同一项目路径使用唯一字节缓冲；替换兼容存储实现不要求消费者导入内部模块。
- 新业务选择编码和目录规则时在所属插件内实现，不要求项目存储识别该业务。
- 离开项目时，统一保存所有已接受的缓冲写入；任一保存失败都会保留项目会话与未保存内容。
- 配置、主题和最近项目索引继续按原边界存储。
